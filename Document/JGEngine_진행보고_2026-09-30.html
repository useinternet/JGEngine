JGEngine 진행 보고

기준일 2026-09-30 · 엔진 기반 7개 트랙 · 상세 문서: Document/Memory/README.md

요약. 엔진 기반 7개 트랙 중 4개(Memory, DevConsole, GameModule, Server 1차)는 구현과 검증이 끝나 커밋만 남았습니다. Graphics는 렌더링 기반을 마치고 에셋 파이프라인 마무리 단계이며, GameFrameWorks는 규칙 커널과 월드 계층 1차 구현을 끝내고 다음 단계(월드와 렌더링 연결) 착수를 기다립니다. GUI는 전용 작업이 멈춰 있습니다.

지금 필요한 것. 첫째, 전 트랙의 변경이 한 작업 트리에 커밋되지 않은 채 섞여 있어 git add -A로 한 번에 커밋해 기준선을 만드는 일입니다. 둘째, 후속 작업을 막고 있는 결정 두 가지(Graphics 에셋 저장 형식, Server 월드 연결 착수 여부)입니다. 결정 목록은 7절에 모았습니다.

원칙 (지침서 1절) 우리는 게임 엔진을 만들고, 그 위에 보드 & 카드 게임을 만듭니다. 지금의 초점은 엔진 기반입니다. 레퍼런스 게임(아컴호러 등)은 요구사항 확인용 참고 자료일 뿐이며, 이 보고서의 진척도 엔진 시스템 단위로만 측정했습니다.

2. 지금 가장 중요한 세 가지

1. 한 커밋으로 기준선 만들기GameFrameWorks, Server, DevConsole, GameModule, Memory의 변경이 커밋되지 않은 채 한 작업 트리에 섞여 있고, 새 소스 폴더 여러 개가 아직 git에 추가되지 않았습니다. 콘솔 명령 코드에 여러 트랙이 의존하므로 트랙별로 나눠 커밋하면 빌드가 깨집니다. git add -A로 한 번에 커밋하고, 재빌드된 빌드 도구 exe 2개와 프로젝트 템플릿, 삭제된 JGDev_Graphics를 함께 넣어야 합니다. 체크리스트는 진행현황 5절.
2. 막힌 결정 두 가지Graphics의 에셋 저장 형식(4MB 텍스처가 73.7MB 파일로 저장되는 문제)이 에셋 파이프라인 전체를 막고 있고, Server의 월드 연결(Phase 5) 착수 여부가 네트워크 트랙의 다음 단계를 막고 있습니다.
3. 공유 파일 조율GameFrameWorks와 Server가 같은 GameMaster 파일을 고치고, DevConsole·GameModule이 같은 Core 파일을 고칩니다. 병렬 세션이 착수하기 전에 상대 트랙 현황 문서의 의존 절을 확인하는 규칙을 문서에 넣었습니다.
