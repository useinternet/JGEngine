데이터 테이블 설계

2026-10-01 · 요청: "데이터 관련 기반 작업. .json 기반으로 하고, 에디터에서 해당 에셋을 엑셀처럼 편집" · 상태: 설계만(코드 변경 없음) · 결정 6개 대기

요약. 행(고유 키) × 열(타입이 있는 값)로 된 데이터를 새 에셋 JGDataTable로 만듭니다. 파일은 지금 에셋과 같은 .jgasset이고 내용은 JSON입니다. 열 정의(스키마)도 같은 파일에 들어 있어서, 에디터는 게임 코드 없이 테이블을 열고 열을 추가하고 셀을 고칠 수 있습니다. 엑셀의 머리행과 같은 방식입니다.

게임 코드는 필요한 열만 C++ 멤버에 묶어서 읽습니다(HDataTableView<T>). 묶는 순간 열 이름과 타입을 검사하므로, 테이블과 코드가 어긋나면 로드할 때 바로 오류가 납니다. 런타임 데이터는 읽기 전용이고, 순회 순서는 늘 파일의 행 순서입니다. GameMaster 결정론과 맞추기 위해서입니다.

에디터에는 "Data Table Editor" 창이 생깁니다. 셀 선택, 키보드 이동, 바로 입력, 범위 선택, 엑셀·구글 시트와 복사/붙여넣기, 실행 취소, 정렬과 필터, 저장을 지원합니다. 착수 전에 정해 주실 것이 6개 있고, 모두 권고안이 있습니다(결정 항목).

파일 형식

지금 .jgasset과 같은 껍데기 안에 JGDataTable 절이 들어갑니다. 아래는 읽기 쉽게 줄인 것이고, 실제 저장은 값마다 한 줄입니다.

"JGDataTable": {
    "FormatVersion": 1,
    "KeyColumn": "Id",
    "Columns": [
        { "Name": "Count", "Type": "Int",      "Default": 0, "Min": 0 },
        { "Name": "Rate",  "Type": "Float",    "Default": 1.0 },
        { "Name": "Kind",  "Type": "Enum",     "EnumValues": [ "A", "B", "C" ], "Default": "A" },
        { "Name": "Mesh",  "Type": "AssetRef", "AssetClass": "JGStaticMesh", "Default": "" },
        { "Name": "Next",  "Type": "RowRef",   "Table": "/JGGame/Data/OtherTable", "Default": "" }
    ],
    "Rows": [
        { "Id": "Row_A", "Count": 3, "Rate": 1.5, "Kind": "B", "Mesh": "/JGGame/Meshes/Box", "Next": "Row_X" }
    ]
}
  • 행은 열 이름을 키로 한 객체이고 모든 셀을 적습니다. 그래서 손으로 고치기 쉽고, 기본값을 바꿔도 기존 데이터의 뜻이 바뀌지 않습니다.
  • 셀 하나를 고치면 diff도 한 줄입니다. 같은 내용이면 다시 저장해도 바이트가 같습니다. 다른 셀을 고친 두 변경은 git이 깨끗이 병합합니다.
  • 행 순서 = 파일 순서 = 런타임 순회 순서입니다. 에디터에서 정렬해 봐도 파일 순서는 그대로이고, "정렬을 행 순서로 적용" 명령만 순서를 바꿉니다.
  • UTF-8로 저장합니다(읽을 때 BOM은 건너뜁니다). 파일 이름은 ASCII만 씁니다. 저장은 임시 파일에 쓴 뒤 교체하므로 중간에 죽어도 원본이 남습니다.

키 열은 비어 있거나 중복되면 저장을 막습니다(런타임 색인이 깨지므로). 그 밖의 문제는 경고로 보여 주고 저장은 허용합니다. Int 열에 "abc" 같은 타입 오류는 입력할 때 거부합니다.

게임 코드에서 쓰는 법

struct HSampleRow
{
    int32      Count = 0;
    float32    Rate  = 1.0f;
    HAssetPath Mesh;
    PName      Next;

    static void BindColumns(HDataTableRowBinder<HSampleRow>& binder)
    {
        binder.Bind("Count", &HSampleRow::Count);
        binder.Bind("Rate",  &HSampleRow::Rate);
        binder.Bind("Mesh",  &HSampleRow::Mesh);
        binder.Bind("Next",  &HSampleRow::Next);
    }
};

HDataTableView<HSampleRow> view;
if (view.Bind(table, &issues) == false)    // 열 없음 · 타입 불일치 → 어느 열인지 알려 줌
{
}
const HSampleRow* row = view.Find(PName("Row_A"));
  • Bind가 모든 행을 한 번에 C++ 배열로 바꿉니다. 그 뒤 조회는 키 색인이고, 순회는 행 순서입니다.
  • 규칙 상태(GameMaster)에는 행 키만 넣고 값은 뷰에서 읽습니다. 데이터는 불변입니다.
  • 에디터에서 저장하면 로드된 테이블이 바뀌고 OnChanged가 불립니다. 쓰는 쪽은 그때 다시 Bind합니다.

지금 코드에서 확인한 것 (설계 근거)

영역사실그래서
에셋.jgasset은 이미 JSON이고, 시작할 때 Content 전체를 비동기로 올립니다. JGTexture가 직렬화를 직접 쓰는 선례가 있습니다새 에셋 타입 하나로 저장·로드·GUID·경로가 따라옵니다
리플렉션프로퍼티 값을 읽고 쓰려면 컴파일 타임 타입이 필요합니다(SetValue<T>). JGSTRUCT는 빈 매크로이고, 헤더 파서는 공백으로 나눠 HHashMap<PName, int32> 같은 타입을 못 읽습니다UE DataTable처럼 "C++ 구조체가 스키마"로 가려면 리플렉션 확장이 먼저입니다 → 스키마를 에셋에 두는 쪽을 권합니다
JSONToObject가 파싱 오류를 무시합니다. 값을 읽으면 원본에서 옮겨 가서 두 번 못 읽습니다. 객체 키를 나열하는 API가 없습니다손으로 고친 파일의 오류를 줄:칸으로 알려 주고, 모르는 열을 찾으려면 Core 보강 3개가 필요합니다(기존 동작은 그대로 두고 추가만)
에디터 글꼴에디터 ImGui는 기본 영문 글꼴만 씁니다지금은 한글 셀이 보이지 않습니다 → 한글 글꼴(GUI BL-3)이 선행입니다
GUI 모듈ImGui는 GUI 모듈 안에서만 부르고, 키 래퍼는 Escape 하나, 클립보드 래퍼는 없습니다. 위젯은 클래스마다 하나만 열립니다그리드는 GUI 모듈 안 독립 컨트롤로 만들고, 여러 테이블은 한 창 안의 탭으로 엽니다
GameFrameWorks네트워크 일치 검사(RulesFingerprint)는 등록된 규칙 목록만 봅니다테이블에 내용 지문(ComputeContentHash)을 두고, 지문에 넣는 연결은 네트워크 게임이 테이블을 쓸 때 GFW·Server와 정합니다
