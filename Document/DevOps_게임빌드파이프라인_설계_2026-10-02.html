JGConsole.exe -runCook -project=C:\Develop\MyGame [-config=ReleaseGame] [-output=…]

작업은 임시 폴더에서 하고 마지막에 바꿔 넣습니다. 그래서 중간에 실패해도 이전 패키지는 그대로 남습니다. 출력 폴더는 비었거나 이전 패키지일 때만 지우고, 엔진 · 프로젝트 · 드라이브 루트이면 거부합니다.

1차 "쿠킹"은 고르기 + 검사 + 배치입니다. 이진 에셋 변환 · 셰이더 사전 컴파일 · 묶음 파일 · 압축은 2차(보류 후보)입니다. 지금 에셋은 실행에 쓰는 형식 그대로라, 변환하지 않아도 동작합니다.

4. 실행 구조 — 결정 ①

루트를 Bin/ · Content/ · exe 로 깨끗하게 두려면, 루트 exe 가 엔진을 직접 링크하면 안 됩니다. 엔진은 CRT DLL 방식이라 그러면 CRT DLL 을 루트에 둬야 하기 때문입니다. 그래서 3층으로 나눕니다: 작은 부트스트랩 exe → 진입 DLL → GameHost 모듈.

(a) 한 프로세스 — 권고(b) 두 프로세스 (언리얼식)
방식<Name>.exe 가 같은 프로세스에 Bin/ DLL 을 올림 (Unity 의 exe + UnityPlayer.dll 과 같은 꼴)<Name>.exe 가 Bin/<Name>-Game.exe 를 실행하고 기다림
좋은 점프로세스 1개 — 종료 코드 · 크래시 덤프 · 디버거 · 오버레이가 자연스러움. -host 같은 명령줄도 그대로 동작DLL 경로를 설정할 필요가 없음. Bin 안 exe 를 바로 실행 · 디버그 가능

② ✔ a저장 · 로그 위치(a) 패키지 폴더 안 Saved/ — 폴더째 옮기면 같이 감. ProjectAH 지금 방식과 같음(b) %LOCALAPPDATA%\<Name>\ — Program Files 처럼 쓰기 금지 폴더에 설치할 때 필요 (함수 하나라 나중에 바꾸기 쉬움)
③ ✔ bContent 밖 데이터
ProjectAH 는 게임 코드가 프로젝트 폴더의 데이터 폴더 2개(25MB · 144MB)를 직접 읽음		(a) 프로젝트 설정에 적은 폴더를 패키지 루트에 같은 경로로 복사 — 게임 코드는 그대로지만, 루트에 그 폴더가 더 보임(b) Content 만 패키징 — 선택됨. 루트가 정확히 Bin/ Content/ exe. 엔진 · 게임의 Content 밖 데이터는 Content 로 옮기도록 요청(GP-G4 · GP-P0)
④ ✔ a착수 범위 · 배정(a) M1 + M2 를 위 배정대로 총괄이 전달, M3 은 M2 뒤(b) M1 만 먼저 · (c) DevOps 혼자 순서대로 (약 2배 느림)

추가 지시: 기본 게임 화면 1920×1080 (처음 안 1280×720).

제가 정해 둔 기본값 (이견이 있으면 바꿉니다)

  • 기본 구성 ReleaseGame. -config=ConfirmGame 은 프로파일을 켠 확인용입니다.
  • 출력 <Project>/Package/<Config>/
  • 창 모드 1920×1080(사용자 지시). 모니터보다 크면 맞춰 줄입니다. -fullscreen 은 테두리 없는 전체 화면이고, 게임은 VSync 를 켭니다.
  • 셰이더는 원문을 복사합니다(사전 컴파일은 나중). assimp DLL 은 같이 배포하고(분리는 나중), CRT 는 앱 로컬로 넣습니다.

7. 오늘 확인한 사실

확인결과
ReleaseGame 엔진 빌드처음에는 zlibstatic.lib 를 못 찾아 실패했습니다. BuildTool 이 엔진 솔루션에는 3rd-party 를 복사하지 않기 때문입니다(→ GP-D0). 3개를 넣은 뒤에는 14 프로젝트 오류 0 · 경고 0, 37.4초.
Release 실행자체 테스트(gmtest · 게임 UI 193 · DataTable 127 · 콘솔 64 · 네트워크 전체) 통과. 런처 30초 실행 종료 0 · 오류 0 · 메모리 누수 0.
D3D 디버그 층Debug 에서만 켜집니다 → Release 패키지에 개발자 도구가 필요 없습니다.
GameFrameWorks 의존Core · Asset · Graphics 뿐입니다(ImGui 없음) → 런타임에 남는 모듈은 Asset · Graphics · GameFrameWorks 입니다.
에셋 경로/JGEngine/ · /JGGame/ 토큰 + 상대 경로 → 패키지에서는 두 마운트만 바꾸면 됩니다.
작업 폴더 의존지금 루트는 작업 폴더 기준이라, JGConsole 을 다른 폴더에서 실행하면 엔진 경로가 틀어집니다 → GP-D1 에서 exe 위치 기준으로 바꿉니다.

8. 리스크

리스크대응
개발 PC 에서만 되는 의존(VC 런타임 · 시스템 글꼴)패키징 때 각 DLL 이 쓰는 DLL 을 검사해 채웁니다. 게임 Content 에 글꼴을 넣기를 권합니다. 깨끗한 PC 에서 한 번 실행해 보시면 확실합니다.
숨은 개발 경로 사용패키지 모드에서는 개발 경로 함수가 빈 값과 오류 로그를 냅니다. 스모크와 "다른 경로로 복사해 실행"으로 확인합니다.
여러 세션이 같은 파일을 고침파일마다 소유 세션을 정합니다. 경계 헤더를 먼저 올리고, 착수 전에 git status 로 확인합니다.
에디터 회귀(크기 변경 이관 · 뷰포트 교체 · 루트 기준 변경)에디터 e2e · 배치 1 · 2 · 회귀 5종을 다시 돕니다.
출력 폴더를 잘못 지움지워도 되는 폴더만 지우는 가드를 두고, 임시 폴더에서 만든 뒤 바꿔 넣습니다.
