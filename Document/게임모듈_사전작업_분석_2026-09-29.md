## 0. 결론

- **배치 파일 2개 자체는 작다**(템플릿 복사 + 툴 호출). 막는 것은 툴과 런타임이 **루트를 하나(`../../`)만 안다**는 점이다.
- **재현**: 요청한 구조의 `MyGame` 을 지금 툴에 물리면 모듈 2개(재현 당시 이름 Game, Editor)는 수집되지만, BuildTool 이 Step 4(PCH 삽입)에서 엔진 루트 기준 경로를 열다 예외 → **Debug CRT abort 대화상자에서 배치가 멈춘다.** sln · `module_system_info.json` 까지 못 간다. HeaderTool 은 게임 헤더를 통째로 건너뛴다.
- **필요한 작업**: 툴 16건(필수 15) · 런타임 7건(필수 3) · 절차 5건. 필수만 하면 "빈 폴더 → 배치 1 → 배치 2 → `MyGame.sln` 빌드 → JGEditor 에서 `MyGame` · `MyGameEditor` 로드 + 리플렉션 등록"까지 간다.
- **병렬**: 기준선 정리(①)와 계약 고정(②)만 단일 트랙이고, 그 뒤 툴 · 런타임/호스트 · 템플릿/배치/가이드 3트랙이 동시에 간다(§5).
- **결정 D1–D7 은 2026-09-29 확정**(§6). 이 문서의 해당 항목은 결정대로 고쳐 두었다.

## 1. 목표 구조

### 1-1. 폴더와 로드 방식

```
<Engine>/Build/BatchFiles/CreateGameProject.bat <ProjectDir> [Name]   ← 배치 1
<Engine>/Build/BatchFiles/GenerateGameProjectFiles.bat <ProjectDir>   ← 배치 2
<Engine>/Build/Templates/GameProject/                                 ← 템플릿 (Source/ 밖, §2-1)

<ProjectDir>/
  <Name>.jgproject              Name · EngineRoot(비우면 JGENGINE_ROOT) · 모듈 목록
  GenerateProjectFiles.bat      배치 2 호출 래퍼
  <Name>.sln                    생성물 (Engine 그룹 + 게임 그룹)
  Bin/<Config>/                 엔진 + 게임 산출물, 3rd party dll/lib
  Content/
  Source/<Name>/                <Name>.module.json · <Name>Defines.h · <Name>Module.h/.cpp                    (H<Name>Module)
  Source/<Name>Editor/          <Name>Editor.module.json · <Name>EditorDefines.h · <Name>EditorModule.h/.cpp  (H<Name>EditorModule)
  Temp/{CodeGen,Obj,ProjectFiles}/   CodeGen 에는 게임 모듈 것만
```

폴더 = 모듈 = DLL = premake 프로젝트 이름(D5). 예: `MyGame` → `Source/MyGame` · `MyGame.dll` · `_MYGAME` · `MYGAME_API` · `HMyGameModule`, `Source/MyGameEditor` · `MyGameEditor.dll` · `_MYGAMEEDITOR` · `MYGAMEEDITOR_API` · `HMyGameEditorModule`.

| 실행 | 호스트 | 로드하는 게임 모듈 |
|---|---|---|
| 에디터 환경 | JGEditor (D2) | `<Name>` + `<Name>Editor` (D1) |
| 게임 실행 | 미정 — 창 · Graphics 를 여는 쪽이 필요. 첫 목표(에디터 + 헤드리스)에는 쓰지 않음 | `<Name>` (`<Name>Editor` 는 제외. 지금은 코드젠이 전부 로드 — R5) |

### 1-2. 생성물 위치 (계약)

원칙: **프로젝트 모드는 엔진 트리에 아무것도 쓰지 않는다.** 엔진 단독 모드는 "프로젝트 루트 = 엔진 루트"인 특수 경우로 두어 지금 산출물과 바이트 동일해야 한다(회귀 기준).

| 생성물 | 지금 (엔진 단독) | 프로젝트 모드 |
|---|---|---|
| premake 스크립트 · 호출 bat | `<Engine>/jgengine.lua` · `jgengine.bat` | `<Project>/` |
| sln | `<Engine>/JGEngine.sln` | `<Project>/<Name>.sln` |
| vcxproj · obj | `<Engine>/Temp/{ProjectFiles,Obj}` | `<Project>/Temp/...` |
| 엔진 모듈 코드젠 | `<Engine>/Temp/CodeGen` (엔진 PreBuild) | **그대로 엔진 것을 읽는다** (D4). 프로젝트 모드는 다시 만들지 않는다 |
| 게임 모듈 코드젠 | — | `<Project>/Temp/CodeGen` |
| `module_system_info.json` | 엔진 것: 엔진 모듈만 | 프로젝트 것: 엔진 + 게임 SharedLib (런타임이 전부 로드해야 하므로) |
| 산출물 | `<Engine>/Bin/<Cfg>` | `<Project>/Bin/<Cfg>` |
| 3rd party (zlibstatic.lib, assimp-mt.lib/.dll) | 손으로 복사해 둔 것 | 생성 시 복사 (B8) |
| 엔진 소스 · Shader · 엔진 Content | 읽기 | 읽기 전용 |
| 엔진 루트 해석 (D7) | `../../` | `-project` 인자 또는 실행 파일 위치의 `../../*.jgproject` → EngineRoot → 비어 있으면 환경변수 `JGENGINE_ROOT` → 둘 다 없으면 오류 |

### 2-3. 템플릿 파일과 규칙

초안: `Document/Memory/tools/gameproject_repro/MyGame/Source/{MyGame,MyGameEditor}/` (D5 이름으로 갱신, 아직 빌드는 안 됨). 템플릿은 이 초안의 `MyGame` 을 `{PROJECT_NAME}`, `MYGAME` 을 `{PROJECT_NAME_UPPER}` 로 바꾼 것이다.

| 파일 | 내용 | 규칙 · 근거 |
|---|---|---|
| `Source/<Name>/<Name>.module.json` | SharedLib · 의존 `Core, GameFrameWorks` · Defines `_<NAME>` | define 은 반드시 `_` + 대문자 모듈명. HeaderTool 이 만드는 등록 파일이 `#ifdef _<NAME>` 으로 `Engine_CodeGenerate` export 를 정한다(HeaderTool.cpp:1253-1258, 1312). 폴더명 = json 파일명 = ModuleName(BuildTool.cpp:534, HeaderTool 은 폴더명을 모듈명으로 씀 :137-151) |

| `<Name>Module.h/.cpp` | `H<Name>Module : IModuleInterface` · `JG_MODULE_IMPL(H<Name>Module, <NAME>_C_API)` · `GetModuleType()` = `JGTYPE(H<Name>Module)` | 매크로가 `_Create_Module_Interface_` · `Link_Module` 을 export(Module.h:8-16). 모듈 조회 키가 타입 해시라 엔진 클래스와 이름이 겹치면 ConnectModule 실패(Module.cpp:132-139) → §2-1 이름 검사 |

| 모든 .cpp | 첫 줄 `#include "PCH/PCH.h"` · UTF-8 | `/utf-8` 고정(BuildTemplate.lua:59). CP949 면 C4828 |
| 리플렉션 헤더 | 헤더당 `JGCLASS` 1개, `JGPROPERTY()` 는 한 줄, 타입에 공백 · `::` 금지, `JGSTRUCT` 미지원(기존 제약) | 추가로 **파일명이 의존 모듈의 리플렉션 헤더와 겹치면 안 된다.** 생성 헤더를 파일명만으로 include 하고(Actors/Actor.h:5) 자기 CodeGen 경로가 의존 경로보다 앞이라(BuildTool.cpp:264-271) 게임 `Actor.h` 를 만들면 엔진 `Actor.h` 가 게임의 `Actor.generation.h` 를 집는다 |

## 3. 두번째 — BuildTool / HeaderTool 추가 구현

### 3-1. 재현: 지금 툴에 MyGame 을 물린 결과

방법: 가짜 엔진 루트(엔진의 `*.module.json` 17개 · `BuildTemplate.lua` · 툴 exe · premake 만 복사)에 요청 구조의 `MyGame` 을 두고, 인자 json 을 `UserWorkDirectory = <MyGame>`, `UserWorkCategories = ["Source"]` 로 바꿔 HeaderTool → BuildTool 을 2회. 엔진 트리는 읽기만 했다. 재현 당시 모듈 이름은 D5 이전의 `Game` · `Editor` 였고, 그 뒤 초안을 `MyGame` · `MyGameEditor` 로 바꿨다(다시 돌리면 이름 충돌 행은 나오지 않고 나머지는 같다).

| 단계 | 결과 |
|---|---|
| BuildTool Step 1–2 수집 | 엔진 16 + 게임 2(Editor, Game). 의존 해석 오류 0 → **1단 구조는 스캔 수정 없이 잡힌다** |
| Step 3 lua | 그룹 `MyGame/Source` 생성. 게임 모듈 경로가 엔진 루트 기준 문자열로 나간다: `Editor` → `"Source/Editor/"` = **엔진의 `Source/Editor` 카테고리**(DevConsole · JGEditor 등), `Game` → `"Source/Game/"` · `"Temp/CodeGen/Game/"`(엔진 Game 과 같은 코드젠 폴더) |
| Step 4 PCH 삽입 | 2회 모두 `Step 4. Insert Include PCH..` 직후 멈춤. 프로세스 창 제목 `Microsoft Visual C++ Runtime Library`(abort 대화상자) → 강제 종료. 엔진 루트 밑에 없는 `Source/Game/` 을 `recursive_directory_iterator` 로 연 예외(BuildTool.cpp:408-412, FileHelper.cpp:222) |
| Step 5 premake · module_system_info | 도달 못 함. `Temp/CodeGen` 이 빈 폴더로 남아 다음 HeaderTool 도 대상 0 |
| HeaderTool 2회 | 종료 139, 생성물 0 |
| 게임 프로젝트 폴더 | 아무것도 안 써짐 |
| (수동) Step 3 lua → premake | 생성은 성공하지만 sln 이 엔진 루트의 `JGEngine.sln`. `Game` 프로젝트는 **1개뿐** — 게임 Game 이 엔진 Game 에 합쳐져 include 가 `..\..\Source\Runtime\Game;..\..\Source\Game;…`. `Editor.vcxproj` 는 include 첫 항목 `..\..\Source\Editor`, 출력 `..\..\Bin\DevelopEngine\`(엔진 Bin) |
| 대조군(같은 가짜 루트, `UserWorkCategories = []`) | Step 1–5 완주, premake 실행, `module_system_info.json` 기록(11개), `Compelete Build Tool Run..` 뒤 종료 시 세그폴트(139). **멈춤은 게임 모듈 경로 때문**이다 |

**D4 평가 — 찬성. 앞서 권한 "프로젝트에 엔진 코드젠까지 생성"보다 낫다.** 엔진 소스와 엔진 코드젠이 항상 같은 트리에 있어 서로 어긋나지 않는다. 프로젝트 사본 방식이었다면 엔진 헤더가 바뀔 때마다 각 게임 프로젝트의 사본이 낡고, 그 오류가 게임 솔루션 안의 엔진 코드에서 터진다. 게임 코드젠에는 엔진 헤더 정보가 필요 없어(부모 클래스는 `JGType::GenerateType<부모>()` 로만 참조, HeaderTool.cpp:1097-1100) 프로젝트 모드 HeaderTool 은 게임 헤더만 보면 된다. 조건 4개:

| 조건 | 이유 |
|---|---|
| 프로젝트 모드는 엔진 코드젠을 만들지도 고치지도 않는다 (H3 · H5) | 엔진 트리 쓰기 0 원칙 유지. 엔진 코드젠은 엔진 PreBuild 소관 |
| 배치 2 는 엔진 코드젠이 없으면 멈추고 엔진 `GenerateProjectFiles.bat` 을 먼저 하라고 안내 (§2-2) | `Temp/` 는 git 미추적 → 새 클론 · Temp 삭제 뒤에는 없다 |
| 엔진에 리플렉션 헤더가 **추가**되면 게임 프로젝트도 배치 2 를 다시 돌린다 (가이드에 명시) | vcxproj 파일 목록은 생성 시점 글롭이라 새 `.generation.cpp` 가 게임 솔루션의 엔진 프로젝트에 안 들어간다 → 링크 오류 |
| HeaderTool 은 바뀐 파일만 쓴다 (H6) | 엔진 코드젠을 여러 솔루션 · 세션이 함께 읽게 되므로, 매번 다시 쓰면 엔진 PreBuild 한 번이 전부를 재컴파일시킨다 |

**D7 해석 순서**: EngineRoot 가 적혀 있으면 그것(절대경로 또는 프로젝트 기준 상대경로), 비어 있으면 `JGENGINE_ROOT`. 배치 1 은 만든 엔진의 경로를 기본으로 적는다. `.jgproject` 가 이기게 하는 이유: 병렬 작업은 에이전트마다 엔진 worktree 가 다른데 환경변수는 PC 에 하나라 모든 프로젝트를 한 엔진으로 끌고 간다. 다른 PC 와 공유할 프로젝트는 EngineRoot 를 비워 두고 각자 환경변수로 가리킨다.
