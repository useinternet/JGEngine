2026-10-02 낮 · GameFrameWorks 게임 UI(UI/) · 게임 프로젝트 요청 ER-010(글 서식) · ER-011(글꼴 아틀라스 용량) · 결정: "권고 대로 진행"(D-17 · D-18) · 상태: 메인 트리 반영, 미커밋(커밋은 사용자 — GG-C2)

요약. 글자 요소에 문단 서식(줄 간격 · 자간 · 장평 · 문단 간격 · 요소 전체 합성 굵게/기울임)과 양쪽 맞춤을 넣었고, 글 안 마크업(<b> <i> <color=#…> <hscale=…>)으로 글의 일부만 굵게 · 기울임 · 색 · 장평을 바꿀 수 있게 했습니다. 글꼴 아틀라스는 한 장이 차면 새 페이지를 열고, 상한(기본 4장)에서는 이번 프레임에 쓰지 않은 가장 오래된 페이지를 비워 다시 씁니다. 글꼴에 없는 글자는 대체 글꼴로 그립니다.

결과. 헤드리스 셀프 테스트 243/243(요청서 완료 기준 포함), 기존 회귀 통과, 메인 트리 빌드 오류 0. 검증 게임에 서식 패널을 붙여 에디터 실제 입력 20단계를 다시 통과했고, 디버거 아래에서 실행 중 D3D12 메시지는 0건이었습니다. 두 아틀라스 페이지의 글자가 한 줄에 함께 그려지는 것도 화면에서 확인했습니다.

남은 일. 커밋(사용자), 실제 한글 IME 확인(GG-9U). 확인해 주신 GUI 3-5(imgui.ini 추적 해제 · 백업 zip 삭제)는 끝냈습니다. 구간 글꼴 바꾸기 · 글 사이 그림 · 아틀라스 부분 갱신은 보류 표에 있습니다.

2. 쓰는 법 — 글 서식 (ER-010, GG-10)

할 일방법
문단 서식HGameUIParagraphStyle을 text->SetParagraphStyle(style). LineHeight(기준선 사이, 0 = 글꼴 기본) · LetterSpacing(1/1000 em, 글자 사이에만, 음수 가능) · HorizontalScale(1.0 = 100%) · ParagraphSpacing(줄바꿈 문자 다음 문단 앞) · bBold · bItalic(요소 전체 합성)
양쪽 맞춤SetAlignment(EGameUIHorizontalAlign::Justify, …) + 줄바꿈(Word · Character). 자동으로 바뀐 줄만 폭에 맞추고, 문단 마지막 줄 · 말줄임 줄은 왼쪽. 남는 폭은 글자 사이에 나누되 띄어쓰기 뒤에 4배를 줍니다(띄어쓰기가 적은 한글 줄도 고르게 펴짐)
구간 서식SetRichText(true) 뒤 글에 <b>…</b> <i>…</i> <color=#RRGGBB>…</color>(또는 #RRGGBBAA) <hscale=140>…</hscale>(퍼센트). 겹쳐 쓸 수 있습니다. 글자 그대로의 꺾쇠 · & 는 &lt; &gt; &amp;. 모르는 태그 · 짝 없는 닫는 태그 · 잘못된 값은 글자 그대로 보입니다(글이 조용히 사라지지 않음). 기본은 꺼짐
합성 방식굵게 = 글자마다 폭 + em/24, 커버리지를 넓힌 글리프를 따로 래스터화 · 기울임 = 기준선을 축으로 12° 비튼 사각형(폭은 그대로) · 장평 = 그 폭으로 래스터화(늘린 그림이 아니라 선명함). 굵은 · 기울임 글꼴 면은 아직 쓰지 않습니다(GG-H25)
측정MeasureContent(width, manager)와 새 LayoutContent(width, manager, layout)(그리기와 같은 줄 · 글자 자리)가 서식을 반영합니다. 직접 배치는 PGameUIFont::LayoutText(text, HGameUITextLayoutOptions, layout). 지금까지의 7인자 LayoutText는 서식 없는 배치 그대로입니다
text->SetRichText(true);
text->SetText(PString("<b>굵게</b> 보통 <i>기울임</i> <color=#FF5A5A>빨강</color> <hscale=140>넓게</hscale>"));

HGameUIParagraphStyle style;
style.LineHeight    = 45.0f;     // 35px 본문
style.LetterSpacing = -100.0f;   // -0.1 em
text->SetParagraphStyle(style);
text->SetWrap(EGameUITextWrap::Word);
text->SetAlignment(EGameUIHorizontalAlign::Justify, EGameUIVerticalAlign::Top);

3. 쓰는 법 — 글꼴 아틀라스 · 대체 (ER-011, GG-11)

할 일방법
기본 동작바뀌었습니다. 1024² 페이지(4MB)가 차면 새 페이지를 엽니다. 상한에서는 이번 프레임에 쓰지 않은 가장 오래된 페이지를 비우고 다시 채웁니다(비운 글자는 다음에 쓸 때 다시 래스터화). 게임 코드를 바꾸지 않아도 글자가 빠지지 않습니다
상한font->SetAtlasPageLimit(n)(기본 4). 한 프레임에 상한보다 많이 필요하면 상한을 넘겨 열고 경고 "Font atlas needs more than N pages in one frame"을 한 번 남깁니다. 넘겨 연 페이지와 줄인 상한은 ClearGlyphs까지 남습니다
비우기font->ClearGlyphs() — 글리프와 페이지를 모두 비웁니다(화면을 크게 바꿀 때). 그리기 목록을 만들기 전에 부릅니다
확인GetAtlasPageCount() · GetAtlasStats()(페이지 수 · 상한 · 사용률 · 비운 페이지 · 상한 넘김) · GetGlyphCount()
글꼴 대체font->SetFallbackFont(other)(사슬 가능, 돌면 거부). 이 글꼴에 없는 글자는 대체 글꼴의 폭 · 글리프로 배치하고 그립니다. 줄 높이 · 기준선은 원래 글꼴, 다른 글꼴 사이 커닝은 0. HasGlyph는 대체 사슬까지 봅니다. 글꼴을 준비할 때(그리기 전) 정합니다

5. 알아둘 것

항목내용
빌드첫 빌드에서 C2280이 났습니다. PGameUIFont가 DLL 내보내기 클래스라, 막지 않으면 컴파일러가 복사 대입을 만들어 내보내려 하고, 이동만 되는 아틀라스 페이지(4MB)와 부딪힙니다. 글꼴 복사를 금지해 해결했습니다.
프레임"이번 프레임" = 관리자가 그리기 목록을 한 번 만드는 동안(PGameUIFont::BeginFrame). 관리자는 목록을 만들자마자 그리므로 관리자가 여럿이어도 안전합니다. 헤드리스처럼 그리기 목록을 만들지 않으면 비우지 않고 상한을 넘깁니다.
기울임폭이 그대로라 기울인 글자가 다음 글자 쪽으로 조금 넘어갑니다. 진짜 기울임 글꼴 면은 보류(GG-H25)입니다.
API 변경GetGlyph는 값으로 돌려줍니다(글리프에 페이지 · 글꼴), GetAtlasTexture(page) · GetAtlasPixels(page), IsAtlasFull 삭제. 게임 프로젝트 코드에서 쓰는 곳이 없음을 확인했습니다. 엔진 헤더가 바뀌었으니 게임 솔루션은 다시 빌드합니다.
범위 밖구간 글꼴 바꾸기 · 글 사이 그림 · 로컬라이제이션(GG-H3), 바뀐 사각형만 올리는 부분 갱신 · 1채널 아틀라스(GG-H4 — Graphics 기능 필요), 굵은 · 기울임 글꼴 면(GG-H25).
