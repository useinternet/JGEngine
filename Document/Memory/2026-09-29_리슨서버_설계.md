## 이번에 확인한 사실 (코드에 적혀 있지 않은 것)
- 엔진 어디에도 네트워크 코드 · 라이브러리가 없다(ThirdParty: assimp · rapidjson · spdlog · stb · zlib). `DevScene.cpp` 의 "enet" 검색 적중은 `SceneTexture` 오탐.
- **Winsock 포함 순서:** PCH 가 `d3d12.h`(`PCH.h:27`) · `Rpc.h`(`PCH.h:43`)로, Core 가 `PlatformDefines.h:7` 로 `Windows.h` 를 `WIN32_LEAN_AND_MEAN` 없이 들여와 구버전 `winsock.h` 가 먼저 들어간다. 뒤에 `winsock2.h` 를 넣으면 오류 102건(C2011 `sockaddr` …). `winsock2.h` 를 PCH 맨 앞에 두면 빌드 · `WSAStartup` 성공.
- `PName` ID = `GStringTable::RegisterString` → `PString::GetStringTableID()` → `_stringCode` = `std::hash<std::string>`(`String.cpp:433`, `Hash.h:25`). 내용 해시라 같은 빌드면 프로세스 간 같다 → 이름 인터닝 순서는 결정론 위험이 아니다.
- zlib 은 PCH 의 `#pragma comment(lib, "zlibstatic.lib")`(`PCH.h:47`)로 이미 링크된다(사용처는 `Graphics/Classes/Texture.cpp`).
- 시스템 라이브러리 링크는 `#pragma comment(lib, …)` 관례(PCH.h). `ws2_32.lib` 도 같은 식.
- 커널 `Validate` 는 보낸 연결을 모른다 — 내장 `EndTurn` 은 `CurrentActor`, `ResolveChoice` 는 `Chooser` 인지만 본다(`GameplayRuleEngine.cpp:51, 72`). 소유 검사는 세션 몫.
- 게임 명령(핸들러)에는 엔진이 "현재 행동자만"을 강제하지 않는다 — `handler->Validate` 에 맡긴다(`GameplayRuleEngine.cpp:80-87`). 그래서 차례 밖 명령(신속 카드 등)은 게임 규칙으로 허용할 수 있다. 엔진이 막는 것은 선택 대기 중의 다른 명령뿐이다(`:59-63`).
- `PGameplayAgentRunner::Step` 은 `PGameMaster::Submit` 을 직접 부른다 → 호스트 AI 명령이 방송을 건너뛰므로 "고르기"와 "Submit" 분리 필요.
- `JGLauncher/Main.cpp:6` 의 `main()` 은 인자를 받지 않는다(`-host`/`-join` 경로 없음). `HCoreSystemArguments` 에도 명령줄 필드가 없다.
- 이번 세션 도중(11:15~11:24) 다른 세션이 `Simulation` → `GameMaster/Gameplay` 이름 변경을 소스에 적용했다. 보고서는 새 이름 기준이다. JGConsole 명령은 `gmtest`(구 `simtest` 도 받음).
- boardgame.io 문서 확인: 무브는 기본으로 클라 · 서버 양쪽 실행, 비밀 상태는 `playerView`(`PlayerView.STRIP_SECRETS`), 비밀에 닿는 무브는 `client: false` 로 서버 전용 — 방안 A → C 의 실례.
