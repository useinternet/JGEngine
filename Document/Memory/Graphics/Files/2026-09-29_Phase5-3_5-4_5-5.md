# 2026-09-29 Phase 5-3 · 5-4 · 5-5

## 결론
- **5-3 로그 포맷:** `JG_LOG`는 printf 방식이라 `{0}`은 글자 그대로 찍히고 인자가 버려졌다. 10곳을 `%s`/`%d`로 바꿨다. `Json.h`의 정의되지 않은 매크로는 `static_assert`로 바꿨다.
- **5-4 셰이더 타깃:** FXC는 셰이더 모델 5.1까지라 `cs_6_0`이면 컴퓨트 셰이더가 전부 실패했다. `cs_5_1`로 바꿨고 FXC는 유지한다.
- **5-5 프레임 파이프라이닝:** 프레임 2개가 GPU에 겹쳐 올라간다. **지금 장면에서는 효과가 없다**(CPU 병목, 이전에도 대기 0.005ms/프레임). GPU가 병목인 부하에서는 13.7ms → 9.9ms(73 → 101fps). 겹침이 실제로 일어난 실행에서도 오류와 D3D12 메시지는 0이었다.

## 알아 둘 것
- `JG_LOG` 형식 문자열은 printf 방식이다(`PString::Format` → snprintf). fmt 방식(`{0}`)은 에러 없이 그대로 찍힌다.
- `PSharedPtr`에는 `operator bool`이 없다. `if (auto p = ...)`는 컴파일되지 않으니 `.IsValid()`를 쓴다.
- `HDirectXAPI`와 `PCommandQueue`는 Graphics.dll에서 내보내지 않는다. GUI 같은 다른 모듈은 `PDirectX12API`(GRAPHICS_API)의 메서드를 쓴다.
- 새 GPU 가시 데이터를 매 프레임 CPU에서 쓰는 코드를 넣을 때는 `GetFrameIndex()`로 나눠 쓰거나 리스트의 업로드 할당자를 쓴다.
- 인스턴스 부하는 depth 테스트 덕분에 픽셀 비용 없이 정점 비용만 늘려, CPU 시간을 그대로 둔 채 GPU만 무겁게 만든다(`frame_timing_snippet.cpp.txt` (C)).
