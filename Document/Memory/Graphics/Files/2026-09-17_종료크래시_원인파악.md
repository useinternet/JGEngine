# 2026-09-17 작업 기록 — 종료 시 크래시 원인 파악

## 요청
애플리케이션 종료 시 `PResourceStateTracker::UnRegisterResource` → `std::_Hash::_Find_last` 크래시 원인 파악.

## 수행 내용
콜스택 각 프레임을 실제 소스와 대조하고, `Bin/DevelopEngine/jg_log.txt` 종료 구간을 확인해 원인을 특정했다.
**분석만 수행했고 코드 수정은 하지 않았다.**

## 결과 요약
이미 GC로 파괴된 `PDirectX12API` 인스턴스에 대한 **use-after-free**.

- `HDirectXAPI::getDX12API()` (DirectX12API.cpp:472) 가 `static PDirectX12API* cachedAPI` 에
  raw 포인터를 캐시해두고 **무효화하지 않는다.**
- `PDirectX12API`는 `IMemoryObject` 파생이라 엔진 GC 관리 대상이며,
  `HJGGraphicsModule::ShutdownModule()` 이 `_graphicsAPI = nullptr` 한 직후
  `GModuleGlobalSystem::Destroy()` (Module.cpp:192) 의 GC Flush에서 파괴된다.
- `AllocatedMemoryBlockQueue`가 FIFO라 부팅 초기 할당된 `PDirectX12API`가
  텍스처/버퍼보다 **항상 먼저** 파괴된다.
- 이후 `~PDX12Texture()` → `HDirectXAPI::DestroyCommittedResource()` 가 죽은 포인터로
  `_resourceRefCache.find()` 를 호출 → 해제된 버킷 체인 순회 → `_Find_last` 크래시.

보조 원인:
- `HDirectXAPI::` 정적 래퍼 전부 `getDX12API()` 반환값 null 체크 없음 → 캐시만 고치면 nullptr 크래시로 바뀜.
- `GModuleGlobalSystem::Destroy()` 가 `HHashMap` 순회 순서로 Shutdown → 모듈 파괴 순서 비결정적.

동일 크래시 경로를 가진 타입: `DX12Texture`, `DX12VertexBuffer`, `DX12IndexBuffer`,
`DX12ConstantBuffer`, `DX12StructuredBuffer`, `UploadAllocator`.
