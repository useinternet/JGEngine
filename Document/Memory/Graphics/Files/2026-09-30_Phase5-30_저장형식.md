## 2. 바꾼 것

| 파일 | 내용 |
|---|---|
| `Core/FileIO/Json.h/.cpp` | `PJsonData::AddBinaryMember(key, data, size)`(base64 문자열 멤버), `GetBinaryData(HList<uint8>*)`(이 값을 바이트로), `IsString()`. base64(RFC 4648, '=' 채움)는 `Json.cpp` 안 익명 함수. 인코딩 결과를 `PString`에 넣지 않는다(PString은 만들 때마다 전체 해시) |
| `Graphics/Classes/Texture.cpp` | `WriteJson`: zlib 압축 픽셀 → `AddBinaryMember("Pixels")`. `ReadJson`: `FindMember("Pixels")` 한 번 → 문자열이면 base64, 배열이면 옛 형식 |
| `Graphics/Classes/StaticMesh.cpp` | `HStaticSubMesh::WriteJson`: `VertexStride`(56) + `Vertexes`(HVertexData 바이트) + `Indexes`(uint32 바이트)를 base64로. 메시는 zlib 안 함(float는 잘 안 줄고 base64만으로 12배 감소). `ReadJson`: 문자열이면 새 형식(스트라이드 · 크기 검사, 틀리면 오류 로그), 아니면 옛 배열 |

새 파일 모양(메타데이터는 그대로 읽히는 JSON, 큰 배열만 한 줄 문자열):

```
"SubMeshName": "Beta_Surface",
"VertexStride": 56,
"Vertexes": "a+MuQdMPxELT5QvB...(한 줄)",
"Indexes": "AwAAAAIAAAABAAAA...(한 줄)"
...
"Pixels": "eJwA/z8AwAU5HEQE...(5,594,120자 = 4,195,590B)"      ← zlib 헤더(0x78 0x9C)가 "eJ"
```

## 5. 다음 에이전트 참고

- **`PJsonData::FindMember`는 값을 옮겨 온다.** `result._value = doc[key]`는 rapidjson 대입이라 이동이다. 같은 키를 두 번 찾으면 두 번째는 null이다. 형식을 가를 때는 한 번 찾아 둔 값에 `IsString()`을 묻는다(이번 `ReadJson` 두 곳).
- 새 형식 에셋은 옛 코드(이 변경 전 바이너리)로 읽을 수 없다. 옛 형식 에셋은 새 코드로 읽힌다.
- `VertexStride`는 `HVertexData` 배치가 바뀔 때 옛 에셋을 조용히 깨뜨리지 않으려는 검사다. 배치를 바꾸면 옛 에셋을 변환할 경로가 필요하다.
