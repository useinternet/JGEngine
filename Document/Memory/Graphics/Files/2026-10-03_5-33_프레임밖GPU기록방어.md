## 1. 문제와 원인

| # | 장면 | 원인 | 수정 전 결과 |
|---|---|---|---|
| ① | 콘솔 명령 안에서 렌더러(`PSceneRenderer`)를 만들어 Render → Resize → Render → 버림 | DevConsole 입력은 `GConsoleCommandGlobalSystem::Update` — 스케줄러 프레임(End() 제출) **뒤** — 에서 실행된다. 기록은 다음 프레임 리스트로 가는데, 다음 갱신 첫머리의 메모리 GC 가 버린 텍스처를 파괴하면서 `UnRegisterResource` 로 상태 기록을 지운다. 다음 End() 에서 보류 배리어(리스트의 첫 상태 전이)가 대상을 못 찾아 빠진다 | D3D12 [538](COMMON 상태에서 ClearRenderTargetView · ClearDepthStencilView) 16 + [527](ResourceBarrier 이전 상태 불일치) 12 = 28줄 — GFW 실측과 같은 수 |
| ② | 같은 콘솔 명령을 GPU 가 바쁠 때(앞 프레임이 GPU 에서 아직 실행 중) | 프레임 밖 `RequestCommandList` 는 `Begin()` 의 펜스 대기 전에 그 프레임 인덱스의 리스트(FramesInFlight 프레임 전에 제출된 것)를 `Reset` 한다 | GPU 부하(`JG_GPUSTRESS=20000`)에서 D3D12 [552] "command allocator is being reset before previous executions associated with the allocator have completed" 2줄(+ ① 28줄) |

프레임 안(GraphicsBegin ~ GraphicsEnd 사이 단계 — 게임 화면 · 에디터 화면 · DevScene)에서는 GC 가 제출 뒤에 돌고 `Begin()` 이 이미 기다렸으므로 둘 다 생기지 않았다.

## 2. 바꾼 것 (메인, 미커밋 — Graphics 파일만)

| 파일 | 내용 |
|---|---|
| `DirectX12/DirectX12API.cpp` | `DestroyCommittedResource`: 큐가 있으면 `PResourceStateTracker::ReleaseResource`(놓음 표시만) + `DeferRelease`, 큐가 없으면(종료 뒤) 예전처럼 바로 `UnRegisterResource` |
| `DirectX12/Classes/ResourceStateTracker.h/.cpp` | `HResourceInfo::bReleased`, `ReleaseResource()`, `IsRegistered()` = 등록돼 있고 놓지 않음(스테이징 관리자가 "대상 소유자가 파괴됨"을 판단하는 뜻은 그대로) |
| `DirectX12/Classes/CommandQueue.h/.cpp` | 미룬 해제가 리소스를 놓을 때 `UnRegisterResource`(뮤텍스 밖에서, 참조를 놓기 전에) — `releaseDeferred` · `ReleaseAllDeferred` → `unregisterReleased`. `RequestCommandList` 가 닫힌 리스트를 Reset 하기 전에 `waitForFrameReuse` — 그 인덱스의 마지막 제출이 GPU 에서 안 끝났으면 기다리고 Trace 로그 한 줄 |

다른 세션 파일은 건드리지 않았다(콘솔 명령 실행 시점 · Core 그대로). 메인 빌드는 Graphics 만 다시 링크(7초).

동작 변화: 상태 추적의 "Remove Counting Resource / UnRegister …" Trace 로그가 해제 때가 아니라 그 프레임의 GPU 작업이 끝난 뒤(보통 2프레임 뒤)에 찍힌다. 종료 때(`Destroy()` 가 상태 맵을 먼저 비움)는 이 로그가 안 찍힌다.
