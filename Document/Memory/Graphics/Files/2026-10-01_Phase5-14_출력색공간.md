# Phase 5-14 출력 색 공간: 8비트 sRGB 출력 (2026-10-01)

- 결정: 사용자 2026-10-01 "a ㄱㄱ" = D-3 (a) 8비트 sRGB 출력, 장면은 FP16 선형 그대로 · 마지막에 sRGB 변환.
- 상태: 구현 · 검증 완료, 메인 트리 반영 · 빌드(13:33), 미커밋.

## 1. 문제 (전)

출력 버퍼가 `R16G16B16A16_Float`라 OS(DWM)가 값을 선형(scRGB)으로 보고 sRGB로 한 번 더 인코딩했다. 3D는 선형으로 계산하니 맞게 보였지만, sRGB로 정한 색(ImGui 테마 · 에디터 팔레트 · 게임 UI)은 두 번 인코딩돼 옅게 보였고(창 배경 0.06 → `#454545`), 반투명은 선형 공간에서 섞여 진하게 보였다. 각 트랙이 국소 보정(`HGUI::DisplayColor`의 sRGB → 선형, 메모리 창 `displayColor`, 알파 낮추기)을 넣고 있었다.

## 5. 다음 에이전트 참고

- 화면에 보여 줄 장면 결과는 `PSceneRenderer::GetDisplayTexture()`. `GetOutputTexture()`는 선형이라 GUI로 그대로 보이면 어둡다.
- UI 색(ImGui · 에디터 팔레트 · 게임 UI)은 sRGB 값을 그대로 쓴다. `HGUI::DisplayColor`는 이제 변환이 없다. 반투명은 sRGB 공간에서 섞인다(디자인 도구와 같음).
- 3D 텍스처(알베도)는 5-29에서 `_SRGB` 포맷으로 읽어야 조명 계산이 선형이 된다. 2D · UI 이미지는 UNORM 그대로(디스플레이에 그대로 나감).
- 톤매핑: 디스플레이 셰이더(`SceneRenderer.cpp` `DisplayShaderCode`)의 `saturate` 자리에 넣는다.
