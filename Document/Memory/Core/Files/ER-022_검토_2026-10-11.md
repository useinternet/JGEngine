### 3.2 모듈 구조

| 항목 | 제안 |
|---|---|
| 자리 | 새 `Source/Runtime/Audio/` + `Audio.module.json`(SharedLib, 의존 `Core` 만, `Defines ["_AUDIO"]`), `AudioDefines.h`(`AUDIO_API` · `AUDIO_C_API`), 모듈 클래스 `HAudioModule`(`JG_MODULE_IMPL`). 바깥 코드는 `Source/ThirdParty/miniaudio/miniaudio.h`(0.11.25 그대로 + LICENSE). 구현 .cpp 하나에서만 `stb_vorbis.c`(헤더 모드) → `miniaudio.h`(구현) → `stb_vorbis.c` 순으로 넣는다. 링크할 시스템 라이브러리는 없다(miniaudio 가 실행 중에 불러온다) |
| 공개 API | 정적 `HAudio`(요청서 모양). 엔진 헤더에 miniaudio 형은 나오지 않는다. `PlaySound(경로, 인자) → HAudioHandle`(인자: 묶음 · 크기 · 높낮이 · 되풀이 · 페이드 인 초), `Stop(핸들, 페이드 초)` · `Pause` · `Resume` · `IsPlaying`, `PlayMusic(경로, 페이드 초)` · `StopMusic(페이드 초)`(배경음 한 칸 편의 함수: 앞 곡은 줄며 멈추고 새 곡은 커지며 되풀이), `SetBusVolume` · `GetBusVolume(EAudioBus::Master · Music · Effects)`, `SetBackgroundMode(그대로 · 줄이기(크기) · 끄기)`, `Preload(경로)`(첫 재생 끊김 막기), `StopAll(페이드 초)`. 두 번째 분위기 소리는 `PlaySound(…, 되풀이 + Music 묶음 + 페이드 인)` 로 낸다 |
| 소리 이름 | 토큰 경로 + 확장자(`/JGGame/Sounds/UI/CardPlay.wav`). 게임 UI 글꼴 · 그림, 데이터 테이블 AssetRef 칸과 같은 방식이다. 요청서 예의 짧은 이름(`UI/CardPlay`)은 게임이 감싼다 |
| 연결 | 소리를 쓰는 게임 모듈만 연결한다: `module.json` `ModuleDependencies` 에 `Audio`(빌드 · 패키지에 담기), `StartupModule` 에서 `ConnectModule("Audio")`(템플릿의 GameFrameWorks 줄과 같다). 에디터 · GameHost 목록은 그대로다. JGConsole 엔진 목록(`Main.cpp:19`)에만 `Audio` 를 더해 헤드리스 자체 검사 `audio.selftest` 를 부른다(DevOps 파일 한 줄 — 알리고 넣는다) |
| 시작 · 종료 | `StartupModule` 에서 전역 시스템(`GAudioGlobalSystem` — 매 프레임 `Update` 에서 끝난 소리 정리 · 앱 활성 처리)을 등록하고 장치를 연다. 창이 없으면(`MainWindow` null — 헤드리스) 장치를 열지 않는다. 시스템 `Destroy` 가 모든 모듈 `ShutdownModule` 보다 먼저 돌므로(`CoreSystem.cpp:255-298`) `Destroy` 에서 모든 소리와 장치를 닫고, 그 뒤의 API 부르기는 아무 일도 하지 않는다. 매 프레임 일은 스케줄러(`ScheduleByFrame`)가 아니라 전역 시스템 `Update` 에 둔다 — 스케줄러에는 빼는 API 가 없어 모듈을 끊은 뒤에도 Raw 작업이 불린다 |
| 스레드 | 섞기는 miniaudio 오디오 스레드, 흘려 풀기 · 미리 풀기는 miniaudio 작업 스레드 1개가 한다. 엔진 스케줄러에는 올리지 않는다 — 오래 도는 작업이 에셋 로드 줄을 막는다(`Thread.cpp:44` 바쁜 스레드를 쉬는 것으로 본다, 코드로 읽은 것). 오디오 스레드 안에서는 엔진 로그 · 엔진 할당을 하지 않고, 알릴 일은 메인 스레드 `Update` 에서 남긴다 |

### 3.3 파일 · 패키징

| 항목 | 제안 |
|---|---|
| 읽기 | 토큰 경로 → `EngineContentDirectory()` · `GameContentDirectory()` + 상대 경로 → `HFileHelper::ReadAllBytes` 로 통째 읽기 → miniaudio 파일 갈고리(VFS)가 그 메모리에서 읽는다. 패키지 읽기 검사를 그대로 통과한다. 디스크에서 조금씩 읽는 새 파일 API 는 만들지 않는다(음악 파일이 수 MB 라 필요 없다) |
| 효과음 | 처음 한 번 끝까지 풀어 두고(같은 경로는 공유 · 참조 수), 재생마다 가벼운 인스턴스를 만든다. 겹치기 수 제한은 두지 않고 동시 재생 수를 통계로 남긴다 |
| 긴 음악 | 흘려 풀기: 압축 파일(ogg)은 메모리에 통째 두고, 푸는 것만 약 2초씩 한다. 3분 128kbps ogg ≈ 2.9MB. 음악을 wav 로 두면 3분에 약 33MB(48kHz 스테레오 16비트)가 메모리에 올라간다 → 음악은 ogg 권장 |
| 쿠킹 | 바꿀 것 없다. Content 안 소리 파일이 그대로 패키지에 들어간다. 엔진 Content 에 소리를 두면 모든 게임 패키지에 들어가므로 엔진은 소리 파일을 두지 않는다(자체 검사 소리는 코드로 만든다) |
| 스모크 | 장치가 없거나 열리지 않으면 Warning(오류 아님) — 스모크가 실패하지 않게. 소리 파일이 없거나 못 풀면 Error — 패키지에서 빠진 소리를 스모크가 잡는다 |

### 3.4 게임 연결

| 자리 | 방법 |
|---|---|
| 게임 UI 움직임(D-32) | 묶음의 함수 부르기 단계: `.Call([]() { HAudio::PlaySound("/JGGame/Sounds/Card/Land.wav"); })`. 엔진 변경 없음 |
| 연출 큐 | 게임 큐 코드(`Begin` · `Tick`)에서 부르거나, 큐가 UI 묶음을 쓰고 그 안 부르기 단계에서 낸다(ER-017 검토의 "큐가 UI 묶음을 쓰면 된다" 방식). 모두 건너뛰기 주의는 §2 |
| 단추 · 끌기 | `PGameUIButton::OnClicked`, 끌기 이벤트에서 부른다 |
| 설정 화면 | 게임이 `SetBusVolume` 을 부르고, 값은 게임 인스턴스 · `Saved/` 에 저장한다 |

### 3.5 위험 · 주의

| 항목 | 내용 |
|---|---|
| 바깥 파일 크기 | miniaudio 3.9MB 한 파일. 구현 .cpp 하나에만 넣고 PCH 에는 넣지 않는다. 컴파일 시간은 미측정(1단계에서 잰다). 판마다 ABI 가 달라 판을 고정해 둔다(0.11.25) |
| 장치가 없는 PC | miniaudio 는 WASAPI → DirectSound → WinMM → Null(무음) 순으로 열어 장치가 없어도 시작한다. 소스로 확인했고 실제 장치 없는 PC 에서는 미확인이다. 무음 장치를 강제로 쓰는 시험(자체 검사)으로 대신 확인하고, 실기는 사용자 PC 에서 장치를 끈 상태 확인을 부탁한다(에이전트는 시스템 설정을 바꾸지 않는다) |
| ogg 되감기 | stb_vorbis 를 파일 갈고리로 쓰면 곡 길이를 모르고, 뒤로 감기는 처음부터 다시 푼다. 되풀이(처음으로 감기)는 문제없다. 곡 중간으로 감기는 1차 범위 밖 |
| stb_vorbis 취약점 | v1.22 에는 고쳐지지 않은 취약점 보고가 여러 건 있다(조작한 .ogg 를 열 때 — 2023 · 2026 NVD, 10-11 검색). 우리 패키지 안 파일만 재생하면 위험이 낮다. 사용자가 고른 소리 파일 · 모드를 읽게 되면 그때 libvorbis 로 바꾼다 |
| COM | 엔진은 지금 COM 을 쓰지 않는다(엔진 소스 검색 0). miniaudio WASAPI 쪽은 COM 을 초기화한다(방식은 1단계에서 확인). 나중에 메인 스레드에서 단일 스레드 방식 COM(파일 대화 상자 등)을 쓰게 되면 초기화 방식을 맞춘다 |
| 종료 순서 | 시스템 `Destroy` 가 모든 모듈 `ShutdownModule` 보다 먼저라, 게임이 종료 중에 `HAudio` 를 불러도 아무 일이 없게 만든다(장치 · 소리는 `Destroy` 에서 닫음) |
| 메모리 통계 | miniaudio 는 자기 할당(malloc)을 쓴다 → 메모리 통계 창에 소리 메모리가 안 보인다. 엔진 풀로 돌리는 것은 문제가 생기면 한다(지금은 하지 않음) |
| 쿠킹 스모크 소리 | 스모크(300프레임)에서 게임이 배경음을 틀면 쿠킹 PC 에서 몇 초 들린다. 거슬리면 스모크에 무음 인자를 붙인다(보류) |
| 데이터 테이블 AssetRef | 게임이 소리 경로를 AssetRef 칸에 쓰면 쿠킹 참조 검사는 통과하지만 `HAssetPath` 가 .wav · .ogg 마다 "NOT Support Format" 경고를 낸다 → 그런 쓰임이 생기면 경고 대상에서 소리 확장자를 뺀다(Asset, 몇 줄) |
| 에디터 | 게임 모듈이 오디오를 연결하므로 프로젝트 없는 에디터는 지금과 같다. 에디터에서 게임을 띄우면 소리가 나고, 에디터가 뒤로 가면 창 비활성 설정을 따른다 |

## 6. 완료 기준 측정 계획

| # | 측정 |
|---|---|
| (a) 겹치기 | 자체 검사: 장치 없이(`noDevice`) 같은 시험음을 10ms 간격으로 8번 낸다 → 섞은 출력의 최대 진폭이 1번보다 크고, 동시 재생 수 8 → 끝나면 0(정리됨). 검증 게임: 효과음 단추를 빠르게 여러 번 → 로그의 동시 재생 수 + 실제 출력 녹음(아래)에 겹친 소리 |
| (b) 되풀이 · 페이드 | 자체 검사: 0.5초 시험음을 되풀이해 3초 읽기 → 이음매에 빈 구간 없음(짧은 창마다 RMS 가 문턱 이상). `PlayMusic` 으로 곡 바꾸기(1초 페이드) → 앞 곡 크기가 1초 동안 1 → 0 으로 줄고 멈춤, 새 곡은 0 → 1 |
| (c) 묶음 크기 | 자체 검사: 효과음 묶음 0.5 → 출력 RMS 0.5배(±2%), 0 → 무음, Master 0 → 전부 무음, 바꾼 값이 다음 읽기에 바로 반영. 검증 게임: 막대로 크기를 바꾸면 녹음 RMS 가 따라간다 |
| (d) 패키지 | 검증 게임 쿠킹(스모크 오류 0) → 패키지 exe 실행 → 로그(장치 이름 · 소리 파일 읽음 · Content 밖 읽기 0) + 실제 출력 녹음 RMS 가 문턱 이상. 사용자 귀 확인도 부탁한다 |
| (e) 안 쓰는 게임 · 장치 없음 | 오디오를 연결하지 않는 호스트 · 게임은 모듈 목록이 그대로다 → 회귀 7종(gmtest · gameui · input · console · datatable · cookcheck · net.test) · 에디터 종료 0 · live 0. 장치 없음: 무음 장치 강제 실행에서 Warning 1줄 · API 전부 조용히 · 종료 0. 헤드리스 `JGConsole.exe audio.selftest` OK · live 0 |

실제 출력 녹음은 WASAPI loopback(miniaudio loopback 장치)으로 시스템 출력 전체를 잡는다. 다른 앱 소리가 섞일 수 있어 수치는 "소리가 났다 · 안 났다" 판정에만 쓰고, 녹음 파일은 남기지 않는다(수치만).
