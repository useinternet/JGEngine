[원인] Source/Runtime/Core/Misc/Delegate.h
- AddLambda(LambdaType&&) · BindLambda(LambdaType&&) → CreateLambda(TLambda&&) 는 전달 참조라, 왼값을 넘기면 TLambda 가 참조 형(std::function<void()>& 등)으로 추론된다.
- CreateLambda 가 그 TLambda 를 그대로 PLambdaDelegate<TLambda, …> 에 넘겨 저장 멤버 "TLambda _lambda;" 가 참조 멤버가 됐다. 델리게이트 사본(Clone)도 같은 원본을 가리킨다.
  → 원래 변수가 사라지거나 바뀐 뒤 부르면 매달린 참조 / 바뀐 함수를 부른다.
- 같이 찾은 것: HMulticastDelegate::operator+=(T&& l) 가 CreateLambda(std::move(l)) — 왼값을 넘기면 부른 쪽의 람다 · std::function 을 옮겨 가 비워 버린다
  (엔진 · ProjectAH 에 delegate += 사용처 없음).

[수정] Delegate.h (+12/−3, 이 수정만)
- CreateLambda: PLambdaDelegate<std::decay_t<TLambda>, …> 로 값 형을 넘긴다(왼값은 복사, 오른값은 이동). BindLambda · AddLambda · += 는 모두 CreateLambda 를 지난다.
- PLambdaDelegate: 생성자를 복사(const TLambda&) · 이동(TLambda&&) 둘로 — TLambda 가 값 형이 된 뒤 왼값도 받게. Clone 용 생성자(const TLambda&, const tuple&)는 그대로.
- operator+=: std::move(l) → std::forward<T>(l).
- 부르는 쪽 모양은 그대로다. 게임 UI 움직임 PGameUITimeline::Call(TFunction&&)(GameUITween.h:178 — CreateLambda 로 넘김)도 같이 사본을 갖게 된다.
- 주의(바뀐 점): 복사할 수 없는 람다(unique_ptr 를 잡은 람다 등)를 왼값으로 넘기면 이제 컴파일 오류다(전에는 참조로 붙었다). 오른값은 전에도 Clone 이 복사를 요구해 안 됐다 —
  엔진 · ProjectAH 에 그런 쓰임 없음(아래 사용처).

[자체 검사 delegate.selftest — 람다 저장 9 검사 추가(25 → 34)]
- AddLambda 왼값 람다(상태 있는 mutable 람다): 구독을 두 번 불러도 원래 람다의 상태는 그대로(사본)
- AddLambda 왼값 std::function: 건 뒤 변수에 다른 함수를 넣어도 구독은 처음 함수
- 요청서 완료 기준: std::function 변수가 블록을 나가 사라진 뒤에도 구독이 정상으로 불림(예외 없음 · 결과 맞음)
- CreateLambda · BindLambda 왼값 람다도 사본, 델리게이트 사본(Clone)은 원본을 지운 뒤에도 자기 람다로 동작
- 덧붙인 인자(payload): 왼값 · 오른값 람다 모두 그대로 받음
- += 왼값 std::function: 원래 변수가 비지 않고(옮겨 가지 않음) 구독과 원래 변수 둘 다 동작
- 결과가 매번 같도록 짰다(상태 비교 · 변수 바꾸기). 매달린 참조를 직접 부르는 검사는 예외를 잡는다.
