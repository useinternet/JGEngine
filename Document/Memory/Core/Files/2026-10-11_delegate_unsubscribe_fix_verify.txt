1. PSPDelegate::GetOwner (옛 Delegate.h:255) 조건이 뒤집혀 있었다.
     return _object.IsValid() ? nullptr : _object.Pin().GetRawConstPointer();
   - 주인이 살아 있으면 nullptr → RemoveObject(owner) · IsBoundTo(owner) · ClearIfBoundTo(owner) 가 SP 구독을 못 찾는다.
   - 주인이 죽었으면 Pin() 이 nullptr → 역시 nullptr. 결국 SP 구독은 어떤 경우에도 주인으로 찾을 수 없었다.
2. 같은 패턴을 보다가 같은 파일(HMulticastDelegate)에서 함께 드러난 것:
   a. RemoveObject 가 맨 뒤 구독과 바꿔 지운 뒤 ++i 로 넘어가 바꿔 온 구독을 건너뛰었다. 같은 주인 구독이 2개 이상이면 하나가 남는다([r1, r2, r1] → [r1, r2]).
   b. 방송(BroadCast) 중의 Remove · RemoveObject · RemoveAll 은 Callback.Clear() 만 하고 핸들은 유효로 두었다.
      - 같은 방송의 뒤 순서에서 빈 콜백을 Execute → assert(_allocator.HasAllocation(), 옛 Delegate.h:680). 릴리스에서는 빈 저장소 호출.
      - 콜백이 자기 자신을 빼면 실행 중인 콜백의 저장소(캡처)를 그 자리에서 지웠다.
      - 지운 자리는 핸들이 유효라 Add 가 다시 쓰지 못하고 목록에 계속 남아, 다음 방송마다 같은 assert 가 난다.
3. 다른 델리게이트: PRawDelegate::GetOwner 는 _pObject 그대로(정상), 람다 · static 은 주인 없음(nullptr, 정상).
   단일 HDelegate 의 GetOwner · IsBoundTo · ClearIfBoundTo 는 인스턴스의 GetOwner 를 그대로 쓰므로 1 을 고치면 함께 고쳐진다.

- PSPDelegate::GetOwner → return _object.Pin().GetRawConstPointer();
  살아 있는 주인의 주소, 주인이 죽었으면 nullptr(같은 주소에 새 객체가 들어와도 맞지 않는다).
- HMulticastDelegate
  - 새 도우미 removeAt(i): 방송 중이면 핸들만 무효(남은 방송에서 건너뜀) + _bHasRemovedWhileLocked, 콜백은 방송이 끝날 때 지운다.
    방송 중이 아니면 맨 뒤와 바꿔 지우고, 맨 뒤가 i 자리로 왔으면 true(그 자리를 다시 본다).
  - RemoveObject: nullptr 이면 바로 반환, 유효 핸들 + 주인 일치만, removeAt 결과로 같은 자리 재검사.
  - Remove(handle): removeAt 사용.
  - RemoveAll: 방송 중이면 모든 핸들 무효 + 플래그(콜백은 지우지 않음), 아니면 clear.
  - Unlock: 가장 바깥 방송이 끝날 때(_locks == 0) 플래그가 있으면 핸들 무효 구독을 지운다.
  - Add: 방송 중에는 빈 자리를 다시 쓰지 않고 뒤에 붙인다(뺀 자리의 콜백이 아직 실행 중일 수 있다).
  - 이동 생성 · 이동 대입이 플래그도 옮긴다.
- 바꾸지 않음: BroadCast, Compress()(호출자 0 · 논리 오류 — 보류 3).
