문제: 한 패키지 폴더에서 같은 <Name>.exe 를 둘 이상 띄우면 모두 Saved/Logs/<Name>.log 를 연다 — 로그 시스템(GLogGlobalSystem)이 시작할 때
  파일을 비우고 spdlog 가 공유 모드(_SH_DENYNO)로 열어서, 뒤에 뜬 쪽이 앞 기록을 지우고 그 뒤 줄이 섞였다(게임 쪽 확인: 방장 "hosting on port" 줄이 지워짐).

== 1. 변경 — Source/Programs/JGGameLaunch/JGGameLaunch.cpp 한 파일(GP-D2 진입 DLL)
- claimLogFile: 기본 경로(<루트>/Saved/Logs/<exe 이름>.log)부터 <이름>_2.log, _3.log … (최대 32) 차례로, 파일을 OPEN_ALWAYS 로 열고
  (있는 내용은 건드리지 않음) 파일 끝 훨씬 뒤(0x7FFFFFFF00000000) 1 바이트에 LockFileEx 배타 잠금(LOCKFILE_FAIL_IMMEDIATELY).
  잠기면 그 이름은 이 실행 것 — 핸들을 게임이 끝날 때까지 쥔다. ERROR_LOCK_VIOLATION(다른 실행이 쥠) · ERROR_SHARING_VIOLATION(다른 프로그램이
  혼자 열어 둠)이면 다음 이름, 그 밖의 실패(권한 · 경로)면 예전처럼 기본 이름을 로그 시스템에 맡긴다.
  왜 이 방식: 잡기가 OS 에서 원자적(동시에 뜬 셋 중 하나만 이긴다), 프로세스가 죽어도 OS 가 푼다, 경로 표기가 달라도 같은 파일이면 같은 잠금,
  잠금 범위가 로그 내용 밖이라 로그 시스템의 비우기 · 덧붙여 쓰기와 부딪치지 않는다, 남는 파일 없음.
- -logfile=<경로>: 로그 파일을 고른다. 상대 경로는 <루트>/Saved/Logs 기준, 절대 경로는 그대로. 쓰는 중이면 같은 규칙으로 _2 …
- 로그 첫머리에 "[GameLaunch]: Log file <경로> (process <pid>)" 한 줄 — 다른 이름을 골랐으면 " - <기본 이름> is in use by another run of this package".
- 혼자 띄우면 이름 그대로(쿠킹 스모크 · 배포 실행기가 <Name>.log 를 읽는다). 개발 실행(JGLauncher · JGConsole 의 jg_log.txt)은 그대로 — 보류 MT-H1.
