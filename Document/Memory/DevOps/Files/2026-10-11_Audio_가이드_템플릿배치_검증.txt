== 4. 게임 템플릿 배치 실패 종료 코드 (GM-B5)
Core 보고: worktree 엔진으로 만든 게임을 메인으로 옮기며 .jgproject EngineRoot 만 바꾸자 Critical "belongs to engine … but this tool is in …" 이 나고도
  배치는 종료 0.
원인: 툴(JGHeaderTool · JGBuildTool)은 -project= 를 못 쓰면 "Not a usable game project" Critical + 종료 1, 엔진 GenerateGameProjectFiles.bat 도 1 을
  돌려준다. 게임 쪽 GenerateProjectFiles.bat(템플릿) 마지막 줄 "if errorlevel 1 pause" 에서 pause 가 배치를 0 으로 끝낸다.
  스크래치 실험: call 한 배치가 exit /b 1 → "if errorlevel 1 pause" 로 끝나면 cmd /c 종료 0, "if errorlevel 1 ( pause / exit /b 1 )" 이면 1.
고침: Build/Templates/GameProject/GenerateProjectFiles.bat 마지막 줄 → if errorlevel 1 ( pause · exit /b 1 ) + 주석 2줄(CRLF 유지).
  템플릿은 배치 1 이 디스크에서 읽으므로 다시 빌드할 것 없음. 이미 만든 게임 프로젝트(ProjectAH · Temp/Games)의 배치는 그대로 — 가이드 6절에 바꾸는 법.
실제 툴로 확인(메인 Bin, MainTree exec, 검증 게임 Temp/Games/TplCheck — 확인 뒤 삭제):
  배치 1 CreateGameProject.bat → exit 0, 생성된 GenerateProjectFiles.bat 에 새 마지막 줄(엔진 경로 C:\Develop\JGEngine 치환)
  배치 2 정상 → exit 0, TplCheck.sln 생성 ("[GenerateGameProjectFiles] done")
  Project.EngineRoot 를 C:/Develop/JGEngine/Temp/Games 로(다른 엔진 흉내) → 새 배치 exit 1:
    [critical][Core]: Project TplCheck belongs to engine C:/Develop/JGEngine/Temp/Games/, but this tool is in C:/Develop/JGEngine/. Use that engine's batch files or fix EngineRoot
    [critical][HeaderTool]: Not a usable game project: C:\Develop\JGEngine\Temp\Games\TplCheck
    [GenerateGameProjectFiles] failed. See the log above or Build\BatchFiles\jg_log.txt
  같은 상태에서 옛 마지막 줄 사본(GenerateProjectFiles_old.bat) → 같은 오류 줄인데 exit 0  ← 고치기 전 동작 재현
