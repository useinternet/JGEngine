# 게임 프로젝트 생성 가이드

엔진 밖 폴더에 게임 프로젝트를 만들고, 엔진을 소스로 포함한 솔루션을 생성해 JGEditor 에서 실행하기까지.
배경과 설계 결정은 `Document/게임모듈_사전작업_분석_2026-09-29.md`.

---

## 0. 준비

| 항목 | 내용 |
|---|---|
| 도구 | Visual Studio 2022 (C++ 데스크톱 개발) |
| 경로 | 엔진 · 프로젝트 경로 모두 **ASCII** (예: `D:\Games\MyGame`). 한글 등이 든 프로젝트 경로는 배치가 처음에 거부한다. 공백은 된다 |
| 엔진 코드젠 | 엔진 루트에서 `GenerateProjectFiles.bat` 를 한 번 실행해 엔진 `Temp/CodeGen` 이 있어야 한다. 게임 프로젝트는 엔진 코드젠을 읽기만 한다 |

---

## 1. 프로젝트 만들기

```bat
<Engine>\Build\BatchFiles\CreateGameProject.bat D:\Games\MyGame
```

두 번째 인자로 이름을 따로 줄 수 있다(`CreateGameProject.bat D:\Games\Proto MyGame`). 비우면 폴더 이름.

**이름 규칙** — 이름이 폴더 · 모듈 · DLL · 클래스 이름이 된다.

| 규칙 | 이유 |
|---|---|
| C++ 식별자 (ASCII 영문 · 숫자 · `_`, 숫자로 시작 금지) | `H<Name>Module` 같은 클래스 이름이 된다 |
| `JG` 로 시작 금지 | 엔진 모듈 몫. `JG` 는 에디터 모듈이 `JGEditor` 가 된다 |
| 엔진 모듈 이름 금지 (`GUI`, `Asset`, `Graphics`, `GameFrameWorks` …) | DLL 이 같은 Bin 에서 부딪히고, 모듈 클래스 이름이 엔진 것과 겹친다 |
| `Game` 금지 (대소문자 무시) | 템플릿 엔트리 액터 `JGGameEntryActor` · `GameEntryActor.h` 가 GameFrameWorks 의 것과 같아진다 |
| **프로젝트 안 파일 · 폴더 이름도 ASCII** | 엔진 FileIO 는 UTF-8(한글 등) 경로를 지원하지 않는다 — ER-004 반려, 사용자 결정 D-26(2026-10-02). 프로젝트 경로 자체는 이미 P4 검사로 ASCII 만 받는다 |

만들어지는 것:

```
D:\Games\MyGame\
  MyGame.jgproject             이름 · 엔진 경로 · 모듈 목록
  GenerateProjectFiles.bat     솔루션 생성 (아래 2단계)
  .gitignore                   Bin/ Temp/ .vs/ *.sln MyGame.lua Package/ Saved/
  Bin\  Content\  Temp\
  Source\MyGame\               게임 모듈 (MyGame.dll)
    MyGame.module.json · MyGameDefines.h · MyGameModule.h/.cpp · MyGameEntryActor.h/.cpp
  Source\MyGameEditor\         에디터 모듈 (MyGameEditor.dll)
    MyGameEditor.module.json · MyGameEditorDefines.h · MyGameEditorModule.h/.cpp
```

## 2. 솔루션 만들기

```bat
D:\Games\MyGame\GenerateProjectFiles.bat
```

`MyGame.sln` 이 생긴다. 엔진 프로젝트(Engine 그룹)와 게임 모듈(MyGame 그룹)이 함께 들어 있고, 산출물은 모두 `MyGame\Bin\<구성>\` 에 모인다.

**다시 실행해야 할 때** — 파일 목록은 생성 시점에 정해진다.

| 한 일 | 다시 실행 |
|---|---|
| 게임 소스 파일 추가 · 삭제 · 이름 변경 | `GenerateProjectFiles.bat` |
| 게임 헤더에 `JGCLASS` · `JGPROPERTY` · `JGENUM` 추가 · 변경 | `GenerateProjectFiles.bat` |
| 게임 모듈 `*.module.json` 의 의존(`ModuleDependencies`) 변경 — 예: 소리를 쓰려고 `Audio` 추가(9절) | `GenerateProjectFiles.bat` |
| 엔진에 파일 · 리플렉션 헤더 추가, 엔진 모듈 추가 · 삭제 — 예: 2026-10-11 오디오 모듈 `Audio`(오디오 재생, D-37) | 엔진 `GenerateProjectFiles.bat` → 게임 `GenerateProjectFiles.bat`. 게임 솔루션의 `JGConsole` 은 엔진 소스로 다시 빌드되므로, 다시 돌리기 전까지 게임 Bin 의 `JGConsole` 은 실행마다 `Fail Connect Audio Module` 오류 줄을 남긴다(명령 · 종료 코드는 그대로) |
| 엔진 빌드 템플릿(`JGBuildTool/Template/BuildTemplate.lua`)이 바뀜 — 예: 2026-10-02 병렬 컴파일 `/MP`(DevOps BS-1) | 게임 `GenerateProjectFiles.bat`. 다시 돌리기 전까지 이미 만든 게임 프로젝트(ProjectAH 등)는 옛 설정으로 빌드한다. 엔진 `PCH.h` 변경(BS-2)은 다시 돌리지 않아도 다음 빌드에 들어간다(전체 다시 컴파일) |
| 엔진 · 게임 소스 내용만 수정 | 필요 없음. 그냥 빌드 |

## 3. 빌드 · 실행

1. `MyGame.sln` 을 연다. 시작 프로젝트는 `JGLauncher` 로 지정돼 있다.
2. 구성 **DevelopEngine** 으로 빌드한다(엔진 · 게임 모두 Debug. 게임 코드 디버깅도 이 구성으로 한다).
3. F5. 창 제목이 `JGEditor - MyGame` 이고, `Bin\DevelopEngine\jg_log.txt` 에 다음이 보이면 정상이다.

```
Project MyGame: project D:/Games/MyGame/, engine <Engine>/
Startup MyGame Module...
MyGame entry actor entered world
Startup MyGameEditor Module...
```

에디터 메뉴 `MyGame > Reload World` 는 에디터 모듈이 붙인 예시 메뉴다.

**명령 한 줄로 에디터 띄우기 (RunEditor, 2026-10-17)** — 빌드해 둔 에디터를 띄우고 바로 끝난다(에디터가 끝날 때까지 기다리지 않음). 대시보드 "에디터 실행" 버튼이 부르는 스크립트다.

```bat
<Engine>\Build\BatchFiles\RunEditor.cmd -project=D:\Games\MyGame
```

`-project=` 를 빼면 엔진 단독 에디터(`<Engine>\Bin\DevelopEngine\JGLauncher.exe`)다. 게임 프로젝트는 `<Project>\Bin\DevelopEngine\JGLauncher.exe` 를 그 폴더를 작업 폴더로 해서 따로 띄운다. 띄우기 전에 빌드 중인지 본다 — 엔진 단독은 메인 트리 잠금(`MainTree.cmd`) · 도우미 밖 MSBuild · cl · link · 10초 안에 바뀐 빌드 출력, 게임 프로젝트는 그 프로젝트 폴더의 MSBuild · cl · link · 빌드 출력만 본다. `-wait=<초>`(0 ~ 600, 기본 0)를 주면 빌드가 끝나길 그만큼 기다렸다가 띄운다. 출력은 한국어 한 줄이고, 결과는 종료 코드로 나뉜다.

| 종료 코드 | 뜻 | 출력 예 |
|---|---|---|
| 0 | 에디터를 띄움 | `에디터를 띄움(pid 44108) — Bin\DevelopEngine\JGLauncher.exe` |
| 89 | 같은 Bin 의 에디터가 이미 떠 있음 — 두 번째는 띄우지 않음 | `이미 떠 있음 — Bin\DevelopEngine\JGLauncher.exe pid 44108, 14:39:03 부터. 두 번째는 띄우지 않음` |
| 90 | 빌드 중 — `-wait` 만큼 기다려도 안 끝남(기본은 기다리지 않음) | `빌드 중 — Core: build DevelopEngine JGEngine.sln, 1m20s째. 끝나면 다시 눌러 주세요` |
| 91 | 사용법이 틀림(모르는 인자, `-wait` 범위 밖) | `사용법이 틀림 — 모르는 인자 foo (…)` |
| 92 | 에디터를 아직 빌드하지 않음, 또는 `-project=` 폴더에 `.jgproject` 가 없음 | `에디터 실행 파일이 없음 — …\JGLauncher.exe (먼저 빌드)` |
| 93 | 에디터가 뜨지 못했거나 2초 안에 끝남 | `에디터가 바로 끝남(종료 코드 1) — …\Bin\DevelopEngine\jg_log.txt 를 보세요` |

에디터가 떠 있는 동안 `MainTree.cmd` 빌드는 지금처럼 에디터가 닫히길 기다린다(RunEditor 는 에디터를 띄우는 순간에만 잠금을 잡는다). 기록은 `<Engine>\Temp\MainTree\history.log` 의 `editor` 줄. 누가 불렀는지는 `-name=<누구>`(기본 `RunEditor`).

**창 없이 확인** — 게임 모듈이 헤드리스로 뜨고 내려가는지 본다(`Bin\DevelopEngine` 에서).

```bat
JGConsole.exe module.test MyGame
```

`MyGame entry actor entered world` → `module.test: MyGame connected (error logs 0)` → `disconnected (error logs 0)` → `OK` 이고 종료 코드 0 이면 정상이다. 연결 · 해제하는 동안 `[error]` · `[critical]` 로그가 하나라도 나오면 종료 코드 1. `MyGameEditor` 는 GUI 가 없어 실패하는 것이 정상이다.

**게임 명령 실행** — 게임 모듈이 등록한 콘솔 명령은 맨 앞에 `-game` 을 붙여 부른다(같은 게임 Bin 에서, D-30).

```bat
JGConsole.exe -game <명령> [인자...]
```

`.jgproject` 의 `GameModules` 를 적힌 순서대로 연결하고(`EditorModules` 는 연결하지 않음) 명령을 돌린 뒤, 결과대로 종료 코드 0(성공) · 1(실패)을 돌려준다. `-game` 은 명령 앞에만 쓴다(명령 뒤에 쓰면 그 명령의 인자). `-game` 없이 게임 명령을 부르면 Unknown 오류와 함께 `Commands of game modules need -game: JGConsole.exe -game <명령>` 안내만 나오고 종료 1. 게임 모듈 연결에 실패하거나 엔진 Bin(게임 프로젝트 아님)에서 `-game` 을 쓰면 명령을 돌리지 않고 종료 1. `JGConsole.exe -game help` 는 게임 명령까지 든 목록이다.

**멀티플레이로 실행** — 같은 게임을 두 번 띄운다. 호스트는 `JGLauncher.exe -host` (포트 기본 47771, 바꾸려면 `-host=<포트>`), 참가자는 `JGLauncher.exe -join=<호스트 주소>[:<포트>] -name=<이름>`. 참가자는 호스트의 월드를 따라 로드하고, 게임이 이미 진행 중이면 지금 상태를 받는다. 로그에 `JGGameInstance: hosting on port 47771` · `JGGameInstance: joining ...` · `PGameplayClientSession: joined as slot 1` 이 보이면 연결된 것이다. 호스트는 모든 인터페이스로 열어 Windows 방화벽 확인 창이 뜰 수 있다(한 기계 안에서 시험할 때는 `-bind=127.0.0.1`). 엔트리 액터는 4절의 멀티플레이 규약을 따라야 한다.

## 4. 두 모듈의 역할

| 모듈 | 로드되는 곳 | 둘 것 |
|---|---|---|
| `MyGame` | 게임 실행 · 에디터 환경 | 규칙 · 액터 · 게임 인스턴스. 시작 시 GameFrameWorks 를 연결하고 엔트리 액터를 등록한 뒤 월드를 로드한다 |
| `MyGameEditor` | 에디터 환경(JGEditor)만 | 이 게임 전용 에디터 메뉴 · 위젯. `MyGame` 에 의존 |

JGEditor 가 `.jgproject` 의 `GameModules` → `EditorModules` 순으로 연결하고, 종료는 역순으로 먼저 내린다.

**지킬 것**

| 규칙 | 이유 |
|---|---|
| 의존 모듈은 `*.module.json` 의 `ModuleDependencies` 에 **직접** 적는다 | 의존은 전이되지 않는다. `MyGame` 헤더가 GameFrameWorks 헤더를 include 하면 `MyGameEditor` 에도 `GameFrameWorks` 를 적어야 한다 |
| GameFrameWorks 를 쓰면 그 의존(`Asset` · `Graphics`)도 적는다 — 템플릿에 이미 있다(2026-10-02~) | GFW 헤더 일부(`Actors/CameraActor.h` · `Components/StaticMeshComponent.h` · `Data/DataTable.h` 등)가 Asset · Graphics 헤더를 include 한다. 이 날짜 전에 만든 프로젝트는 자기 `*.module.json` 에 직접 넣는다 |
| `ShutdownModule` 에서 의존 모듈을 Disconnect 하지 않는다 | 모듈 연결에 참조 카운트가 없다. 종료 순서는 JGEditor 와 엔진이 맡는다 |
| 모듈이 `PSharedPtr` 로 든 전역 객체는 `ShutdownModule` 에서 Reset | GC 종료 순서 문제 |
| 모든 .cpp 첫 줄 `#include "PCH/PCH.h"`, 파일은 UTF-8 | 빌드 옵션 `/utf-8` |
| 리플렉션 헤더: 헤더 하나에 `JGCLASS` 하나, 자기 `<파일>.generation.h` 를 직접 include, `JGPROPERTY()` 는 한 줄, 타입에 공백 · `::` 금지, `JGSTRUCT` 미지원 | 헤더 툴이 줄 단위로 읽는다 |
| 리플렉션 헤더 파일 이름을 엔진 것(`Actor.h`, `World.h` …)과 겹치지 않게 | 생성 헤더를 파일 이름으로 찾으므로 엔진 헤더가 게임의 생성 헤더를 집는다 |
| DevelopGame 구성에서도 `ConfirmConfig` (템플릿 기본값) | `DebugConfig` 는 엔진(Release)과 CRT 가 달라 링크되지 않는다(LNK2038) |
| 엔트리 액터(멀티플레이 규약): 규칙 · 컴포넌트 등록은 모든 기계에서, 초기 상태 구성과 시작(`JGGameMasterActor::StartGame`)은 `GetGameInstance().IsAuthority()` 일 때만 | 클라는 호스트가 보낸 초기 상태로 시작한다. `PGameMaster::Start` 를 직접 불러도 싱글은 세션이 이어받지만, 클라에서 부르면 호스트와 어긋난다. 템플릿 `OnEnterWorld` 주석이 예시다 (Server 5-2b) |
| 세션 공유 데이터(방 정보 — `PGameplayHostSession::SetSessionData` · `PGameplaySession::FindSessionData`)는 방 화면 표시용이다. 규칙 코드(규칙 · 흐름 · 에이전트)는 읽지 않는다 | 기계마다 도착 시점이 다르다. 판에 쓰는 값은 방장이 판을 시작할 때 초기 상태에 넣는다(대기방 기능 묶음 D-38, 2026-10-12) |

**모듈을 더 만들 때** — `Source\<Module>\<Module>.module.json` 을 두고(폴더 이름 = 파일 이름 = ModuleName), define 은 `_` + 대문자 모듈명(`_<MODULE>`), `.jgproject` 의 `GameModules` 또는 `EditorModules` 에 이름을 추가한 뒤 `GenerateProjectFiles.bat`.

## 5. 엔진 위치

`MyGame.jgproject` 의 `EngineRoot` 가 엔진을 가리킨다(배치 1 이 만든 엔진 경로를 적는다). 비워 두면 환경변수 `JGENGINE_ROOT` 를 쓴다. 둘 다 있으면 `EngineRoot` 가 이긴다.

- 다른 PC 와 프로젝트를 공유할 때: `EngineRoot` 를 비우고 각자 `JGENGINE_ROOT` 를 설정한다. `GenerateProjectFiles.bat` 안의 엔진 경로도 고친다.
- 엔진 worktree 가 여러 개일 때: 프로젝트는 `EngineRoot` 의 엔진 하나에 묶인다. 다른 엔진의 배치 파일로 생성하면 거부한다. 에이전트마다 프로젝트 사본을 쓴다.
- 프로젝트를 다른 엔진으로 옮길 때(예: worktree 엔진으로 만든 검증 게임을 메인 엔진으로): `EngineRoot` 와 `GenerateProjectFiles.bat` 안의 엔진 경로를 **둘 다** 바꾼다. `EngineRoot` 만 바꾸면 배치가 옛 엔진의 툴을 불러 `Project MyGame belongs to engine <새 엔진>, but this tool is in <옛 엔진>`(Critical)으로 솔루션을 만들지 않는다(6절).

## 6. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| `engine code generation is missing` | 엔진 루트에서 `GenerateProjectFiles.bat` |
| `Project MyGame belongs to engine ..., but this tool is in ...` | 다른 엔진의 배치 파일로 실행했다 — `EngineRoot` 만 바꾸고 `GenerateProjectFiles.bat` 의 엔진 경로는 그대로 둔 경우도 이것이다(5절). 그 엔진 것을 쓰거나 `EngineRoot` 와 배치의 엔진 경로를 맞춘다. 솔루션은 만들어지지 않는다 |
| `Engine root is unknown` (실행 시) | `EngineRoot` 가 비었고 `JGENGINE_ROOT` 도 없다 |
| `Project names starting with JG are reserved` · `... is an engine module name` · `Game is reserved` | 이름 규칙(1단계) |
| 게임 솔루션의 `Game` 프로젝트가 `C1083 ... Source\Runtime\Game\Main.cpp` 로 실패 | 엔진 `Game` 모듈 삭제(GameModule R4) 전에 만든 솔루션이다. 게임 `GenerateProjectFiles.bat` 를 다시 실행한다 |
| LNK1104 `zlibstatic.lib` / 실행 시 Graphics 로드 실패 | `Bin\<구성>\` 의 3rd party 파일이 없다. `GenerateProjectFiles.bat` 를 다시 실행하면 복사한다 |
| unresolved external `Module_..._Code_Generation_...` | 리플렉션 헤더를 추가하고 솔루션을 다시 만들지 않았다 |
| 헤더 툴 · 빌드 툴 오류 | 콘솔 출력과 `<Engine>\Build\BatchFiles\jg_log.txt`. 툴은 실패하면 종료 코드 1 로 끝난다 |
| 게임 `GenerateProjectFiles.bat` 가 오류(`[GenerateGameProjectFiles] failed`)를 내고도 종료 코드 0 | 2026-10-11 전 템플릿으로 만든 배치다 — 마지막 줄 `if errorlevel 1 pause` 의 `pause` 가 0 으로 끝낸다(창으로 보면 오류가 보이지만 스크립트 · 에이전트는 성공으로 안다). 마지막 줄을 지금 템플릿처럼 `if errorlevel 1 (` · `pause` · `exit /b 1` · `)` 네 줄로 바꾸면 실패 때 1 로 끝난다(DevOps GM-B5) |
| `Project path must be ASCII ...` | 프로젝트 경로(폴더 이름)에 한글 등 ASCII 가 아닌 문자가 있다. 영문 경로에 만들거나 옮긴다(공백은 된다) |
| `'PreBuild.bat' is not recognized` (엔진 `GenerateProjectFiles.bat`) | 2026-09-30 이전 배치 파일이다. 지금 배치는 `NoDefaultCurrentDirectoryInExePath` 가 켜진 셸에서도, 어느 폴더에서 실행해도 돈다 |
| `/JGGame/...` 에셋이 `Game content is only available in a game project` | 엔진 단독으로 실행했다. 게임 `Bin\<구성>\JGLauncher.exe` 로 실행한다 |

## 7. 게임 에셋 (Content)

게임 에셋(`.jgasset`)은 `MyGame\Content\` 아래에 둔다. 경로는 `/JGGame/<Content 기준 상대경로>` 이고 엔진 에셋은 그대로 `/JGEngine/...` 이다.

| 경로 | 가리키는 파일 |
|---|---|
| `/JGEngine/TempAsset/Sample` | `<Engine>\Content\TempAsset\Sample.jgasset` |
| `/JGGame/Cards/Deck` | `MyGame\Content\Cards\Deck.jgasset` |

- 시작할 때 엔진 Content → 게임 Content 순으로 모든 `.jgasset` 을 올린다. 확장자를 빼면 `.jgasset` 이 붙는다.
- 엔진 단독 실행(엔진 `Bin`)에는 게임 Content 가 없다.
- **엔진 에셋 파일을 복사해 쓸 때는 `_guid` 를 바꾼다.** 같은 GUID 가 두 번 올라오면 나중 것은 `Duplicate asset guid ... with <먼저 올라온 경로>. Skipped` 오류와 함께 로드되지 않는다(먼저 것은 그대로 쓴다).

## 8. 게임만 실행 · 패키징 (DevOps GP, 2026-10-03)

### 개발 중 게임만 실행

```bat
MyGame\Bin\DevelopEngine\JGLauncher.exe -game
```

- 에디터(ImGui) 없이 창 전체가 게임 화면이다(월드 + 게임 UI). 호스트는 엔진 `GameHost` 모듈이고, 게임 모듈의 `StartupModule` 이 올린 월드를 그린다.
- 창 설정은 `.jgproject` 의 `"Package"."Window"`(기본 1920×1080 창 모드 · VSync). 명령줄 `-windowed` · `-fullscreen`(테두리 없는 전체 화면) · `-res=1600x900` · `-novsync` 가 앞선다. 모니터보다 크면 비율을 지켜 줄인다.
- 에디터 모듈(`MyGameEditor`)은 연결도 로드도 하지 않는다(런타임 모듈 목록 `Temp\CodeGen\runtime_module_info.json` — 배치 2 가 만든다).
- 그릴 카메라가 없으면 검은 화면이고 로그에 `GameHost: nothing to draw yet (... no active camera)` 가 한 번 나온다.

### 패키지 만들기(쿠킹)

```bat
<Engine>\Bin\DevelopEngine\JGConsole.exe -runCook -project=D:\Games\MyGame
```

- 결과 `MyGame\Package\ReleaseGame\` = `MyGame.exe` · `Bin\` · `Content\`(`Content\JGEngine` = 엔진, `Content\JGGame` = 게임). 다른 PC 로 폴더째 옮겨 `MyGame.exe` 를 실행하면 게임만 뜬다. 저장 · 로그는 실행하면 생기는 `Saved\`(로그 `Saved\Logs\MyGame.log`). 같은 패키지에서 여럿 띄우면 두 번째부터 `MyGame_2.log` · `MyGame_3.log` … 에 따로 쓰고(혼자 띄우면 `MyGame.log` 그대로), 로그 첫머리에 `Log file <경로> (process <번호>)` 줄이 있다(ER-024, 2026-10-11). 로그 파일을 고르려면 `-logfile=<경로>`(상대 경로는 `Saved\Logs` 기준, 예: `-logfile=Host.log`).
- 옵션: `-config=ConfirmGame`(확인용, 기본 `ReleaseGame`) · `-output=<폴더>` · `-skipbuild`(이미 빌드한 `Bin\<구성>` 사용) · `-nosmoke`(GPU 없는 환경) · `-smokeframes=300`. 같은 명령의 콘솔 이름은 `cook.run`.
- 단계: 검사 → 솔루션 생성(배치 2) → `ReleaseGame` 빌드(VS 2022 MSBuild) → 런타임 모듈 → Bin 배치(+ DLL 검사 · VC++ 런타임 앱 로컬) → exe → Content(고르기 · 검사 · 복사) → `Bin\JGPackage.json` → 스모크 실행(창이 몇 초 뜬다) → 교체. 처음 약 1분 30초.
- PDB 는 `Package\ReleaseGame-Symbols\`(배포하지 않음), 로그 · 보고서는 `Temp\Cook\ReleaseGame\`(`report.txt` · `build.log` · `smoke.log`).
- **패키지에는 Content 만 들어간다**(사용자 결정 D-23 ③). 게임이 실행 중 읽는 데이터는 `MyGame\Content\` 아래에 두고 `HFileHelper::GameContentDirectory()` 기준으로 읽는다. 저장은 `HFileHelper::SavedDirectory()`. 패키지에서 Content · Saved · Bin 밖을 읽으면 로그에 `Package reads outside Content/Saved/Bin` 경고가 나온다.
- 게임 UI 기본 글꼴은 게임 `Content\Fonts\GameUIDefault.ttf` → 엔진 Content 같은 자리 → OS 글꼴(맑은 고딕 → Arial) 순서로 찾는다. 게임이 게임 UI 매니저의 `SetDefaultFont` 로 정할 수도 있다. 게임 UI 글꼴 · 이미지 읽기도 패키지 읽기 가드를 거치므로(GUI ER-016, 10-03), OS 글꼴로 넘어가면 스모크 보고에 `reads outside Content 1`, 쿠킹 경고 `the game reads 1 folder(s) outside Content/Saved/Bin`, 글꼴 경고가 나온다. 쿠킹은 실패하지 않는다. 내부 빌드면 그대로 두어도 되고, 배포할 패키지는 배포해도 되는 글꼴 파일을 게임 `Content\Fonts\GameUIDefault.ttf` 로 넣는다.
- 패키지에 넣지 않을 Content: `.jgproject` `"Package": { "ExcludeContent": [ "Dev/", "*.psd" ] }`(폴더는 `/` 로 끝, `*.확장자`). 엔진 Content 의 `RawResources/` · `TempAsset/` 는 늘 빠진다 — 게임이 쓰는 에셋은 게임 Content 에 복사해 둔다(`_guid` 를 바꿔서).
- 패키지는 `ConfirmGame` · `ReleaseGame` 구성(`JG_WITH_EDITOR` 0)으로만 만든다. 이 구성의 exe 를 `Bin\<구성>` 에서 바로 실행하면 "game package build" 오류 후 끝난다(정상).

| 증상 | 원인 · 조치 |
|---|---|
| `cook: ... is not a previous package - choose another -output=` | 출력 폴더에 다른 파일이 있다. 쿠킹은 이전 패키지(`Bin\JGPackage.json` 이 있는 폴더)나 빈 폴더만 지운다 |
| `runtime module depends on an editor module: A -> B` | 게임 모듈이 에디터 모듈(엔진 `Source\Editor` · `MyGameEditor`)에 의존한다. 의존을 에디터 모듈로 옮긴다 |
| `launch module GameHost is not a runtime module` | 배치 2 를 다시 돌린다(옛 `runtime_module_info.json`) |
| `content: <경로> : ...` | 에셋 검사 실패(깨진 참조 · GUID 중복 · 데이터 테이블). 경로를 고친다 |
| `smoke run failed` | `Temp\Cook\<구성>\smoke.log` 의 `[error]` 줄. 패키지에서 Content 밖 데이터를 읽는지 먼저 본다 |
| `the game reads N folder(s) outside Content/Saved/Bin` (경고) | `smoke.log` 의 `Package reads outside Content/Saved/Bin: <경로>` 줄이 그 경로다. 실행 데이터면 Content 로 옮긴다. 경로가 OS 글꼴(`C:\Windows\Fonts\...`)이면 게임 UI 기본 글꼴이 Content 에 없는 것 — 위 글꼴 줄 |

### 멀티플레이 확인 (패키지)

- 한 PC 에서 확인: 호스트 `MyGame.exe -host -bind=127.0.0.1`, 참가자 `MyGame.exe -join=127.0.0.1`. 같은 패키지 폴더에서 바로 두 번 띄워도 된다 — 두 번째 실행의 로그는 `Saved\Logs\MyGame_2.log` 다(ER-024, 2026-10-11. 그 전 패키지는 로그가 섞여 폴더를 복사해 띄웠다). 어느 쪽 로그인지 이름으로 나누려면 `-logfile=Host.log` · `-logfile=Guest.log`.
- 다른 PC 와 할 때: 호스트는 `-bind` 없이 `MyGame.exe -host[=포트]`(기본 47771, TCP). 처음 열 때 Windows 방화벽 확인 창이 뜨면 "허용"을 눌러야 다른 PC 가 들어올 수 있다. 참가자는 `MyGame.exe -join=<호스트 IP>[:포트]`.
- 참가자는 호스트가 포트를 연 뒤에 띄운다(접속은 한 번만 시도한다). 공유기 밖(인터넷)에서는 호스트 쪽 공유기에서 포트를 열어야 한다. 엔진은 중계 서버를 두지 않는다.
- 엔진 네트워크 프로토콜 버전(2026-10-12 부터 2)이 다른 빌드끼리는 입장할 때 `protocol a != b` 로 거절된다. 같은 엔진으로 빌드 · 쿠킹한 패키지끼리 시험한다(대기방 기능 묶음 D-38).
- 확인 기록: Server GP-S1(10-03) — 검증 게임 NetDuel 패키지 두 개(루프백)로 두 쪽 seq · 체크섬 같음, 종료 0, 방화벽 창 없음(`Memory/Server/Files/2026-10-03_GP-S1_package_results.txt`).

## 9. 소리 쓰기 (오디오 재생 D-37, 2026-10-11)

엔진 모듈 `Audio`(miniaudio)로 효과음 · 배경음을 낸다. 소리를 안 쓰는 게임은 아무것도 하지 않아도 된다(지금과 같다).

1. 게임 모듈 `Source\MyGame\MyGame.module.json` 의 `ModuleDependencies` 에 `"Audio"` 를 더하고 `GenerateProjectFiles.bat` 를 다시 실행한다(2절 표). 게임 빌드와 패키지 `Bin\`(8절)에 `Audio.dll` 이 들어간다.
2. 게임 모듈 `StartupModule` 에서 GameFrameWorks 다음에 연결한다(템플릿의 GameFrameWorks 연결과 같은 모양).

```cpp
if (GModuleGlobalSystem::GetInstance().ConnectModule("Audio") == false)
{
	JG_LOG(MyGame, ELogLevel::Critical, "Fail Connect Audio Module...");
}
```

3. 소리 파일은 게임 `Content\` 안(예: `Content\Sounds\`)에 둔다. 코드에서는 Content 토큰 경로 + 확장자로 부른다: `/JGGame/Sounds/UI/Click.wav`. 효과음은 wav(16비트 PCM), 음악 · 분위기 소리는 ogg 를 권한다(mp3 · flac 도 풀린다). 쿠킹이 그대로 담는다(Content 만 패키징 — 8절).
4. `#include "Audio.h"` 뒤 **메인 스레드에서만** 부른다: `HAudio::Play(경로)` · `HAudio::PlayMusic(경로, 페이드 초)` · `HAudio::SetBusVolume(EAudioBus::Effects, 0.8f)` · `HAudio::SetBackgroundMode(EAudioBackgroundMode::Lower, 0.3f)`. 자세한 것은 엔진 `Source\Runtime\Audio\Audio.h` 머리 주석.
5. `-nosound` 로 띄우면 무음 장치로 돈다(동작은 그대로, 소리만 안 남). 소리 장치가 없는 PC 도 Warning 한 줄 뒤 무음으로 돈다. 창이 없는 `JGConsole` 은 늘 무음 장치다(`JGConsole.exe audio.selftest`).
6. 엔진에 Audio 가 들어오기(2026-10-11) 전에 만든 게임 프로젝트는 엔진 `GenerateProjectFiles.bat` → 게임 `GenerateProjectFiles.bat` 를 한 번 다시 실행한다(2절 표).

확인 기록: Core 세션 검증 게임 `Temp\Games\AudioCheck`(메인 엔진, 10-11) — 쿠킹 97.1초 OK, 런타임 모듈에 `Audio`, 패키지 `Bin\Audio.dll`, Content 9(셰이더 5 + 소리 4), 스모크 오류 0 · Content 밖 읽기 0(`Temp\Cook\ReleaseGame\report.txt`).
