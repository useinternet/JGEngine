## 2. 기준선(현재 설정) 분석 — 전체 빌드 272.6초

컴파일 249번(PCH 14 포함), CPU 합 344초 = 프런트엔드 323초 + 백엔드 21초. 컴파일이 이어진 시간 271초 동안 **동시에 1개만 컴파일한 시간이 215초**, 2개 33초, 3~4개 17초.

| 모듈 | 파일 | CPU 합(초) | 걸린 시간(초) | 가장 느린 파일 |
|---|---|---|---|---|
| GameFrameWorks | 75 | 123.9 | 131.2 | `Network/GameplayNetSelfTest.cpp` 2.86초 |
| GameFrameWorks (생성 코드) | 20 | 30.0 | 31.8 | `GameplayControllerActor.generation.cpp` 1.93초 |
| Graphics | 32 | 48.6 | 55.7 | `Importers/FBXAssetImporter.cpp` 1.85초 |
| PCH.cpp (프로젝트마다) | 14 | 27.0 | — | 1.93초 |
| Core | 37 | 22.7 | 22.7 | `CoreSystem.cpp` 1.94초 |
| GUI | 19 | 16.4 | 17.7 | `GUIModule.cpp` 1.86초 |
| 나머지 8개 모듈 + 생성 코드 | 52 | 75.7 | — | 모두 1.2~1.8초 |

- "걸린 시간 ≈ CPU 합" → 프로젝트 안에서 직렬. 프로젝트 사이 병렬(MSBuild `-m`)은 의존 관계 때문에 거의 없다: Core → Asset → Graphics → GameFrameWorks → JGEditor · JGConsole 가 한 줄이고, GameFrameWorks 가 그 줄의 대부분이다.
- 파일 하나가 1.3~2.9초인데 코드는 작다. `AI/Main.cpp`(`PCH.h` + `Core.h` + 빈 함수)가 프런트엔드 1.3초 → **`Core.h` 묶음을 읽는 데만 파일당 약 1.3초**. `Core.h` 는 `Misc/Log.h`(spdlog) · `FileIO/Json.h`(rapidjson) · 엔진 Core 헤더 30여 개를 끌어오고, 엔진 헤더 59개가 `Core.h` 를 include 한다. ## 7. 재현

`tools/build_timing/`: `run_build.sh`(MSBuild 실행 · 벽시계 · 로그), `analyze.py`(모듈별 CPU · 걸린 시간 · 동시 수 · 느린 파일 · 링크), `incremental_real.sh`(증분 4종). 예:

```

python analyze.py <스크래치패드>/bs/r1.log
```
