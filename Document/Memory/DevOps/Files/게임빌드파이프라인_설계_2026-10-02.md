# 게임 빌드 파이프라인(쿠킹 · 패키징) 설계 — 2026-10-02

작성: DevOps 세션. 상태: **결정됨(사용자 2026-10-02 밤) — 착수.** D-23 ① (a) 한 프로세스 · ② (a) 패키지 폴더 안 `Saved/` · ③ **(b) Content 만 패키징** — 엔진 · 게임이 Content 밖 데이터를 쓰면 Content 안으로 옮기라고 요청 · ④ (a) M1 + M2 를 7절 배정대로. 추가 지시: **기본 게임 화면 1920×1080**. 아래 본문은 결정을 반영해 고쳤다(처음 안과 달라진 곳은 9절 표). 다른 세션 배정은 7절대로 — 총괄이 떠 있지 않으면 진행현황 D-23 행이 작업 지시서다.
사용자 보고서: `Document/DevOps_게임빌드파이프라인_설계_2026-10-02.html`. TODO: `DevOps/TODO.md` "GP" 절.

요청(사용자, 10-02): "게임 빌드 파이프라인을 만들고 싶어. 언리얼 엔진의 쿠킹 및 패키징처럼 `JGConsole.exe -runCook -project=<프로젝트 경로>` 로 명령하면 쿠킹 · 패키징을 해서 `Bin/` · `Content/` · `<게임프로젝트이름>.exe` 로 결과가 나오고, exe 를 실행하면 게임만 실행. 지금은 ImGui 창 안에 띄우는데, 그게 아니라 화면 전체가 게임 화면. 큰 작업이니 설계를 꼼꼼히 해서 보고하고, 다른 세션이 나눠 할 수 있게 업무 배정도 계획해 달라."

이 설계는 보류였던 D-5(게임 단독 실행 호스트, 사용자 09-30 "필요 시 진행") · DevOps GM-H1 · R5 · B10 을 다시 연다.

## 0. 결론

1. **명령 하나로 끝까지 간다.** `JGConsole.exe -runCook -project=<경로>` 는 10단계를 돈다: 검사 → 프로젝트 파일 생성 → ReleaseGame 빌드 → 런타임 모듈 고르기 → Bin 배치 → exe → Content 쿠킹 → 서술자 → 스모크 실행 → 보고. 결과물은 `<Project>/Package/ReleaseGame/` 아래 `Bin/` · `Content/` · `<Name>.exe` 이다.
2. **"게임만" 띄우는 새 런타임 모듈 `GameHost` 를 만든다.** JGEditor 자리에 들어가서 창 · Graphics · Asset · GameFrameWorks · 게임 모듈만 올린다. 게임 화면(월드 + 게임 UI)은 ImGui 를 거치지 않고 스왑체인에 바로 낸다. 에디터 쪽(JGEditor · GUI · Devkit · DevConsole · DevStatistics · `<Name>Editor`)은 패키지에 들어가지 않는다.
3. **공용 부품 넷을 먼저 만든다.**
   - 엔진 입력 계층(Core)
   - 게임 뷰포트(GameFrameWorks — 에디터 씬 뷰포트와 같이 씀)
   - Graphics 크기 변경과 출력 경로
   - 패키지 모드(Core 경로)

   앞의 셋이 있으면 개발 중에도 `JGLauncher.exe -game` 으로 게임만 띄울 수 있다(M1).
4. **Release 빌드 자체는 이미 된다(10-02 프로브).** 3rd-party 라이브러리만 `Bin/ReleaseGame` 에 있으면 엔진 14 프로젝트가 오류 0 · 경고 0 으로 37.4초에 빌드된다. Release 자체 테스트와 런처 30초 실행도 정상이다. 막는 것은 하나뿐이다: BuildTool 이 엔진 솔루션에는 3rd-party 를 복사하지 않는다(GP-D0).
5. **일은 18개(GP-*, 선택 1개 별도), 세션 9곳(총괄 포함)에 나눈다.** 크리티컬 패스는 DevOps 다(패키지 모드 → exe → GameHost → 쿠킹 명령). 사용자 결정 4개(9절 D-23 ①~④)는 10-02 밤에 났다. 결정 ③ 때문에 두 요청이 생겼다: 엔진 셰이더를 Content 로(GP-G4, Graphics), ProjectAH 데이터를 Content 로(GP-P0, 게임 구현).

## 1. 요구사항 해석 · 범위

| # | 요구 | 설계에서의 뜻 |
|---|---|---|
| R1 | `JGConsole.exe -runCook -project=<경로>` | JGConsole 의 쿠킹 명령이다. `-runCook` 은 언리얼식 별칭이고, 콘솔 명령 이름은 규칙(area.action)대로 `cook.run` 이다. **어느 작업 폴더에서 실행해도 같은 결과**가 나와야 한다(지금 루트 해석은 작업 폴더 기준이라 GP-D1 에서 고침) |
| R2 | 쿠킹 및 패키징 | 1차 쿠킹은 세 가지다: **고르기**(포함 · 제외 규칙), **검사**(파싱 · GUID · 참조), **배치**(패키지 마운트 구조로 복사). 형식 변환(이진 에셋 · 셰이더 바이트코드 · 묶음 파일 · 압축)은 2차(보류 후보 GP-H1 · H3) |
| R3 | 결과 `Bin/` · `Content/` · `<Name>.exe` | 패키지 루트에는 **정확히 이 셋**만 둔다(D-23 ③ (b) — Content 만 패키징). 실행하면 `Saved/` 가 생긴다(D-23 ②). 엔진 · 프로젝트 소스, 툴, 에디터 바이너리는 넣지 않는다. 엔진 · 게임이 실행 중 Content 밖 데이터를 읽으면 그 데이터를 Content 안으로 옮긴다(GP-G4 · GP-P0) |
| R4 | exe 실행 → 게임만 | 에디터 모듈은 로드도 연결도 하지 않는다. 엔진 · 프로젝트 폴더가 없어도 되고, 패키지 폴더를 다른 경로로 옮겨도 실행된다 |
| R5 | 화면 = 게임 화면 | ImGui 는 쓰지 않는다. 월드(활성 카메라)와 게임 UI(`JGGameWidget`)가 창 전체를 채운다. 창 크기 변경, 테두리 없는 전체 화면, 입력(포인터 · 키 · 글자 · IME)을 지원한다 |
| R6 | 다른 세션이 나눠 하기 | 작업을 분야별로 쪼갠다. 세션 사이의 인터페이스(헤더 초안)는 먼저 정한다(4절 · 7절) |

**범위 밖(1차):** 설치 프로그램, 코드 서명, 게임패드, 전용 서버 패키지(창 없음), Windows x64 외 플랫폼, 에셋 변환 · 압축, 패치 · 증분 배포, 독점 전체 화면.

## 2. 지금 구조 (조사 결과, 근거는 11절)

| 영역 | 지금 | 패키지에 미치는 영향 |
|---|---|---|
| 실행 | `JGLauncher.exe`(ConsoleApp) → LaunchModule `JGEditor` 순서로 간다. JGEditor 가 창(1936×1119)을 만들고, 엔진 모듈 7개(Graphics · GUI · Asset · DevStatistics · DevConsole · Devkit · GameFrameWorks)를 연결한 뒤, 프로젝트 Game · Editor 모듈을 연결하고 씬 뷰포트를 연다 | 게임용 호스트가 없다(D-5 보류였음) |

| 출력 | `PDX12FrameBuffer::Update` 는 이 순서로 돈다: 지우기 → `SubmitTexture` 된 텍스처 복사 → `OnUpdate`(GUI 그리기) → `Present(0, 0)` | 텍스처를 화면에 내는 길은 이미 있다. VSync 는 없다 |

## 3. 목표 산출물

```
<Project>/Package/ReleaseGame/            기본 출력(-output= 로 바꿈). 쿠킹마다 새로 만든다
├─ <Name>.exe                             부트스트랩(정적 CRT, 수백 KB). Bin 을 DLL 경로로 잡고 엔진을 올린다
├─ Bin/
│  ├─ JGGameLaunch.dll                    엔진 진입: Core 생성 · 프레임 루프 · 종료 코드
│  ├─ GameHost.dll                        게임 호스트 모듈: 창 · 출력 · 입력
│  ├─ Asset.dll  Graphics.dll  GameFrameWorks.dll     (AI.dll 은 게임이 의존할 때만)
│  ├─ <Name>.dll                          게임 모듈(.jgproject GameModules)
│  ├─ assimp-vc143-mt.dll                 Graphics 가 import 한다(GP-H2 로 뺄 수 있음)
│  ├─ vcruntime140.dll  vcruntime140_1.dll  msvcp140.dll   앱 로컬 CRT(import 감사가 필요한 것만 고름)
│  └─ JGPackage.json                      패키지 서술자: 이름 · 버전 · 구성 · 모듈 목록 · 창 설정
├─ Content/
│  ├─ JGEngine/                           = /JGEngine/  (Shaders/ + 엔진 에셋 — 원본 <Engine>/Content, GP-G4 뒤 셰이더 포함)
│  └─ JGGame/                             = /JGGame/    (게임 에셋)
└─ (Saved/)                               실행하면 생긴다: Logs/<Name>.log, 게임 저장 — D-23 ②
<Project>/Package/ReleaseGame-Symbols/     PDB(배포하지 않음, 크래시 분석용)
<Project>/Temp/Cook/ReleaseGame/           cook.log · build.log · smoke.log · report.txt
```

**넣지 않는 것:**
- 개발 · 에디터 모듈: JGEditor · GUI · Devkit · DevConsole · DevStatistics · `<Name>Editor`
- 툴 exe: JGLauncher · JGConsole · JGBuildTool · JGHeaderTool
- 빌드 부산물: `*_Dynamic.dll`(개발용 핫 리로드 사본) · `.lib` · `.exp` · `.idb`
- 엔진 Content 의 `RawResources` · `TempAsset`
- 소스

마운트 폴더 이름(`JGEngine` · `JGGame`)은 에셋 경로 토큰과 같게 둔다. 그래야 토큰을 그대로 마운트 이름으로 쓸 수 있다.

## 4. 설계

### 4-1 전체 흐름

```
JGConsole -runCook -project=P [-config=C] [-output=O]
  1 검사      .jgproject 를 읽는다 · EngineRoot = 이 엔진인지 · 경로가 ASCII 인지(P4 규칙) · 출력 폴더 가드(4-8)
  2 생성      <Engine>/Build/BatchFiles/GenerateGameProjectFiles.bat P   (JGHeaderTool + JGBuildTool -project=)
  3 빌드      vswhere 로 MSBuild 를 찾는다 → P/<Name>.sln -p:Configuration=C -p:Platform=x64 -m
  4 모듈 닫힘 GameHost + GameModules 에서 시작해 module.json 의존을 따라 SharedLib 를 모은다(4-9). 에디터 모듈이 섞이면 실패
  5 Bin 배치  P/Bin/C 에서 닫힘 목록 + JGGameLaunch.dll 을 복사 → import 감사로 CRT · 3rd-party 채움(4-12) → PDB 는 Symbols 로
  6 exe       JGGameBootstrap.exe → <Name>.exe
  7 쿠킹      엔진 Content → Content/JGEngine, 게임 Content → Content/JGGame — Content 만(D-23 ③), 검사(4-10)
  8 서술자    Bin/JGPackage.json
  9 스모크    <Name>.exe -smoke=300 → 종료 0 · 로그 error/critical 0 확인 → Saved/ 지움
 10 보고      Temp/Cook/C/report.txt(단계별 시간 · 파일 수 · 크기) + 콘솔 요약, 종료 코드 0 / 1
```

- 스테이징은 `<Output>.staging/` 에서 하고, 마지막에 `<Output>` 과 바꾼다. 중간에 실패하면 이전 패키지가 그대로 남는다.
- 1차는 매번 전부 새로 만든다(증분 없음). 큰 프로젝트도 복사는 수 초 ~ 수십 초다.

### 4-2 실행 구조 — 부트스트랩 · 진입 DLL · 호스트 모듈 (D-23 ①)

| 층 | 이름 · 위치 | 하는 일 | 왜 따로 두나 |
|---|---|---|---|

### 4-3 패키지 빌드 (Core) — `JG_WITH_EDITOR` 로 컴파일 때 구분 (구현됨 GP-D1, 10-02 밤)

**구분 방법(사용자 결정 10-02 밤 — "디파인 하나로, IsPackageMode 함수는 제거"):** `CoreDefines.h` 의 `JG_WITH_EDITOR`(언리얼 `WITH_EDITOR`).
기존 구성 디파인에서 만든다 — BuildTool 변경 없음.

| 구성 | `JG_WITH_EDITOR` | 경로 · 실행 |
|---|---|---|
| DevelopEngine · DevelopGame | 1 (구성 디파인이 없을 때도 1) | 에디터 빌드. 엔진 · 프로젝트 폴더 경로. 에디터 · 툴 · `JGLauncher -game`. 이 구성의 `JGGameLaunch` 는 패키지 실행을 거절(종료 코드 4) |
| ConfirmGame · ReleaseGame | 0 | **패키지 전용 빌드.** 루트 = 패키지 루트(아래 표 오른쪽 열). 패키지 없이 실행하면 Critical 후 바로 종료(Create = false, 종료 코드 2) |

실행 중 플래그 · `IsPackageMode()` 는 두지 않는다(처음 구현에 있었다가 사용자 지시로 제거). 패키지 디버깅은 ConfirmGame + PDB(GP-D0). Debug 게임 구성이 필요해지면 구성을 하나 더한다.

**인자 · 전역 값:** `HCoreSystemArguments` 에 `PackageDirectory`(패키지 빌드만) · `LogFilePath`. `HCoreSystemGlobalValues` 에 `PackageLaunchModule` · `PackageRuntimeModules`(STL — GCoreSystem 이 메모리 시스템보다 오래 산다). 패키지 빌드에서 `bProjectMode` 는 서술자를 읽었을 때만 true.

**`resolveRootDirectories`:**
- 패키지 빌드: `PackageDirectory` 의 `Bin/JGPackage.json` 을 `HPackageDescriptor`(`HProjectDescriptor` 와 같은 `IJsonable` 방식)로 읽는다. 엔진 루트 = 프로젝트 루트 = 패키지 루트.
- 에디터 빌드: 지금과 같다. 단, **기본 루트를 작업 폴더가 아니라 exe 위치 기준 `../../`** 로 바꿨다. 작업 폴더 기준과 같은 곳이면 상대경로 `"../../"` 를 그대로 써서 툴 생성물이 바이트 같다(검증됨).

### 4-4 GameHost 모듈

**시작(StartupModule):**

1. **창을 만든다.** 제목 · 크기 · 모드는 이 순서로 정한다.
   - 명령줄: `-windowed` · `-fullscreen` · `-res=WxH`
   - 설정 파일: 패키지면 `JGPackage.json`, 개발이면 `.jgproject` `Package.Window`
   - 기본값: **창 1920×1080**(사용자 지시 10-02). 모니터 작업 영역보다 크면 16:9 를 지키며 작업 영역에 맞춰 줄이고 로그를 남긴다(1080p 모니터에서는 제목 줄 · 작업 표시줄 때문에 1920×1080 창이 다 들어가지 않는다)

   만든 창은 `GlobalValues.MainWindow` 에 등록한다(JGEditor 와 같음).
2. **엔진 모듈을 연결한다:** Graphics → Asset → GameFrameWorks. JGEditor 의 순서에서 GUI · DevStatistics · DevConsole · Devkit 를 뺀 것이다.
3. **게임 모듈을 연결한다.** 목록은 패키지 `GameModules`, 개발이면 `.jgproject` `GameModules` 다. `EditorModules` 는 연결하지 않는다. 게임 모듈의 StartupModule 이 지금처럼 엔트리 액터를 정하고 월드를 올린다(템플릿 `{PROJECT_NAME}Module.cpp`).
4. **게임 뷰포트를 만든다.** `PGameViewport` 를 창 클라이언트 크기로 만들고 창 이벤트를 연결한다.
   - `OnResize` → 뷰포트 크기 변경(크기 변경이 멈춘 뒤 한 번)
   - `OnInput` → `viewport->HandleInput`
   - 글자 입력 포커스가 있으면 IME 조합 창 위치를 맞춘다
5. **렌더 작업을 프레임 `End` 단계에 등록한다.**

**프레임 순서** (`EMainThreadExecutionOrder`):

| 단계 | 하는 일 |
|---|---|
| GraphicsBegin | Graphics BeginFrame |
| Update | GFW 월드 · 게임 UI 갱신 (지금 그대로) |
| End | GameHost: `viewport->Render()`(월드 → 디스플레이 텍스처 → 게임 UI) → `frameBuffer->SubmitTexture(display)` |
| GraphicsEnd | Graphics EndFrame: 지우기 → 텍스처 복사 → (GUI 없음) → Present |
| UpdateWindow | 메시지 펌프 → 입력 이벤트 → 뷰포트. 다음 프레임 Update 에 반영된다 |

- 최소화돼 크기가 0 이면 렌더와 제출을 건너뛴다.
- 종료 경로는 두 가지다. 창을 닫으면 `WM_DESTROY` 로 지금처럼 루프가 끝난다. 코드에서는 `GCoreSystem::RequestExit` 로 끝낸다.
- 해제(ShutdownModule)는 게임 모듈 역순 해제 → 뷰포트 → 창 순서다(JGEditor 와 같은 규칙).

### 4-5 게임 뷰포트 코어 (GameFrameWorks `Viewport/GameViewport.h`)

에디터 씬 뷰포트와 GameHost 가 같이 쓰는 런타임 부품이다. ImGui 와 창을 모른다. 입력은 엔진 이벤트(4-6)로 받고, 출력은 텍스처로 낸다.

### 4-6 엔진 입력 계층 (Core)

```cpp
// Source/Runtime/Core/Input/InputEvent.h
enum class EInputEventType : uint8 { PointerMove, PointerDown, PointerUp, PointerWheel, PointerLeave, KeyDown, KeyUp, Char, FocusGained, FocusLost };
enum class EPointerButton  : uint8 { Left, Right, Middle, X1, X2 };
enum class EInputModifier  : uint8 { None = 0, Shift = 1 << 0, Ctrl = 1 << 1, Alt = 1 << 2 };

struct HInputEvent
{
	EInputEventType Type;
	HVector2        Position;     // 창 클라이언트 픽셀 (포인터)
	EPointerButton  Button;
	float           WheelDelta;   // 한 칸 = 1.0
	EKeyCode        Key;          // Core/Input/Key.h (있음)
	bool            bRepeat;
	EInputModifier  Modifiers;
	uint32          Codepoint;    // Char: UTF-32 (UTF-16 서로게이트 쌍을 합침)
};

// HWindowCallBacks:  JG_DECLARE_MULTICAST_DELEGATE(HOnInput, const HInputEvent&);  HOnInput OnInput;
// HPlatform:         GetClipboardText / SetClipboardText (UTF-8), SetImeCompositionRect(창, 사각형)
// HJWindowArguments: EWindowMode Mode (Windowed / BorderlessFullscreen), bool bResizable
```

- **Win32 매핑:**
  - 포인터: `WM_MOUSEMOVE` · `WM_[L/R/M/X]BUTTONDOWN/UP/DBLCLK` · `WM_MOUSEWHEEL/HWHEEL` · `WM_MOUSELEAVE`(TrackMouseEvent)
  - 키: `WM_KEYDOWN/UP` · `WM_SYSKEYDOWN/UP`
  - 글자 · 포커스: `WM_CHAR` · `WM_SETFOCUS/KILLFOCUS`
  - 버튼을 누르고 있는 동안 `SetCapture` 한다.
- **IME 1차 범위는 GG-9(D-14)와 같다.** 확정 글자는 `WM_CHAR` 로 받고, 엔진은 조합 창 위치만 맞춘다(`ImmSetCompositionWindow`). 조합 중인 글자를 게임 UI 가 직접 그리는 것은 나중이다.
- **에디터(ImGui)는 영향이 없다.** 원시 `WndProc` 브로드캐스트는 그대로 둔다. `OnInput` 은 에디터에서도 나오지만, 구독자가 없으면 하는 일이 없다.
- **창 모드:** 테두리 없는 전체 화면 = `WS_POPUP` + 모니터 크기. 독점 전체 화면은 하지 않는다.

**구현 위치:**
- `Source/Programs/JGConsole/Cook/` 에 단계별 파일을 둔다. JGConsole 규칙("JGConsole 전용 명령은 이 프로그램에")을 따른다.
- `JGConsole/Main.cpp` 는 argv 첫 토큰이 `-runCook` 이면 `cook.run` 으로 바꿔 실행한다.
- 프로세스 실행(출력 → 로그 파일, 종료 코드, 시간 제한)은 우선 `Cook/ProcessRunner` 로 두고, 에디터 메뉴(GP-E2)가 필요해지면 Core `HPlatform` 으로 올린다.
- 에디터는 자기 DLL 을 다시 빌드할 수 없다. 그래서 에디터에서 패키징할 때도 이 명령을 자식 프로세스로 부른다.

**출력 폴더 가드**(지우기 전에 반드시 확인):
- 지워도 되는 경우: 폴더가 없음 · 비어 있음 · 이전 패키지(`Bin/JGPackage.json` 이 있음)
- 이 밖의 폴더면 실패한다.
- 드라이브 루트, 엔진 루트, 프로젝트 루트이거나 그 조상 폴더면 무조건 실패한다.
- 동시에 쿠킹하지 않게 `<Project>/Temp/Cook/cook.lock` 을 잡는다.

**실패 처리:**
- 단계마다 `[Cook n/10] <이름> … ok (12.3 s)` 를 한 줄 출력한다.
- 실패하면 원인 줄(빌드 오류는 마지막 30줄)과 로그 경로를 보여 주고 종료 코드 1 로 끝낸다.
- 이전 패키지는 남긴다(4-1 스테이징).

### 4-9 모듈 닫힘 (B10 · R5 를 대신함)

- **목록 만들기:** 뿌리는 `GameHost` + `GameModules` 다. 각 `module.json` 의 `ModuleDependencies` 를 따라가며 SharedLib 만 모은다. Core 는 StaticLib 이라 각 DLL 안에 들어 있다. 결과는 의존 순서(위상 정렬)로 `RuntimeModules` 에 쓴다.
- **가드:**

  - `GUI` · `Devkit`(ImGui 기반 개발용)이 들어오면 경고한다.
- **module.json 에 새 필드는 필요 없다.** 폴더와 `.jgproject` 로 판별한다. 09-29 B10 메모("`GameModules` / `EditorModules` 를 BuildTool 이 읽으면 새 필드 없이 가능")와 같은 결론이다.

### 4-12 런타임 의존 감사 · CRT

- **감사 방법:** 배치한 exe · DLL 의 PE import 표(지연 로드 포함)를 읽고, DLL 이름마다 아래 순서로 판정한다.
  1. 이미 배치됨 → 통과
  2. Windows 시스템 DLL(System32 에 있고 재배포 대상이 아님, `api-ms-win-*`) → 통과
  3. VC 런타임 → VS Redist(`VC/Redist/MSVC/<ver>/x64/Microsoft.VC143.CRT`, 컴파일러 14.38 이상 버전)에서 복사
  4. 그 밖 → `<Project>/Bin/<Config>` 에 있으면 복사하고 경고, 없으면 실패
- **왜 감사가 핵심인가:** 개발 PC 는 System32 에 VC 런타임이 깔려 있어서, CRT 를 빠뜨려도 실행된다. 스모크로는 못 잡고 감사로만 잡힌다.
- **이 PC 확인:** `vswhere.exe` 있음. Redist 14.36 · 14.38 · 14.42 있음.
- **대안:** VC++ 재배포 설치 파일을 요구한다(설치 프로그램이 생길 때).

## 8. 검증 계획

공통으로 검증 게임 `Temp/Games/GPCheck` 를 쓴다. 템플릿에 게임 UI 버튼 · 입력란 하나와 월드 메시 하나를 넣은 것이다.

**M1 (개발 모드, `GPCheck/Bin/DevelopGame/JGLauncher.exe -game`):**
1. 창 제목 = `GPCheck`. 로그에 GUI · DevConsole · Devkit · DevStatistics · JGEditor 시작 줄이 0, `GPCheckEditor` 연결이 0
2. 리드백 PNG 에서 화면 전체가 월드 + 게임 UI 다(ImGui 창 · 메뉴 막대 없음)
3. 입력이 모두 동작한다:
   - 버튼 클릭 이벤트
   - 입력란 영문 · 한글(IME 확정)
   - Esc 뒤로가기
   - 월드 클릭 → 컨트롤러 피킹 로그
4. 창 크기 변경 3회, 최소화/복원, `-fullscreen`, 다시 창 모드 — D3D 오류 0
5. 닫기 → 종료 0 · live 0. 에디터 회귀: 같은 프로젝트를 에디터로 띄워 씬 뷰포트 e2e 가 같다

**M2 (패키지):**
1. `JGConsole.exe -runCook -project=…/GPCheck` 를 엔진 루트와 `C:\` 두 작업 폴더에서 실행 → 둘 다 종료 0, 결과가 같다
2. 레이아웃이 `Bin/` · `Content/` · `GPCheck.exe` 만이다. `Bin` = 닫힘 목록 + `JGGameLaunch` + CRT + assimp 이고 에디터 DLL 은 0, import 감사 통과
3. `GPCheck.exe` 실행 → M1 1~5 와 같고, 로그가 `Saved/Logs/GPCheck.log` 에 남는다
4. 패키지를 공백이 든 다른 경로로 복사해 실행 → 같다. 패키지 모드 개발 경로 함수 오류 로그 0, Content 밖 읽기 경고 0(읽기 가드)
5. 실패 경로가 모두 종료 1 + 메시지로 끝난다:
   - 깨진 에셋 참조
   - 에디터 모듈 의존
   - 출력 가드(엔진 루트 지정)
   - 빌드 오류
6. 회귀: 엔진 PreBuild · 배치 1 · 2 · 에디터 · 자체 테스트 5종이 그대로다(D1 의 루트 변경)

**M3:**
1. ProjectAH 패키지 플레이(게임 구현)
2. 패키지 exe 2개로 Host/Join 해서 seq · 체크섬이 같다(Server)
3. 에디터 씬 뷰포트를 공용 뷰포트로 옮긴 뒤 e2e 가 같다(JGEditor)
