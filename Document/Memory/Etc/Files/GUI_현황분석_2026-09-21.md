## 0. 요약

- **빌드·실행 정상.** GUI 모듈은 컴파일되고, 런처 실행 시 메인 메뉴 + 도킹 레이어 + DevFeature 창(씬 이미지)이 뜬다. 로그에 GUI 쪽 오류 없음.
- **구조는 잡혀 있지만 "최소 동작" 상태.** 2024-11 재설계 후 위젯 3종·컴포넌트 2종·정적 래퍼 함수 9개가 전부다. 옛 설계(GGUIGlobalSystem, Builder, 컴포넌트 라이브러리 9종)는 `Source/Runtime/GUI_백업.zip`에만 남아 있다.
- **확정 버그 8건.** 핵심은 위젯 업데이트 경로가 통째로 죽어 있다는 것: `OnUpdate`/`OnUpdateFrame`이 어떤 위젯에서도 호출되지 않는다(플래그 설정 API 부재 + `UpdateFrame` 대신 `Update` 호출). 그래서 DevScene이 렌더링을 `OnGenerateGUI` 안에서 한다. 메뉴 트리는 이름 충돌·CanAction 미사용 버그가 있다.
- **수명/동기화 위험 8건.** 스케줄 태스크 미해제(스케줄러에 해제 API 자체가 없음), 위젯 맵 미정리, GPU 완료 대기 없이 SRV 힙 해제, SRV 링 오버플로 미검사 등. 지금은 종료 경로가 하나뿐이고 파이프라이닝이 없어 증상이 없다.
- **정리 대상 다수.** 죽은 코드, 저장소에 추적된 백업 zip 2개, 데모 소스 컴파일 포함, 복붙 로그 카테고리.

## 2. 동작 방식

### 2.1 모듈 수명

**시작**(`HJGDev_GraphicsModule::StartupModule`, `JGDev_Graphics.cpp:26`)
```
창 생성 → GlobalValues.MainWindow 설정
→ Connect Graphics → Connect GUI → Connect Asset → Connect DevStatistics → Connect DevConsole → Connect Devkit
→ 메뉴 Dev/DevAI 등록 → OpenWidget<JGDevFeature>()
```
`HGUIModule::StartupModule`(`GUIModule.cpp:17`): Graphics Connect(이미 연결됨) → `PDX12GUIBackend` 생성·Initialize → `OnMainMenuGUI`/`OnGUI`에 자신을 `AddRaw` → 스케줄 등록 2개(`Update` 우선순위, 30Hz `UpdateWidgets`, 매 프레임 `UpdateFrameWidgets`).

`PDX12GUIBackend::Initialize`(`DX12GUIBackend.cpp:29`): ImGui/ImPlot 컨텍스트, 다크 스타일, 키보드 내비게이션 + **도킹 + 멀티 뷰포트** 켜기 → `WindowCallBacks`의 `WndProc`/`OnResize`에 약참조(`AddSP`) 등록 → `ImGui_ImplWin32_Init(MainWindow 핸들)` → `FindModule<HJGGraphicsModule>()`로 `PDirectX12API` 획득 → SRV 힙(1024, 셰이더 가시) + 커맨드 할당자/리스트 생성 → `ImGui_ImplDX12_Init(device, BufferCount=3, R16G16B16A16_FLOAT, 힙, 슬롯0)` → 프레임버퍼 `OnUpdate`/`OnPresent`에 약참조 등록 → `GraphicsBegin` 우선순위에 `NewFrame` 스케줄.

암묵적 전제 두 가지가 있다. (1) GUI Connect 전에 `MainWindow`가 설정되어 있어야 한다(없으면 `ImGui_ImplWin32_Init`에 null 핸들). (2) Graphics의 `PDirectX12API`가 초기화되어 있어야 한다(`JG_CHECK`). 지금은 JGDev_Graphics의 순서가 이걸 만족한다.

**종료**(`HJGDev_GraphicsModule::ShutdownModule`, `JGDev_Graphics.cpp:98`)
```
Disconnect Devkit → DevConsole → DevStatistics → Asset → GUI → Graphics
```
`DisconnectModule`은 `ShutdownModule()` → 맵 제거 → `GMemoryGlobalSystem::Flush()` → 모듈 객체 `Deallocate` 순서다(`Module.cpp:199`). `HGUIModule::ShutdownModule`(`GUIModule.cpp:34`): 위젯 전부 `Shutdown()`(컴포넌트 Shutdown → `OnShutdown`, 컴포넌트 목록 clear) → 백엔드 `Shutdown()`(SRV 힙·리스트 Reset → `ImGui_ImplDX12_Shutdown` → `ImGui_ImplWin32_Shutdown` → ImPlot/ImGui 컨텍스트 파괴) → 백엔드 Reset. **`Widgets` 맵은 비우지 않는다.** 위젯 객체는 모듈 객체가 Deallocate될 때 참조가 풀리고 그다음 Flush(Graphics Disconnect)에서 파괴된다. DLL은 `GCoreSystem::Destroy` 끝에서 일괄 해제되므로 그 시점에 vtable은 살아 있다.

Devkit 모듈의 `ShutdownModule`은 비어 있어서 `JGDevScene`이 잡고 있는 GPU 리소스(렌더 타깃 5장, 머터리얼, 메시, 커맨드)는 Devkit이 아니라 **GUI Shutdown의 위젯 Shutdown 시점**에 풀린다. Graphics가 마지막에 내려가므로 순서는 맞다.

### 2.2 프레임 흐름

스케줄러는 `EMainThreadExecutionOrder` 값 오름차순으로 버킷을 돌고, 같은 버킷 안은 등록 순서다(`Scheduler.cpp:48`). Graphics의 `BeginFrame`이 GUI의 `NewFrame`보다 먼저 등록되므로 아래 순서가 보장된다.

```
GraphicsBegin  HJGGraphicsModule::BeginFrame        큐 Begin(지난 제출 펜스 대기), 스테이징 BeginFrame
               PDX12GUIBackend::NewFrame            SRV 링 인덱스 = 1
                 ImGui_ImplDX12/Win32/ImGui NewFrame
                 풀스크린 투명 창 "DEFAULT_UI_SYSTEM_LAYER" + DockSpace(PassthruCentralNode)
                 OnMainMenuGUI → HMainMenuTree::GenerateMainMenuGUI   ← 메뉴 클릭 Action(OpenWidget)은 여기서 즉시 실행
                 OnGUI → HGUIModule::GenerateWidgetGUI
                   열린 JGWidget마다: PushID → Begin(제목, &open) → SetupLayout→OnLayout → OnGenerateGUI → End → PopID
                     JGDevFeature::OnGenerateGUI → DevScene->GenerateGUI (BeginChild → JGDevScene::OnGenerateGUI)
                       ├ RenderScene()  : 지오메트리 패스 + 합성 패스를 Default 우선순위 리스트에 기록
                       └ HGUI::Image     : GPUAllocate → SRV 링 슬롯에 CopyDescriptorsSimple → ImGui::Image
Begin
Update         HGUIModule::UpdateWidgets(30Hz), UpdateFrameWidgets(매 프레임)   ← 현재 둘 다 아무 위젯도 갱신하지 않음 (3-A-1, 3-A-2)
End
GraphicsEnd    HJGGraphicsModule::EndFrame
                 RecordUploads(Upload 리스트) → FrameBuffer.Update(Present 리스트)
                   백버퍼 PRESENT→RT, 클리어 → OnUpdate → PDX12GUIBackend::OnUpdate
                     OMSetRenderTargets(백버퍼) + SetDescriptorHeaps(SRV 힙) + ImGui::Render + RenderDrawData   ← 화면에 보이는 건 전부 ImGui
                   → PRESENT 전이
                 RecordReadbacks → 큐 End(우선순위 순 실행, Signal) → Present
                   OnPresent → PDX12GUIBackend::OnPresent → UpdatePlatformWindows + RenderPlatformWindowsDefault (뷰포트별 ImGui 자체 큐)
UpdateWindow   메시지 펌프 → WndProc → ImGui_ImplWin32_WndProcHandler / WM_SIZE → OnResize → FrameBuffer.Resize
```

요점 세 가지.
1. **최종 화면 = ImGui 드로우.** 엔진 씬은 텍스처로 렌더되고 `HGUI::Image`로 ImGui 창 안에 표시된다. 백버퍼 포맷 `R16G16B16A16_Float`는 ImGui 초기화 인자와 일치한다(`DirectX12API.cpp:80`, `DX12GUIBackend.cpp:74`).
2. **위젯 GUI 생성이 `Update` 단계보다 앞선다.** `GraphicsBegin` 버킷 안에서 GUI가 만들어지므로 `Update`에서 바꾼 위젯 상태는 다음 프레임에 보인다. 버그는 아니지만 위젯 업데이트 경로가 살아나면 알고 있어야 한다.
3. **씬 렌더가 GUI 생성에 묶여 있다.** `JGDevScene::RenderScene()`이 `OnGenerateGUI`에서 불리므로 DevFeature 창을 닫으면 씬 렌더도 멈춘다. 업데이트 훅이 죽어 있어 생긴 우회다(3-A-2).

### 2.3 위젯 프레임워크

- `JGWidget`: `JGObject` 파생, JGCLASS 리플렉션. `JG_GENERATED_WIDGET_BODY`는 생성 바디에 `GetStaticGUID()`(인라인 static 지역, **프로세스마다 랜덤 GUID**)를 더한다. 이 GUID가 `HGUIModule::Widgets`의 키다(같은 클래스 위젯은 1개만 존재). `OpenWidget<T>`는 템플릿이라 **소비자 DLL 안에서 인스턴스화되어 GUI 모듈의 `Widgets` 맵을 직접 조작**한다. 같은 컴파일러·CRT·설정이라 지금은 문제없다. `GetStaticGUID()`의 static 지역은 dllimport 클래스라면 MSVC가 내보낸 DLL 쪽 하나를 쓰므로 `JGDevFeature`(DEVKIT_API)를 JGDev_Graphics.dll에서 열어도 키가 같다.
- 훅: `OnInitialize/OnShutdown/OnOpen/OnClose/OnUpdate/OnUpdateFrame/OnLayout/OnGenerateGUI`, `GetTitleName()`(ImGui 창 제목 = 실질 식별자), `GetGUID()`(기본 null GUID).
- `JGWidgetComponent`: `Construct()`(`Allocate`가 호출, `Memory.h:599`)에서 GUID 발급 → `BeginChild(GUID 해시)`. 크기는 부모 위젯이 `OnLayout`에서 `SetupLayout(HWidgetComponentLayout)`으로 매 프레임 넣어 준다. 플래그는 `Border`만 반영, `AutoSize`는 선언만.
- `HMainMenuTree`: `AddMainMenuItem("A/B/C")`가 토큰별로 노드를 만들고 마지막 토큰에 아이템을 붙인다. 리프 판정은 `ChildIndexes.empty()`.
- `HGUI::Image`: `GPUAllocate` → 텍스처의 CPU SRV 핸들을 셰이더 가시 힙의 다음 슬롯(1부터, 0은 ImGui 폰트)에 복사, GPU 핸들을 `ImTextureID`로 반환. 인덱스는 `NewFrame`과 `OnUpdate` 끝에서 1로 리셋된다. **한 프레임 안에서만 유효한 링**이다.

### 2.4 옛 설계와의 관계

`Source/Runtime/GUI_백업.zip`(871KB, init 커밋 `c5944f4`부터 추적, 내부 파일 날짜 2023-03 ~ 2024-01)에는 재설계 전 GUI가 들어 있다: `GGUIGlobalSystem`(글로벌 시스템 방식), `HGUIBuilder/HMenuBuilder/HContextMenuBuilder`, `WWidget/WWidgetComponent`(IMemoryObject 기반, 마우스 이벤트 리시버 주석), 컴포넌트 9종(`WBorder, WButton, WComboBox, WInputScalar, WInputText, WList, WSelectable, WText`, `WidgetComponent`), `GUIStyles`, `MenuCommand(s)`, `WidgetContext`, `WMessageBox/WTaskProgressBar`(빈 파일). 현재 설계는 이를 모듈(`HGUIModule`) + JGObject 리플렉션 위젯 + `HGUI` 정적 래퍼로 바꾼 것이고, 컴포넌트 라이브러리와 스타일, 컨텍스트 메뉴는 아직 다시 만들지 않았다(`GUIModule.h:30` 주석 "Context 메뉴 추가"). `JGEditor`의 주석 잔재도 이 옛 설계를 가리킨다.

## 4. 권장 순서 (제안)

1. **P1 버그 수정 (작음, 반나절)** — 3-A 1~7. 특히 2번은 결정이 필요하다: (a) `SetWidgetFlags` API를 추가하고 위젯이 스스로 켜게 하거나, (b) 열린 위젯은 항상 `OnUpdate`/`OnUpdateFrame`을 받도록 플래그 의미를 "항상(닫혀도) 갱신"으로만 축소한다. 어느 쪽이든 `JGDevScene::RenderScene()`을 `OnUpdateFrame`으로 옮겨 GUI 생성과 렌더를 분리할 수 있다. 4번은 키를 전체 경로(`PName("Windows/Statistics")`)로 바꾸면 끝난다.
2. **P2 수명 정리** — 스케줄러에 `Unschedule(ID)` 추가 후 GUI/Graphics/JGDev_Graphics의 `CreateRaw` 태스크 해제, `HGUIModule::ShutdownModule`에서 `Widgets.clear()`, GUI Shutdown 앞에 큐 `Flush()`(또는 Graphics가 제공하는 "GPU 완료 대기" API 호출), `OnResize` 책임을 Graphics 모듈로 이동. 5-5 파이프라이닝 전에 SRV 링을 프레임별 세그먼트로.
3. **P3 정리** — 죽은 코드, zip 2개, 데모 제외, 로그 카테고리, `HGUI` 래퍼 확장 방향(옛 컴포넌트 9종을 `HGUI` 함수로 되살릴지, `JGWidgetComponent` 파생으로 만들지) 결정. ImGui 업그레이드는 `GPUAllocate` 재설계와 묶어서.
