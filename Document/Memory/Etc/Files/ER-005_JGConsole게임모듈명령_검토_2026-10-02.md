4. 엔진 변경이 가장 작다(새 파일 · Core · GFW 변경 없음).

대가: 요청서 완료 기준의 호출이 한 낱말 길어진다. 모르는 명령 안내(4절)로 메운다. 사용자가 "선언한 명령은 어디서든 보이길"(09-30 12:31 DevConsole 기록) 쪽을 더 원하면 (c) 가 그 호출을 그대로 주면서 기존 명령을 건드리지 않는 차선이다.

## 4. 제안 설계 — (b)

| 항목 | 제안 |
|---|---|
| 문법 | `JGConsole.exe [-game] <명령> [인자...]`. JGConsole 이 아는 앞 옵션(`-game`)만 맨 앞에서 먹고, 그다음 토큰부터는 지금처럼 명령이다. DevOps GP-D4 의 별칭(첫 토큰 `-runCook` → `cook.run`, 설계 4-8)은 "앞 옵션을 먹은 뒤의 첫 토큰"에 적용한다 — 같은 함수(`runCommandLine`)에 두 변경이 추가분으로 들어간다 |
| 연결 | `-game` 이면 `CONSOLE_ENGINE_MODULES`(GameFrameWorks) 다음에 `HProjectDescriptor::Load(HFileHelper::ProjectDirectory())` 의 `GameModules` 를 적힌 순서대로 `ConnectModule`. `EditorModules` 는 연결하지 않는다(GUI 없음 — `module.test` 와 같은 이유). 게임 모듈 안의 `ConnectModule("GameFrameWorks")` 는 이미 연결이라 true 만 받는다. 해제는 지금처럼 `GCoreSystem::Destroy` 가 역순(게임 모듈 → GameFrameWorks) |
| 실패 | 프로젝트 모드가 아니면(엔진 Bin) Error "-game needs a game project: run <Project>/Bin/<구성>/JGConsole.exe" 를 남기고 명령을 돌리지 않고 종료 1. 게임 모듈 연결 실패(`ConnectModule` false — DLL 없음 등)도 명령을 돌리지 않고 1. `GameModules` 가 비어 있으면 Warning 만 |
| 종료 코드 | 요청서대로 그대로: 명령 성공 0, 실패 · 모르는 명령 1(+ 위 두 실패 1). 게임 모듈 시작 중 Error 로그는 보이기만 하고 종료 코드는 명령이 정한다. 시작 오류를 엄격히 볼 때는 `module.test <게임>`(Error 한 줄이면 1) |
| 안내 | 프로젝트 모드에서 `-game` 없이 첫 토큰이 등록되지 않은 명령이면(`GConsoleCommandGlobalSystem::IsRegistered` false — 이미 있음) Unknown 오류 앞에 Info 한 줄: "Game module commands need -game: JGConsole.exe -game <명령>" |
| 바뀌는 파일 | `Source/Programs/JGConsole/Main.cpp`(+40~60줄, 머리 주석의 사용법 줄 포함). 문서: `Etc/현황.md` §1.3 명령 표 · §1.6, `ConsoleCommandGlobalSystem.h` 상단 사용법 주석 한 줄, DevOps `Files/게임프로젝트_생성가이드.md` §3 "창 없이 확인"(DevOps 에 알림) |
| 지금 그대로인 JGConsole 성질(문서에 적어 둠) | 프레임을 돌리지 않는다(`Submit` 한 명령은 `ExecutePending` 을 불러야 실행 — 현황 §1.5), GC 를 돌리지 않는다(`GMemoryGlobalSystem::Flush`, GFW B-3 메모). 그래서 `-game` 으로 올린 월드는 시작 상태 그대로다 — 게임 쪽 `ah.state` · `ah.legal` 처럼 진행 중 경기를 보는 명령은 헤드리스에서 "경기 없음"이 정상 |
| 나중에 맞출 것(선택) | DevOps GP-D5 가 넣는 중인 `HRuntimeModuleInfo`(프로젝트 `Temp/CodeGen/runtime_module_info.json` — `RuntimeModules` · `GameModules`)와 `bRuntimeModulesOnly`(게임만 실행할 때 코드젠에서 에디터 DLL 을 올리지 않음)가 들어오면, `-game` 도 같은 목록을 쓸 수 있다. 지금 JGConsole 은 게임 Bin 에서 에디터 DLL 까지 로드만 한다(연결 안 함 — 해 없음). 필수 아님 |

## 7. 사용자 결정 — 진행현황 D-30 (쉬운 말, 지침서 §4)

1. **지금 생기는 일**: 게임 폴더에서 콘솔 실행기(JGConsole)로 게임의 자체 테스트 명령을 부르면 "그런 명령 없음"으로 끝난다. 실행기가 엔진 쪽 모듈만 켜고 게임 모듈은 켜지 않기 때문이다. 그래서 게임 쪽은 지금 환경 변수를 켜고 "모듈 켜기 · 끄기 점검"(`module.test`)을 돌리는 우회로 쓰고 있다.
2. **언제**: 게임의 규칙 · 데이터 검사를 사람 손 없이 매번 같은 방식으로 돌릴 때. 에디터 안의 콘솔 창에서는 지금도 된다.
3. **고를 것** ((가)~(라) = 3절 (a)~(d))

| | 무엇이 달라지나 | 대략 |
|---|---|---|
| (가) 게임 폴더에서 실행하면 늘 게임 모듈을 켬 | 부르는 법은 요청 그대로. 대신 모든 실행이 게임을 먼저 띄워 느려지고 게임 로그가 섞인다. 지금 쓰는 "모듈 켜기 · 끄기 점검"은 이미 켜져 있어서 아무것도 검사하지 않게 된다. 게임 폴더에서 돌린 엔진 자체 테스트 일부가 건너뛰어진다 — 이걸 메우는 보완까지 해야 한다 | 1~2일 |
| **(나) 명령 앞에 `-game` 을 붙일 때만 게임 모듈을 켬** | 부르는 법이 한 낱말 길어진다(`JGConsole.exe -game ah.selftest`). 다른 명령과 지금 점검 절차는 하나도 안 바뀐다. 붙이지 않고 게임 명령을 부르면 "-game 을 붙이세요" 안내가 나온다 | 반나절 |
| (다) 찾는 명령이 없을 때만 게임 모듈을 켜서 다시 찾음 | 부르는 법은 요청 그대로, 다른 명령도 그대로. 다만 명령 목록(`help`)에 게임 명령이 안 보이고, 엔진 명령을 잘못 쳐도 게임을 띄운 뒤에야 "없음"이 나온다 | 반나절 |
| (라) 반려 | 게임 쪽 우회(환경 변수 + 점검 명령)를 그대로 쓴다 | 0 |

4. **권고**: (나). 다른 명령과 지금 점검 절차가 그대로이고, "게임을 띄운다"가 명령줄에 보이며, 게임 실행 옵션(`JGLauncher -game`)과 같은 말이다.
5. **급한지**: 급하지 않다. 게임 쪽은 우회로 진행 중이라 막힌 작업이 없다.
