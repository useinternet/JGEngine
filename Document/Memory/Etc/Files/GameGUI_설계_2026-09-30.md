# GameGUI 설계 (게임 전용 런타임 UI) — 2026-09-30

> **대체됨 (2026-10-01 오전)**: 사용자 지시로 별도 `GameGUI` 모듈 구조를 버리고 GameFrameWorks 안 `UI/`(`JGGameWidget` · CommonUI식 레이어 스택)로 옮겼다. 지금 설계는 `Document/Memory/GameFrameWorks/Files/GameUI_설계_2026-10-01.md`. 이 문서의 §3(2D 그리기 경로) · §4(글꼴 · 이미지 · 입력) · §5-1(좌표) 내용은 그대로 유효하고, §0 · §2 · §5-2 · §6 · §8(모듈 구조 · 캔버스 · 파일)은 이력이다.

사용자 지시(09-30 밤): "GameGUI 시스템을 설계문서 → 기반 → 최소 요소 → 검증까지 진행". 결정 대기였던 진행현황 D-12(게임 UI 트랙 신설)의 착수 지시다.
기준: 엔진 기반만 다룬다(지침서 §1). 이 문서의 요구는 "어떤 보드·카드 게임에도 그대로 쓰이는가"로 거른다. 과설계 금지(§5): 지금 필요한 것만 만들고 나머지는 "나중" 칸에 조건과 함께 둔다.

## 0. 결론

| 항목 | 결정 |
|---|---|
| 무엇 | 게임이 플레이어에게 보여 주는 화면 UI(HUD, 패널, 버튼, 글자, 카드 이미지). **ImGui(GUI 모듈)·에디터에 의존하지 않는 런타임 모듈 `GameGUI`** |
| 누가 쓰나 | 게임 모듈(엔진 밖 GameProject)이 캔버스와 요소를 만들고 이벤트를 받는다 |
| 누가 그리나 | **호스트**. 지금은 에디터 Scene Viewport(JGEditor), 나중에는 단독 실행 호스트(D-5 보류). 호스트는 월드를 그린 출력 텍스처 위에 캔버스를 그리고, 포인터 입력을 먼저 GameGUI에 준다 |
| 어디에 그리나 | 씬 출력 텍스처 위(별도 2D 패스). 그래서 에디터 뷰포트와 나중의 단독 게임에서 똑같이 보인다 |
| 기반 | ① Graphics 2D 그리기 경로(정점·인덱스를 매 프레임 올리고, 배치마다 텍스처·클립, 알파 블렌드, 내장 셰이더) ② TTF 글꼴(stb_truetype, 동적 글리프 아틀라스, 한글) ③ 이미지 파일 → 텍스처(stb_image) ④ 호스트가 넣는 포인터 이벤트 |
| 최소 요소 | 캔버스(기준 해상도·맞춤 배율), 요소 트리(앵커·피벗·위치·크기), Image(패널 겸용), Text, Button(상태 색·라벨·클릭 이벤트), UI 먼저 판정(소비되면 월드 피킹 안 함) |
| 검증 | V1 헤드리스 `JGConsole.exe gamegui.selftest` · V2 검증 게임 프로젝트를 에디터 Scene Viewport에서 실제 클릭 · V3 기존 회귀 |

## 1. 요구사항 (보드·카드 게임 공통)

| 요구 | 예 | 이번 | 나중 (조건) |
|---|---|---|---|
| 이미지 | 카드 앞·뒷면, 패널 배경, 아이콘 | Image: 텍스처 또는 단색, 색 곱하기, UV 사각형 | 9-slice(테두리 늘리기), 밉맵(Graphics 5-29) |
| 글자 | 카드 이름·수치, 턴 표시, 한글 | Text: TTF, 크기, 색, 가로·세로 정렬, `\n` 줄바꿈 | 자동 줄바꿈, 리치 텍스트, 로컬라이제이션 표(문자열 테이블 트랙) |
| 버튼 | 턴 종료, 선택지 | Button: 보통·호버·누름 색, 라벨, `OnClicked` | 비활성 상태, 키보드·게임패드 포커스 |
| 해상도 대응 | 1280×720 ~ 4K | 캔버스 기준 해상도 + 맞춤 배율(min), 앵커·피벗 | 늘이기 앵커, 레이아웃 그룹(손패 부채꼴), 안전 영역 |
| 입력 우선순위 | UI 위 클릭이 보드를 찍지 않게 | 포인터 이벤트 → 위에 있는 요소부터 판정, 소비 여부 반환 | 드래그 앤 드롭(카드 끌기), 툴팁, 호버 지연 |
| 연출 | 카드가 날아감, 강조 | (없음) | GFW 2-4 시퀀서와 함께 트윈 |
| 모달·프롬프트 | "카드를 골라 버려라" | 패널 + 글자 + 버튼 조합으로 만든다 | 모달 스택 |

## 2. 구조

```
 게임 모듈 (엔진 밖)                              호스트 (에디터 JGSceneViewport / 나중 단독 실행 호스트)
   CreateCanvas, AddChild<PGameGUIButton>, OnClicked   │ OnUpdate: 월드 렌더 → RenderCanvases(출력 텍스처)
          │                                            │ OnGenerateGUI: 이미지 입력 → HandlePointer → 소비되면 피킹·궤도 생략
          ▼                                            ▼
 ┌─ GameGUI 모듈 (Core · Graphics 의존. GUI · GameFrameWorks 에 의존하지 않음) ──────────────┐
 │ HGameGUIModule  캔버스 목록 · 글꼴/텍스처 캐시 · RenderCanvases · HandlePointer        │
 │ PGameGUICanvas  기준 해상도 · 배율 · 정렬 순서 · 루트 요소 · 호버/캡처 상태            │
 │ PGameGUIElement ─ PGameGUIImage / PGameGUIText / PGameGUIButton                      │
 │ HGameGUIDrawList  사각형 → 정점·인덱스, (텍스처, 클립)별 배치                          │
 │ PGameGUIFont      stb_truetype, (코드포인트, 픽셀 크기)별 글리프, RGBA8 아틀라스      │
 │ PGameGUIRenderer  그리기 목록 → Graphics 2D 경로                                     │
 └───────────────────────────────────────────────────────────────┬───────────────────────┘
                                                                  ▼
 Graphics: IJGGraphicsCommand::Draw(const H2DDrawArguments&) — 내장 셰이더 draw2d.hlsl, 알파 블렌드, 깊이 없음
```

| 모듈 의존 | 이유 |
|---|---|
| GameGUI → Core, Graphics | 그리기와 텍스처 |
| GameGUI ↛ GUI(ImGui), GameFrameWorks | 게임 UI는 에디터 도구와 게임 규칙 어느 쪽에도 묶이지 않는다(GFW를 순수 로직으로 둔 사용자 결정과 같은 원칙) |
| JGEditor → GameGUI | Scene Viewport가 호스트 |
| 게임 모듈 → GameGUI (+ GameFrameWorks) | 게임이 UI를 만든다. 모듈 연결은 게임이 한다(GameFrameWorks와 같은 방식) |

## 3. 기반 ① Graphics 2D 그리기 경로

기존 명령 계층에는 Surface(메시+머터리얼)와 Screen(풀스크린) 두 그리기만 있다. 머터리얼 도메인을 하나 더 만드는 대신 **내장 셰이더 + 전용 그리기 함수**를 둔다. 머터리얼 템플릿·컴파일 경로를 건드리지 않아 기존 그리기에 영향이 없다. 게임이 UI 셰이더를 직접 쓰는 일(카드 반짝임 등)이 생기면 그때 UI 머터리얼 도메인을 검토한다.

| 추가 | 위치 | 내용 |
|---|---|---|
| `H2DVertex` | `JGGraphicsDefine.h` | `HVector2 Position`(렌더 타깃 픽셀), `HVector2 Texcoord`, `HLinearColor Color` = 32바이트 POD. 입력 레이아웃 POSITION float2 · TEXCOORD float2 · COLOR float4 |
| `H2DDrawCommand` | 같은 곳 | `PSharedPtr<IRawTexture> Texture`, 클립 `int32 ClipLeft/Top/Right/Bottom`(타깃 픽셀), `uint32 IndexOffset/IndexCount` |
| `H2DDrawArguments` | 같은 곳 | 정점·인덱스·명령 목록 포인터(호출 동안만 읽음), `HVector2 TargetSize` |
| `IJGGraphicsCommand::Draw(const H2DDrawArguments&)` | `JGGraphicsCommand.h` | 순수 가상. 구현은 DX12 하나 |
| DX12 구현 | `DX12GraphicsCommand.cpp` | 내장 셰이더 바인딩 → 입력 레이아웃 → 알파 블렌드(색 SrcAlpha/InvSrcAlpha, 알파 One/InvSrcAlpha) · 컬링 없음 → PSO 확정(해시 캐시) → 패스 CB(`Resolution` = 타깃 크기) → 정점·인덱스 업로드 → 명령마다 텍스처(슬롯 0)·시저·`DrawIndexed`. 끝나면 블렌드·래스터 상태를 기본으로 되돌린다 |
| 동적 정점·인덱스 | `CommandList.h/.cpp` | `BindDynamicVertexBuffer(data, count, stride)`, `BindDynamicIndexBuffer(data, count)`: 커맨드 리스트 업로드 할당자(2MB 페이지, 프레임마다 재사용)에서 받는다. 한 번에 페이지를 넘으면 오류 로그 후 그리지 않는다(정점 6만5천 개 = 사각형 1만6천 개) |
| 내장 셰이더 | `Source/Shader/draw2d.hlsl`(신규), `GShaderLibrary::GetShaderCode(name)`(신규 접근자), `PDirectX12API`가 처음 쓸 때 컴파일해 들고 있음 | VS: 픽셀 → NDC(`_Resolution`), PS: `_Draw2DTexture.Sample(_LinearClamp_, uv) * color`(`_Draw2DTexture` = t0 space0, 배치 텍스처를 표 0번 슬롯에 묶는다). 루트 서명은 엔진 표준(b0 패스 CB, t0 텍스처 표, s4 LinearClamp)을 그대로 쓴다 |

주의
- 출력 텍스처는 `R16G16B16A16_Float`이고 색은 그대로 쓴다(ImGui와 같음). 색 공간은 D-3(5-14)이 정해지면 따른다.
- 텍스처가 없는 명령(단색)은 DX12 구현이 엔진 기본 텍스처(흰색 1×1, `HDirectXAPI::GetDefaultTexture`)로 그린다. 클립이 비었거나 인덱스 범위가 틀린 명령은 건너뛴다. (구현 때 바꿈 — 처음 설계는 "오류 로그 후 건너뛰고 GameGUI가 흰 텍스처를 든다"였다)

## 4. 기반 ② 글꼴 · ③ 이미지 · ④ 입력

| 기반 | 설계 | 한계·나중 |
|---|---|---|
| 글꼴 `PGameGUIFont` | TTF 파일 전체를 읽어(std 할당자 — 한글 글꼴은 수 MB, 엔진 풀 블록 한도 2MB) `stbtt_InitFont`. 글리프는 (코드포인트, 픽셀 크기)로 캐시하고 처음 쓸 때 래스터화해 1024×1024 RGBA8 아틀라스(흰색 + 알파 = 커버리지)에 줄 단위로 배치한다. 아틀라스가 바뀌면 그리기 직전에 GPU 텍스처를 다시 만든다(이전 텍스처는 `DeferRelease`로 GPU가 끝낼 때 해제). 줄 높이·자간(kerning)·`\n` | 아틀라스가 차면 경고 후 새 글리프를 그리지 않는다(여러 페이지는 나중). 글꼴 파일은 게임이 Content에 넣고 `LoadFont(path)`. 개발용 기본 글꼴은 시스템 맑은 고딕(`C:/Windows/Fonts/malgun.ttf`) → 없으면 Arial. **시스템 글꼴은 배포 금지 — 게임은 라이선스가 맞는 글꼴을 직접 넣는다** |
| 이미지 | `HGameGUIModule::LoadTexture(path)`: stb_image로 RGBA8 → `CreateRawTexture`(Linear/Clamp, 밉 1). 경로별 캐시 | 밉맵 없음 → 크게 줄여 그리면 계단 현상(Graphics 5-29 밉과 함께). 에셋 파이프라인(`JGTexture`) 연결은 나중. `IRawTexture`를 직접 받는 API도 있다 |
| 입력 | 호스트가 `HGameGUIPointerEvent{ Type(Move/Down/Up/Wheel/Leave), Position(타깃 픽셀), Button(Left/Right/Middle), Wheel }`를 넣는다. `HandlePointer`가 소비 여부를 돌려준다 | 플랫폼 입력(창 메시지 → Core Input)은 단독 실행 호스트(D-5)와 함께. 키보드·포커스는 나중 |

## 5. 최소 요소

### 5-1. 좌표와 배율

| 좌표 | 뜻 |
|---|---|
| 타깃 픽셀 | 렌더 타깃(예 1280×720) |
| 캔버스 논리 단위 | 게임이 정한 기준 해상도(예 1920×1080) 기준. 배율 `s = min(타깃W/기준W, 타깃H/기준H)`, 논리 크기 = 타깃 / s. 요소 좌표는 전부 논리 단위 |
| 요소 사각형 | `부모.min + Anchor × 부모.size + Position − Pivot × Size` (Anchor·Pivot은 0~1) |
| 글자 | 픽셀 크기 = FontSize × s 로 래스터화 → 배율이 바뀌어도 선명하다 |

### 5-2. 타입

| 타입 | 역할 |
|---|---|
| `HGameGUIModule` | `CreateCanvas(name, referenceSize)`, `RemoveCanvas`, `RemoveAllCanvases`, `FindCanvas`, `GetCanvases`, `RenderCanvases(target)`, `HandlePointer(event, targetSize)`, `LoadFont/GetDefaultFont`, `LoadTexture`. 명령 `gamegui.selftest` |
| `PGameGUICanvas` | 이름, 기준 해상도, 정렬 순서(큰 것이 위, 입력도 먼저), 보이기, 루트 요소, 호버·캡처 상태. `BuildDrawList`, `HandlePointer` |
| `PGameGUIElement` | 이름, 보이기, 입력 받기(`bHitTestVisible`), Anchor·Pivot·Position·Size, 자식 목록(`AddChild<T>(name)`, 뒤에 넣은 것이 위). 가상 `onBuildDraw`, `onPointerEnter/Leave/Down/Up` |
| `PGameGUIImage` | 텍스처(없으면 단색), 색, UV 사각형. 패널로도 쓴다 |
| `PGameGUIText` | UTF-8 글자, 글꼴(없으면 기본), 크기, 색, 정렬 |
| `PGameGUIButton` | 보통·호버·누름 색, 텍스처(선택), 라벨·라벨 색·글자 크기, `OnClicked`(멀티캐스트). 입력 받기 기본 켜짐 |
| `HGameGUIDrawList` | 사각형 → 정점·인덱스, 같은 (텍스처 또는 글꼴 아틀라스, 클립)이 이어지면 한 배치 |
| `PGameGUIRenderer` | 그래픽 명령 하나를 들고 캔버스들을 타깃에 그린다 |

### 5-3. 입력 규칙

| 이벤트 | 동작 |
|---|---|
| Move | 논리 좌표로 바꿔 가장 위의 입력 받는 요소를 찾는다. 바뀌면 이전 요소 `Leave`, 새 요소 `Enter` |
| Down(왼쪽) | 맞은 요소가 있으면 `Down`, 캔버스가 그 요소를 캡처. **소비** |
| Up(왼쪽) | 캡처한 요소에 `Up`. 버튼은 누른 상태에서 자기 위에서 떼면 `OnClicked`. 캡처 해제. 캡처가 있었으면 소비 |
| Wheel · 오른쪽·가운데 Down/Up | 입력 받는 요소 위면 소비(월드 줌·궤도를 막는다) |
| Leave | 호버 해제 |
캔버스는 정렬 순서가 높은 것부터 받고, 하나가 소비하면 멈춘다.

## 6. 호스트 연결 (에디터 Scene Viewport)

| 위치 | 변경 |
|---|---|
| `JGSceneViewport::OnUpdate` | 월드 렌더 뒤 `HGameGUIModule::RenderCanvases(_renderer->GetOutputTexture())` (모듈이 연결돼 있을 때만) |
| `JGSceneViewport::handleInput` | 이미지 좌표 → 타깃 픽셀(× 렌더 폭/이미지 폭). 누름(`bClicked`)·뗌(직전 `bDown` → 해제)·이동·휠·벗어남을 이벤트로 넣는다. 소비되면 피킹·궤도·줌을 하지 않는다 |
| `JGEditor.module.json` | 의존에 `GameGUI` |

프로젝트 없는 에디터는 GameGUI를 연결하지 않으므로(게임 모듈이 연결) 아무것도 바뀌지 않는다. (구현 확인: `GameGUI.dll`은 JGEditor 링크로 로드되지만 `StartupModule`은 불리지 않고, Scene Viewport도 열리지 않는다. V3에서 리드백 PNG 불변)
