### 1.3 구현 현황 상세

**흐름**

```
[모듈 DLL 또는 EXE의 .cpp 파일 범위]  static HAutoConsoleCommand X("area.action", "usage", "desc", &handler);
   생성자: 이 바이너리의 정적 목록(Head)에 연결만(풀·레지스트리·로그 사용 안 함, 정적 초기화 = LoadDll 중이라 Core 미연결)
      ↓ 모듈 DLL: GModuleGlobalSystem이 StartupModule 직후 IModuleInterface::RegisterAutoConsoleCommands → 그 DLL의 HAutoConsoleCommand::RegisterAll
      ↓ EXE: 레지스트리 생성자가 RegisterAll(GCoreSystem::Create), Destroy에서 UnregisterAll
GConsoleCommandGlobalSystem (Core 전역 시스템, 메인 스레드 전용)
   _commands: HHashMap<PString, HConsoleCommandDesc{Name, Usage, Description, HConsoleCommandDelegate}>   내장 help [name]
   Execute(line | tokens) 즉시 실행  /  Submit(line) → _pendingLines → Update() = ExecutePending() (스케줄러 모든 버킷 뒤 = 프레임 밖)
입력 A: JGDevConsole 위젯 → Enter → Submit          입력 B: JGConsole.exe argv[1..] → Execute(tokens) → 종료 코드 0/1
출력: JG_LOG → spdlog 싱크 3개(파일 jg_log.txt · stdout · PRecentLogSink) → 위젯이 GetRecentLogs로 표시
미리보기(6-2): 입력줄 글자 → syncCommandPreview → FindCommands(첫 낱말) → HConsoleCommandInfo 목록(핸들러 없음) → 입력줄 위 툴팁
   ↑/↓/Tab: InputTextWithHistory 콜백 → HGUIInputTextKeyDelegate(onInputKey) → 처리하면 입력줄 교체, 아니면 히스토리
로그 필터(6-1): 필터 줄(체크박스 3 + 글자 필터) → 로그 serial 이나 필터가 바뀐 프레임에만 VisibleLines(LogLines 인덱스) 재계산
```

### 1.5 함정 · 주의

| 함정 | 내용 |
|---|---|
| 프로세스별 레지스트리 | 런처 콘솔에서 JGConsole 명령은 안 보이고 반대도 같다. 어떤 모듈의 명령을 어떤 프로그램에서 쓰려면 그 프로그램이 그 모듈을 연결해야 한다: 런처 `JGEditor.cpp:19` `EDITOR_ENGINE_MODULES`, JGConsole `Main.cpp:16` `CONSOLE_ENGINE_MODULES` |
| 로드 ≠ 연결 | 런처는 GameFrameWorks DLL을 클래스 목록용으로 로드만 한다 → 명령 미등록. 명령이 보이면 모듈이 연결됐다는 뜻 |
| Core에 선언 금지 | Core는 정적 라이브러리 → 링커가 .obj를 빼거나 바이너리마다 사본이 생겨 중복 등록. `help`만 레지스트리가 직접 `Register` |
| 파일 범위·캡처 없음 | 함수 안 `static`은 첫 호출 때 생성 → 등록 시점 놓침. 핸들러는 함수 포인터라 캡처 불가 → 모듈 상태는 `FindModule<T>()` |
| 엔진 컨테이너를 static/전역에 두지 않기 | 풀 해제 뒤 DLL 언로드 때 소멸자 크래시. 레지스트리 데이터는 시스템 객체 멤버. `main`의 지역 엔진 컨테이너는 `GCoreSystem::Destroy` 뒤 해제되므로 함수로 분리(`runCommandLine`) |
| 사용자 문자열은 `"%s"` 인자로 | `AddLog`가 서식을 두 번 거친다(`Log.h:56-57`). `HGUI::Text`는 `TextUnformatted`로 고쳤다 |
| `PString::ToInt/ToFloat` 금지 | `std::stoi/stof` 예외 → 엔진에 catch 없음 → 종료 코드 3. `TryGetInt` 또는 `std::from_chars`(64비트는 `TryGetString` 뒤 `from_chars`, 예 `NetCommands.cpp:56-76`) |
| `PString::ToLower` 금지(이름 비교) | 음수 char(한글)에 디버그 CRT assert → `HConsoleCommandArgs::NormalizeName` |
| `Execute` vs `Submit` | 프레임 안(위젯 순회·`OnGenerateGUI`)에서는 `Submit`. JGConsole은 `GCoreSystem::Update`를 돌리지 않아 `Submit`한 줄은 `ExecutePending()`을 직접 불러야 실행된다 |
| JGConsole은 GC를 돌리지 않음 | 핸들러가 GC 객체를 만들면 `GMemoryGlobalSystem::Flush()`를 직접 부른다(GFW TODO B-3 메모) |

## 7. DataTable (데이터 테이블 시스템, 2026-10-01 신규)

### 7.1 역할 · 범위

행(고유 키) × 열(타입) 정적 데이터를 `.jgasset`(내용 JSON) 에셋 `JGDataTable` 로 저장하고, 런타임은 읽기 전용 조회 · C++ 바인딩(`HDataTableView<T>`), 에디터는 "Data Table Editor" 창에서 엑셀처럼(셀 선택 · 키보드 · 바로 입력 · TSV 복사/붙여넣기 · 실행 취소 · 정렬 · 필터) 편집하는 엔진 시스템. 어떤 테이블을 만들고 무슨 열을 둘지는 게임 영역이다.
코드 위치(결정 DT-D3 = GameFrameWorks): Core `FileIO/Json` · `FileHelper` · `Object/ObjectGlobalSystem.h`(추가만), **GameFrameWorks `Source/Runtime/GameFrameWorks/Data/`**(런타임 + 편집 모델 + 셀프 테스트 명령, 18 파일), GUI `Grid/GUIGrid`(데이터를 모르는 그리드) · `GUI.h/.cpp` 끝 13개 래퍼 · `Backends/DX12GUIBackend.cpp` 한글 글꼴, JGEditor `Widgets/DataTableEditor` · `JGEditor.cpp` 메뉴. 파일별 내용은 설계 §14-1.
