## 1. 역할과 범위

| 구분 | 내용 |
|---|---|
| 목적 | 호스트 한 대가 서버 겸 플레이어인 리슨 서버로 턴제 커널 `PGameMaster` 를 여러 기계에 복제한다 |
| 방식 (방안 A) | 호스트의 `PGameMaster` 만 명령을 승인 → `CommandAccepted{seq, slot, 명령, 체크섬}` 방송 → 클라는 복제 `PGameMaster` 에 같은 명령을 `Submit` 하고 체크섬을 비교 |
| 범위 안 | 전송(TCP · 루프백) · 세션(호스트 · 클라) · 메시지 · 입장 / 재접속 / 재동기 · 호스트 AI 구동 · 게임 인스턴스 · 월드 · 액터 연결 · 실행 인자 · 헤드리스 검증 명령 |
| 범위 밖 | 실시간 월드(자유 이동) 액터 복제 · 은닉 정보(PvP) · 매치메이킹(직접 IP · LAN 만, 인터넷은 호스트가 포트 개방) |
| 원칙 | 싱글플레이도 같은 세션 경로(Standalone 호스트 세션)를 탄다. 게임 규칙 · 연출 코드는 넷 모드를 모른다. 게임 인스턴스 월드에서 `PGameMaster::Submit` 은 세션만 부른다(게임 인스턴스 밖 월드 = 자체 테스트가 만든 월드는 예외) |

### 아키텍처 한 눈에

| 계층 | 호스트 (Standalone · ListenServer) | 클라 (Client) |
|---|---|---|
| 소유 | `JGGameInstance` 가 세션을 갖는다(기본 Standalone). 실행 인자 `-host[=포트] [-bind=주소]` 면 ListenServer | 실행 인자 `-join=주소[:포트]` 면 클라 세션. `-name=` 은 플레이어 이름 |
| 틱 | `JGGameInstance::Tick`: 세션 → (클라면 월드 이동) → 월드. 모듈 스케줄러가 매 프레임 부른다 | 같음 |
| 입력 | 컨트롤러(로컬 슬롯이 조작하는 행동자만) → `JGGameMasterActor::Submit`(입력 정책 Block · Buffer · Skip) → 세션 `SubmitLocal`. AI 는 호스트 세션이 구동(한 Tick 최대 64 명령) | 같은 경로. 결과 `Sent`, 한 번에 하나만 보내고 나머지는 `Queued`. 호스트 거절은 `OnLocalCommandRejected` |
| 세션 | `PGameplayHostSession`: 도착 순 줄 세우기 → 소유 검사("not your actor") → `PGameMaster::Submit` → `CommandAccepted` 방송 / `CommandRejected` 회신 | `PGameplayClientSession`: 승인을 받은 순서대로 복제본에 `Submit` → 순번 · 체크섬 비교 → 어긋나면 양쪽 JSON 덤프 · `ResyncRequest` |
| 커널 | `PGameMaster` (권한). `JGGameMasterActor` 가 BeginPlay 에서 세션에 붙이고 EndPlay 에서 뗀다 | `PGameMaster` (복제). 로컬 `Validate` 로 틀린 명령은 왕복 없이 거절 |
| 시작 | 엔트리 액터가 `IsAuthority()` 일 때 초기 상태 구성 + `JGGameMasterActor::StartGame(seed)` → 세션이 `Start` · `StartGame{시드, 지문, 초기 상태}` 방송. 세션을 거치지 않고 `PGameMaster::Start` 를 불러도 호스트 세션이 이어받는다(Playing + 들어와 있는 클라에게 문서) | 받은 초기 상태로 같은 `Start(seed)`. 규칙 지문이 다르면 스스로 종료. `StartGame` 을 부르면 false |
| 월드 이동 | `LoadWorld` 가 엔트리 액터 스폰 **전에** `NotifyTravel(월드 이름)` → `Travel` 방송(뒤따르는 `StartGame` 이 새 월드 몫이 되도록) | `Travel` 받으면 GameMaster 를 떼고(뒤 메시지 보관) 게임 인스턴스가 세션 틱 뒤 같은 이름 월드를 로드 → BeginPlay 에서 붙어 보관 메시지 적용. `Welcome` 의 월드가 지금 월드와 같고 GameMaster 가 붙어 있으면 그대로 둔다 |
| 전송 | `INetTransport` — `PNetTcpTransport` · `PNetLoopbackTransport`. 바이트만 안다, 메인 스레드 Poll | 같음 |
| 복구 | 진행 중 입장 · 재접속(같은 토큰 = 같은 슬롯) · 재동기에 `Document`(zlib 저장 문서) 송신 | `Welcome{bStarted}` 뒤 문서 → `ImportDocument` → 문서 `Sequence` 초과 승인만 적용 |
| 떠나기 · 종료 | `LeaveSession` → Standalone 으로 바꾸고 지금 월드의 GameMaster 를 다시 붙인다(시작된 게임은 이어받음). 종료 시 `Close` + 최대 2 초 송신 마무리 | 호스트가 닫으면 세션 `Closed`(월드는 남는다). 게임이 `OnClosed` 로 정한다 |

| 메시지 · 규약 | 값 |
|---|---|
| 메시지 12종 (`EGameplayNetMessage`) | Hello · Welcome · Refuse · SlotChanged · StartGame · CommandRequest · CommandAccepted · CommandRejected · ResyncRequest · Document · Travel · Ping |
| 바이트 형식 | `[종류 u8][플래그 u8][본문 JSON]`, 문서만 zlib(`[원래 크기 u32][압축]`), Ping 은 본문 없음. 월드 이름 "없음" 은 빈 문자열 |
| 핸드셰이크 | `Hello{프로토콜 버전 1, 상태 스키마, 이름, 토큰}` — 다르면 `Refuse`. 규칙 지문은 `Welcome` · `StartGame` 에 실어 클라가 비교 |
| 순번 | 상태의 `Sequence`(검증 통과 명령마다 1 증가). 세션 전용 카운터 없음 |
| 세션 상태 | `Connecting → Ready → Playing ⇄ Resyncing → Closed`. GameMaster 를 떼면 Playing → Ready. `SubmitLocal` 결과 `Rejected · Executed · PendingChoice · Sent · Queued` → 액터 결과 `Rejected · Executed · PendingChoice · Buffered · Sent` |
| 설정 (`HGameplaySessionConfig`) | `PlayerName` · `MaxPlayers`=4 · `bLocalPlayer` · `PingInterval`=1 s · `TimeoutSeconds`=10 s · `DesyncDumpDirectory`="NetDesync" |
| 실행 인자 (`JGGameInstance` 가 `GetCommandLineA` 로 읽음) | `-host[=포트]` · `-bind=주소`(기본 모든 인터페이스) · `-join=주소[:포트]` · `-name=이름`, 포트 기본 47771. `-join` 은 한 번만 접속한다(거부되면 Closed 로 남고 싱글로 바꾸지 않는다) |

## 5. 알려진 함정 / 주의사항

| 항목 | 내용 |
|---|---|
| Winsock 포함 순서 | PCH 가 `Windows.h` 를 `WIN32_LEAN_AND_MEAN` 없이 들여와 구 `winsock.h` 가 먼저 들어간다. `NetTcpTransport.cpp` 한 파일에서 Winsock 1.1 을 그대로 쓴다(`Files/2026-09-29_winsock_include_probe.txt`). 헤더에는 Winsock 을 넣지 않는다 |
| 공유 PCH 변경 금지 | 바꾸면 16 프로젝트 전체 재빌드 + 다른 세션 빌드와 충돌 |
| 2 프로세스 테스트 유지 | 한 프로세스 테스트는 문자열 테이블 · 리플렉션 목록 · 정적 변수를 공유해 기계 간 차이를 가린다. GameMaster · 세션 · 게임 인스턴스를 바꿨으면 `run_two_process.sh` 를 kernel · world 둘 다 돈다 |
| PName 직렬화 | NAME_NONE 은 문자열 테이블에서 `"(null)"` 이다. PName 을 그대로 JSON 에 쓰면 받는 쪽이 `"(null)"` 을 등록해 NAME_NONE 이 아니게 된다(Phase 5 에서 로비 입장이 빈 이름 월드로 이동하던 원인). 메시지의 이름 필드는 없음을 빈 문자열로 쓴다 |
| 세션 밖에서 시작 | 게임이 `PGameMaster::Start` 를 직접 불러도 호스트 세션이 이어받지만(Playing + 문서), 클라에서 부르면 호스트와 어긋난다. 엔트리 규약(`IsAuthority`)을 지키게 한다 |
| 바인딩 시점 | `JGGameMasterActor` 는 BeginPlay 에서 붙는다(엔트리 액터가 규칙을 다 등록한 뒤라야 클라가 보관된 `StartGame` 을 지문 일치로 적용한다). 엔트리 액터 안의 `StartGame` 은 그 자리에서 붙인다. 세션에 다른 GameMaster 가 붙어 있으면 빼앗지 않는다 |
| 월드 이동 순서 | 호스트 `LoadWorld` 는 엔트리 액터 전에 `Travel` 을 보낸다. 클라 게임 인스턴스는 세션 틱 안(메시지 처리 중)에서 월드를 바꾸지 않고 틱 뒤에 로드한다 |
| `-join` 한 번 접속 | 호스트가 아직 포트를 열지 않았으면 거부되고 Closed 로 남는다(싱글로 바꾸지 않는다 — 바꾸면 게임이 권한 쪽으로 착각해 혼자 시작한다). 시험은 호스트 로그의 `hosting on port` 를 본 뒤 클라를 띄운다(`run_net_duel.sh`) |
| 수신 주소 | `-host` 는 기본 모든 인터페이스 → Windows 방화벽 확인 창. 한 기계 시험은 `-bind=127.0.0.1`. `net.host` 는 기본 127.0.0.1 |
| TCP 정상 종료 | 받지 않은 데이터가 남은 채 `closesocket` 하면 RST. `Close` 뒤 `HasPendingSends()` 가 false 될 때까지 `Tick`(게임 인스턴스 종료는 최대 2 초) |
| 디버그 도구 abort | 디버그 빌드 JGConsole 은 CRT abort 대화상자에서 멈춘다 → 스크립트는 `timeout 400`. 숫자 인자는 예외 없는 파서만 |
| GameMaster · 액터 공유 파일 | GameMaster/ 4 파일, `Core/GameInstance.*`, `Actors/GameMasterActor.*`, `Actors/GameplayControllerActor.*`, `Core/GameFrameWorksModule.cpp` 는 GFW 트랙(· C-3)과 함께 고친다. 착수 전 `git status --porcelain -- Source/Runtime/GameFrameWorks` |
| 병렬 세션 중 작업 | 메인 트리를 스냅숏 커밋(`GIT_INDEX_FILE` 임시 인덱스 → `git add -A` → `write-tree` → `commit-tree`, 메인 인덱스 · 작업 트리 불변)으로 떠 워크트리에서 작업하면 다른 트랙 미커밋 변경을 포함한 채 격리된다. 반영은 파일별로 "메인 == 스냅숏이면 복사, 아니면 `git merge-file`" (`<scratchpad>/merge_to_main.py` 방식) |
| 스크래치 워크트리 빌드 | `%TEMP%` 아래는 MSBuild 가 헤더 의존을 추적하지 않는다(MSB8029) → 헤더를 바꾸면 `-t:Rebuild`. 새 워크트리는 PreBuild 두 번 |
| 결정론 규칙 | 규칙 코드는 상태 + 명령 외 입력 금지, 부동소수 금지, 컴포넌트 필드 전부 기본값 초기화 |
| 체크섬 값 | kernel 모드 값은 접속 순서(어느 클라가 슬롯 1)에 따라 달라질 수 있다. 세 프로세스가 같은지만 본다 |
| 런처 로그 | 두 런처가 같은 `Bin` 의 `jg_log.txt` 를 덮어쓴다 → crashwalk 표준 출력이 증거 |
| JGEditor 재컴파일 | `JGEditor/Widgets`(C-3 이관 위젯)가 `GameInstance.h` · `GameMasterActor.h` · 컨트롤러 헤더를 쓴다. 이 헤더를 바꾸면 JGEditor 도 다시 빌드 |
| 명령 위치 규칙 | 모듈의 테스트 명령은 그 모듈에(`net.test` → GFW). `net.host` / `net.join` 은 루프를 계속 돌아 에디터 콘솔에서 쓰면 에디터가 멈추므로 JGConsole |
