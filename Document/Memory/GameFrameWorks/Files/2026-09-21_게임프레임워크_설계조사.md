### 한 줄 요약
방법론은 ①상속 ②컴포넌트 오브젝트 ③노드 트리 ④ECS ⑤데이터 모델 다섯 갈래이고 상용 엔진은 전부 하이브리드(게임플레이=객체, 핫패스=데이터 지향)다. JGEngine 의 기존 자산(리플렉션·GC·모듈·에셋)은 UE 계열이라 **World/Actor/Component 뼈대 + Godot·Flax 식 Actor 트랜스폼 + 프로토타입 프리팹**이 맞물림이 가장 좋고, 조사 중 **프리팹 다형 직렬화가 이미 동작한다는 것**과 **컴포넌트 클래스 개명 시 프리팹 로드가 널 역참조로 죽는 경로**를 코드로 확인했다.

### 고도(Godot) 답 — 질문에 대한 직답
**Node + SceneTree + PackedScene.** 모든 것이 노드이고, 노드 **종류**는 상속으로(Node3D → VisualInstance3D → MeshInstance3D), 기능 **조합**은 자식 노드로 한다(컴포넌트 없음, 스크립트는 노드당 하나). 씬(`.tscn`)은 노드 서브트리 리소스이며 **씬 = 프리팹 = 레벨이 하나의 재귀 포맷**이다. 인스턴스는 바뀐 프로퍼티만 저장하고 상속 씬이 프리팹 변형 역할. 수명은 **트리 소유**(부모 free → 서브트리 파괴) + Resource 는 참조 카운트. 성능이 필요하면 **서버(RenderingServer 등) + RID 핸들**로 노드를 우회한다. ECS 미채택 이유는 Juan Linietsky 가 2021 년 글로 공식화했다(사용성 우선, 성능은 서버 계층에서).

### 새로 확인한 사실 (모델 교체 후 증분. 이게 이 조사의 실질 수확)

1. **프리팹의 핵심 기계가 이미 있다.** `PJsonData::makeJsonValue(const PSharedPtr<T>&)`(`Json.h:695`)가 `[JGType, 객체데이터]` **2원소 배열로 타입을 함께 저장**하고, `readJsonValue(PSharedPtr<T>*)`(`Json.h:1416`)가 그 타입으로 `getJGObject` → `StaticClass` → `AllocateByClass` 하여 **구체 파생 클래스를 복원**한다. `HList<T>`(`Json.h:650`, `1316`)가 원소마다 위임. 선례로 `Source/Runtime/GUI/Widget.h:44` 의 `JGPROPERTY() HList<PSharedPtr<JGWidgetComponent>>` 가 이미 있고 생성 코드도 확인(`Temp/CodeGen/GUI/Widget.generation.h:19,40`).
   → **"Actor 서브트리 = 컴포넌트·자식 목록" 의 JSON 왕복에 새 직렬화기를 만들 필요가 없다.** 남는 건 델타(오버라이드) 비교와 오브젝트 간 참조(GUID) 해석 둘뿐.

2. **확정 크래시 경로(문서 §5-4-9).** 컴포넌트 클래스를 삭제·개명하거나 모듈 미로드 상태로 프리팹을 읽으면:
   `Json.cpp:48` `getJGObject` 가 미등록 시 **실패가 아니라** `Allocate<JGObject>()` 반환 → `Json.h:1449` `Cast<T>` 실패로 빈 `PSharedPtr` → **빈 rhs 대입이 no-op 인 기존 버그**(메모리 분석 §4-2)로 `*value` 미갱신 → `Json.h:1450` `value->GetRawPointer()` 널 역참조.
   부수로 `Json.h:1425` `if (value == nullptr && _value.IsArray() == false)` 는 `&&` 가 `||` 자리에 있다.
   → **메모리 단계 A-2(`PSharedPtr` 대입 수정)는 선택이 아니라 프리팹의 선행 조건.** 프레임워크 개발 중 클래스 개명은 상시로 일어난다.

3. **`HTransform` 이 없다.** `Core/Math` 에 `HMatrix`(`Matrix.h:10`)·`HVector*`·`HQuaternion`·`HBBox`·`HFrustum`·`HPlane`·`HRay`·`HRect`·`HColor` 는 있으나 위치/회전/스케일 묶음 타입이 없다. `IJsonable` 파생 구조체로 만들어야 한다(`HStaticSubMesh` 가 선례).

4. **`GameFrameWorks` 가 StaticLib** 이다(`GameFrameWorks.module.json`). 게임 모듈(SharedLib)이 Actor 를 파생·등록하려면 **SharedLib + `GAMEFRAMEWORKS_API`** 전환과 `module_system_info.json` 코드젠 대상 등록이 필요하다.

문헌 검증 4건(웹): Flax 는 **TransformComponent 없이 Actor 가 트랜스폼을 직접 보유**(제안의 핵심 근거), Defold 는 `socket:path#fragment` 주소 기반 메시지 패싱, Unity 프리팹 인스턴스는 `m_SourcePrefab` + `m_Modifications` 로 델타 저장, UE 5.4 증분 도달성 분석은 실험적.

### 제안 (문서 §5-2. 결정은 사용자)
뼈대 **A안 = World / Level / Actor / Component**. ① Actor 가 트랜스폼·부모자식 직접 보유(컴포넌트는 트랜스폼 없음 — Flax·Godot 식) ② 소유는 `PSharedPtr`, 역참조는 전부 `PWeakPtr`, 파괴는 `Destroy()` 명시 전파(GC 순서에 기대지 않음) ③ 프리팹 = `JGAsset` 파생 서브트리 JSON + 인스턴스 델타(프로토타입 기반. CDO 없음) ④ 틱은 World 가 그룹별 목록 관리(스케줄러 태스크 금지 — Unschedule 부재) ⑤ 통신은 `HDelegate` 우선 ⑥ 핫패스(렌더·물리)는 Graphics 가 발급한 **세대 핸들**, `PSharedPtr` 소유 금지 ⑦ 저작=런타임으로 시작.

B안(Godot 노드 트리)을 배제한 이유는 스크립팅 언어가 없어 조합이 C++ 단일 상속에 갇히기 때문. C안(ECS)은 리플렉션·GC·모듈이라는 기지불 비용을 버리고 저작 도구를 새로 세워야 해서 1인 개발 범위를 넘는다. 대량 오브젝트 성능은 핫패스 컴포넌트 매니저로 얻는다(Godot 서버 논리).
