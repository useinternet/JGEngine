### 2.2 제안 설계

| 항목 | 제안 |
|---|---|
| API | `struct HGameUIRenderTransform { float32 Angle(도, 화면 기준 시계 방향); HVector2 Scale = (1,1); HVector2 Translation(논리 단위); }`, `SetRenderTransform` · `GetRenderTransform` · `ClearRenderTransform`, `SetOpacity(0~1)` · `GetOpacity`. 기준점 = 요소 피벗(배치 사각형 안 `Pivot` 자리) — 요청서 그대로. 옮기기는 요청서에 없지만 같이 둔다(날아오는 카드를 배치를 다시 짜지 않고 움직임, 판정도 따라감) |
| 그리기 | 요소가 그리기 목록에 넣는 모든 사각형이 지금 변환(부모 × 자식, 렌더 타깃 픽셀의 2x3 행렬)을 거친다 — `HGameUIDrawContext` 에 변환 · 투명도를 두고 `buildDraw` 가 자식으로 내려가며 곱한다. 그림 · 버튼 · 입력란 · 글자 코드는 거의 그대로(사각형 → 네 꼭짓점). 투명도는 정점 알파에 곱한다 |
| 글자 선명도 | 글자는 화면 배율 × 변환 배율(가로 · 세로 배율의 기하 평균)의 정수 픽셀 크기로 래스터화하고, 남는 차이만 사각형으로 맞춘다 → 1.3배여도 흐리지 않다. 정수 픽셀 크기라 배율 애니메이션(1.0 → 1.3)에서도 크기가 몇 단계뿐이라 아틀라스가 넘치지 않는다(GG-11 LRU). 변환이 있으면 정수 픽셀 맞춤(펜 위치 반올림)은 하지 않는다 |
| 판정 | 포인터를 요소마다 역변환해 그 요소 · 자식을 지금처럼 축 정렬 사각형으로 판정한다(돌린 카드는 돌린 모양 안에서만 맞음). 투명도는 판정에 영향 없음(사라지는 카드는 게임이 입력 받기를 끈다) |
| 잘라내기 | 시저는 축 정렬이라, 돌린 요소 안의 잘라내기(`SetClip` · 입력란 여백)는 돌린 사각형을 감싸는 축 정렬 사각형으로 자른다(조금 넓게 잘림). 정확한 회전 잘라내기(스텐실 · 셰이더)는 보류 |
| 바뀌는 파일 | `UI/GameUIElement.h/.cpp`(변환 · 투명도 · 그리기 · 판정), `GameUIDrawList.h/.cpp`(변환 거친 사각형), `GameUIText.cpp`(래스터 크기 · 맞춤), `GameUIImage` · `GameUIButton` · `GameUITextInput`(필요하면 작은 수정), `GameUISelfTest.cpp`. Graphics 변경 없음 |

## 3. ER-015 끌어다 놓기

### 3.1 사실 확인

| 요청서 | 코드 | 맞나 |
|---|---|---|
| 이동은 호버만 바꿈 `GameUIManager.cpp:407-411` | `HandlePointer` `Move` → `setHovered(hit)` 뿐 | 맞음 |
| 요소 콜백 들어옴 · 나감 · 누름 · 뗌, 캡처 있음 `GameUIElement.h:82-86` · `GameUIManager.cpp:412-432` | `onPointerEnter/Leave/Down/Up(bInside)`, `_captured`(누른 요소가 뗌을 받음) | 맞음 |
| 위치 묻기 없음(`GetHoveredElement` 만) `GameUIManager.h:120` | 맞음 | 맞음 |
| 에디터 뷰포트 | `SceneViewport.cpp` `forwardPointerToGameUI`: 버튼을 누른 동안은 이미지 밖에서도 `Move` 를 보내고, 떼면 밖에서도 `Up`. 누르지 않고 밖으로 나가면 `Leave` | 확인 — 끌기 중 밖으로 나가도 위치가 계속 온다 |

### 3.2 제안 설계

| 항목 | 제안 |
|---|---|
| 포인터 상태 | 관리자 `GetPointerPosition()`(논리 단위, 마지막 포인터 이벤트) · `IsPointerDown(button)` · `IsPointerInside()`(`Leave` 뒤 false) |
| 끌기 켜기 | 요소 `SetDraggable(true)`. 켠 요소(또는 그 자식을 누른 경우 가장 가까운 끌 수 있는 조상)만 끌기가 된다 — 버튼 같은 나머지 요소는 손떨림에도 지금처럼 클릭 |
| 시작 · 이동 · 끝 | 누른 자리에서 문턱(`SetDragThreshold`, 기본 6 논리 단위)을 넘게 움직이면 시작. 그 뒤 이동마다 위치, 떼면 끝. 끝에는 놓은 곳 = 끄는 요소와 그 자식을 뺀 맨 위 입력 받는 요소(없으면 nullptr). 이동 때도 그 아래 대상을 같이 준다(놓을 곳 강조). 끌기가 시작되면 그 누름은 클릭이 아니다(뗌 `bInside` = false) |
| 받는 쪽 | 관리자 이벤트 `OnDragBegin(요소, 위치)` · `OnDragMove(요소, 위치, 아래 대상)` · `OnDragEnd(요소, 위치, 놓은 곳, bCanceled)` — 게임 위젯이 한 번 구독하고 요소로 가린다(요소마다 대리자를 두지 않음). 파생 요소용 가상 훅 `onDragBegin/Move/End` 도 같은 때 부른다 |
| 움직이기 | 엔진은 끄는 요소를 옮기지 않는다 — 게임이 이동 이벤트에서 위치(또는 ER-014 의 옮기기)를 바꾼다. 다른 놓기 규칙(놓을 수 있는 곳 · 되돌아가기 애니메이션)은 게임 몫 |
| 취소 | 위젯 스택이 바뀌어(메뉴가 열림 · 끄는 요소가 빠짐) 끄는 요소를 더 쓸 수 없으면 `OnDragEnd(bCanceled = true)`. `CancelDrag()` 도 둔다(창 포커스를 잃어 뗌이 안 오는 경우를 호스트가 정리) |
| 에디터 뷰포트 (d) | 지금 전달 방식 그대로 — 누른 채 이미지 밖으로 나가도 위치가 오고, 밖에서 떼면 끝(놓은 곳 nullptr). 게임 호스트에서는 GP-C1 의 마우스 캡처가 같은 일을 한다 |
| 바뀌는 파일 | `UI/GameUIManager.h/.cpp`(포인터 상태 · 끌기 상태 · 이벤트 · 빼고 판정), `GameUIElement.h/.cpp`(`SetDraggable` · 훅), `GameUISelfTest.cpp`. GP-F1(GameFrameWorks 세션)이 `GameUIManager` 입력 진입점을 고칠 수 있어 착수 전에 알린다 |

### 3.3 검증 계획

| # | 내용 |
