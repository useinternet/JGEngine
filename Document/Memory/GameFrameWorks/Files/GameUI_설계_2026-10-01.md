# GameUI 설계 — GameFrameWorks 안의 JGGameWidget (CommonUI식) — 2026-10-01

사용자 지시(10-01 아침): "GameUI를 모듈로 따로 떼는 게 아니고 GameFrameWork 모듈 안에 있는 거고, JGWidget처럼 JGGameWidget을 이용해서 하고 싶어. 언리얼의 CommonUI처럼."
이어서 사용자가 고른 것: 작성 방식 **유지형(CommonUI식)**, 범위 **이전 + CommonUI 핵심**(포커스 이동 · 탭 · 게임패드는 다음).
이 문서는 `Etc/Files/GameGUI_설계_2026-09-30.md`(별도 `GameGUI` 모듈안)를 대체한다. 기반(2D 그리기 경로 · 글꼴 · 이미지 · 포인터 입력)과 요소 코드는 그대로 옮겨 쓴다.
기준: 엔진 기반만(지침서 §1), 과설계 금지(§5).

## 0. 결론

| 항목 | 결정 |
|---|---|
| 위치 | `Source/Runtime/GameFrameWorks/UI/`. 별도 `GameGUI` 모듈은 없앤다. GFW 의존(Core · Asset · Graphics)은 그대로 |
| 화면 단위 | `JGGameWidget`(JGCLASS) = 화면 하나(HUD, 메뉴, 대화상자). CommonUI 의 ActivatableWidget 자리. 게임은 상속해서 쓴다(JGWidget 처럼) |
| 작성 방식 | 유지형. `OnInitialize` 에서 요소 트리(이미지 · 글자 · 버튼)를 한 번 만들고, 이후에는 값만 바꾼다. 엔진이 매 프레임 트리를 그리고 입력을 판정한다 |
| 관리자 | `PGameUIManager` — `JGGameInstance` 가 가진다(`JGGameInstance::Get().GetUI()`). 월드를 바꿔도 유지된다(Lyra 의 GameInstance 단위 UI 관리자와 같은 자리) |
| 레이어 · 스택 | 레이어 4개 `Game < GameMenu < Menu < Modal`, 레이어마다 스택. Push 하면 새 위젯이 활성이 되고 같은 스택의 이전 위젯은 비활성(안 보임). 빠지면 이전 위젯이 다시 활성 |
| 입력 라우팅 | 위 레이어부터. 각 레이어의 맨 위 위젯이 판정 기회를 얻는다. 입력 모드 `Menu` 위젯을 만나면 거기서 멈춘다(아래 레이어 · 월드는 입력을 못 받는다). 입력 모드 `Game`(HUD)은 UI 위만 받고 나머지는 아래로 |
| 뒤로가기 | `HandleBackAction` → 위 레이어부터 첫 "뒤로가기 처리" 위젯의 `OnBackAction`(기본: 자기를 닫음). 호스트는 Esc 를 여기에 넘긴다 |
| 스타일 | `HGameUITextStyle`(글꼴 · 크기 · 색), `HGameUIButtonStyle`(보통 · 호버 · 누름 · 비활성 색, 배경 텍스처, 라벨 스타일). 관리자 기본 스타일을 두고, 요소는 정하지 않은 값을 기본에서 받는다(CommonUI 의 스타일 클래스 자리) |
| 공통 버튼 | `PGameUIButton`: 스타일, 비활성(`SetEnabled(false)` — 클릭 안 됨, 월드 입력은 막음), `OnClicked` |
| 호스트 | 에디터 Scene Viewport(JGEditor): 월드 렌더 뒤 `Render`, 포인터는 `HandlePointer` 먼저(받으면 피킹 · 궤도 · 줌 안 함), Esc → `HandleBackAction` |
| 그대로 두는 것 | Graphics 2D 그리기 경로(`IJGGraphicsCommand::Draw(H2DDrawArguments)`, `draw2d.hlsl`) — 렌더링 기반이라 Graphics 소유. ImGui(GUI 모듈)는 에디터 · 도구 전용 |

## 1. 사용 모습

```cpp
JGCLASS()
class JGMyHUD : public JGGameWidget                    // Game 레이어, 입력 모드 Game(기본)
{
    JG_GENERATED_CLASS_BODY
    PSharedPtr<PGameUIText> _turnText;
protected:
    virtual void OnInitialize() override                 // 처음 한 번: 트리 구성
    {
        _turnText = AddChild<PGameUIText>(PName("Turn"));
        PSharedPtr<PGameUIButton> menu = AddChild<PGameUIButton>(PName("Menu"));
        menu->OnClicked.AddLambda([]()
        {
            JGGameInstance::Get().GetUI()->PushWidget<JGPauseMenu>(EGameUILayer::Menu);
        });
    }
public:
    void SetTurn(int32 turn);                            // 게임 이벤트에서 부른다
};

JGCLASS()
class JGPauseMenu : public JGGameWidget                 // Menu 레이어: 월드 입력 차단, Esc 로 닫힘
{
    JG_GENERATED_CLASS_BODY
protected:
    virtual void OnInitialize() override
    {
        SetInputMode(EGameWidgetInputMode::Menu);
        SetBackHandler(true);
        PSharedPtr<PGameUIButton> resume = AddChild<PGameUIButton>(PName("Resume"));
        resume->OnClicked.AddLambda([this]() { DeactivateWidget(); });
    }
};

// 게임 모듈: GFW 연결 · 월드 로드 뒤
PSharedPtr<JGMyHUD> hud = JGGameInstance::Get().GetUI()->PushWidget<JGMyHUD>(EGameUILayer::Game);
```

## 2. 수명과 활성

| 훅 | 언제 |
|---|---|
| `OnInitialize` | 처음 스택에 올라갈 때 한 번. 요소 트리를 만든다 |
| `OnActivated` | 스택 맨 위가 될 때(Push 직후, 위 위젯이 빠졌을 때) |
| `OnDeactivated` | 위에 다른 위젯이 올라오거나 자기가 빠질 때 |
| `OnUpdate(dt)` | 활성인 동안 매 프레임(`JGGameInstance::Tick`, 월드 틱 뒤). 값을 끌어와 갱신할 때만 쓴다 |
| `OnBackAction` | 뒤로가기를 받았을 때(뒤로가기 처리 위젯만). 기본은 `DeactivateWidget()` 후 true |
| `OnShutdown` | 스택에서 빠진 뒤. 그 뒤 트리를 비운다 — 같은 객체를 다시 Push 하면 `OnInitialize` 부터 다시 |

- `PushWidget<T>(layer)` 는 매번 새 객체를 만든다(템플릿 — 게임 DLL 에서 인스턴스화, JGWidget `OpenWidget<T>` 와 같은 방식). 리플렉션용 `PushWidgetByClass(JGClass, layer)` 도 둔다.
- `DeactivateWidget()`(위젯) = `RemoveWidget(widget)`(관리자). 맨 위가 아니어도 빠질 수 있다(이미 비활성이라 `OnDeactivated` 없이 `OnShutdown`).
- 스택이 바뀌면 포인터 상태(호버 · 캡처)를 푼다. 버튼 `OnClicked` 안에서 Push · 닫기를 해도 된다(입력 전달은 스냅숏으로 돈다).

## 3. 그리기와 입력

| 항목 | 규칙 |
|---|---|
| 좌표 | 관리자 기준 해상도(기본 1920×1080, `SetReferenceSize`). 배율 `min(타깃/기준)`, 요소 사각형 = `부모.min + Anchor×부모.size + Position − Pivot×Size`. 위젯 루트가 논리 화면 전체 |
| 그리기 | 레이어 아래부터, 각 레이어의 맨 위 위젯만(스택 아래 위젯은 안 보임). 한 그리기 목록 · 한 번의 2D 그리기 |
| 판정 | 입력 위젯 목록 = 위 레이어부터 각 레이어 맨 위 위젯, `Menu` 위젯에서 멈춤. 그 순서로 요소 트리 판정(자식 역순 → 자신) |
| Move | 호버 갱신. 받음 = 요소 위 · 캡처 중 · `Menu` 위젯 있음 |
| Down | 맞은 요소에 전달, 캡처. 받음 = 맞음 또는 `Menu` 위젯 있음(빈 곳 클릭도 월드로 안 감) |
| Up | 캡처한 요소에(안/밖 여부와 함께). 받음 = 캡처 · 맞음 · `Menu` |
| Wheel | 받음 = 요소 위 또는 `Menu` |
| 비활성 요소 | 판정은 되지만(아래 · 월드를 막음) 이벤트를 무시한다. 비활성 부모 아래 자식은 판정에서 부모로 바뀐다(부모 하나로 손패 전체를 끄기) |

## 4. 스타일

| 타입 | 필드 | 규칙 |
|---|---|---|
| `HGameUITextStyle` | Font(nullptr = 기본) · FontSize · Color | `PGameUIText` 는 필드별로 덮어쓴다: 정하지 않은 필드는 관리자 기본 글자 스타일에서 받는다 |
| `HGameUIButtonStyle` | Texture · Normal · Hovered · Pressed · Disabled · Label(글자 스타일) · DisabledLabelColor | 버튼은 `SetStyle` 이 없으면 관리자 기본 버튼 스타일 전체를 쓴다(CommonUI: 버튼마다 스타일 클래스, 없으면 기본) |
| 글꼴 해석 | 요소 → 관리자 기본 글자 스타일 → 관리자 기본 글꼴(엔진 Content `Fonts/GameUIDefault.ttf` → 시스템 맑은 고딕 → Arial, 개발용) | 시스템 글꼴은 배포 금지 |

## 7. 구현 결과 (2026-10-01 오전, 미커밋)

설계대로 구현했고 V1 · V2 · V3 를 통과했다(워크트리 · 메인 트리 둘 다). 원문 `2026-10-01_GameUI_GFW_verify.txt`(이 폴더), 현황 `../현황.md` §10, TODO `../TODO_GameUI.md` GG-7.
- 훅 순서는 CommonUI 와 같다: Push = 새 위젯 `OnInitialize` → 이전 맨 위 `OnDeactivated` → 새 위젯 `OnActivated`. 빼기 = `OnDeactivated` → `OnShutdown` → 아래 위젯 `OnActivated`.
- 메뉴가 떠도 다른 레이어의 HUD 는 활성으로 남는다(입력만 Menu 위젯이 막는다). 같은 스택의 아래 위젯만 비활성 · 안 보임.
- 검증 스크립트는 화면 위치를 렌더 타깃 비율로 역산해야 작은 버튼을 맞춘다(첫 실행에서 버튼 높이로 역산해 Menu 를 빗나감).
