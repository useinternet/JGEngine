### 3.1 트윈이 사는 곳 — 게임 UI 안 vs GFW 공용

| 안 | 내용 | 일수 | 판단 |
|---|---|---|---|
| (1) 게임 UI 안(권고) | `UI/GameUITween` — 대상은 UI 요소 속성, 위젯이 가지고 게임 UI 관리자 `Update` 가 돌린다(위젯이 덮이면 멈춤 · 빠지면 취소가 자연스럽다) | 1.5~2일 | 요청서 사용처가 모두 게임 UI 다(손패 · 덮개 · 판 화면 토큰 · 숫자 — ProjectAH 판도 UI 화면). 월드 쪽 요구는 아직 없다 |
| (2) GFW 공용 | 이징 · 묶음 · 시간 진행을 GFW 공용으로 두고, UI 요소와 월드 액터 · 컴포넌트(3D 말 · 카메라)가 각각 대상 속성을 붙인다. 돌리는 곳이 둘(UI 관리자 · 월드 틱)이 되고 멈춤 · 취소 규칙도 둘 | (1) + 0.5~1일, GameFrameWorks 세션과 같이 | 월드 쪽 움직임 요구가 생기면 그때. (1)에서 이징 함수 · 묶음 단계는 UI 타입에 기대지 않게 써 두어 옮기는 비용을 작게 한다 |

### 3.2 GFW 2-4 시퀀서 · 연출 큐(`JGGameplayCue`)와의 관계

| 항목 | 내용 |
|---|---|
| 겹치지 않는다 | 연출 큐는 "게임 사건 하나를 재생"(사건 단위 `Begin` · `Tick` · `IsDone` · `Skip`, 시간 곡선 없음), 트윈은 "UI 값 하나를 시간에 따라"(곡선 · 묶음). 층이 다르다 |
| 이어 쓰는 법 | 큐가 UI 묶음을 쓰면 된다: `Begin` 에서 묶음 시작 → `IsDone` = 묶음이 끝났나 → `Skip` = 묶음 끝으로 건너뛰기(끝값 · 남은 함수 부르기 — 큐 `Skip` 의 "최종 상태로 즉시"와 같은 뜻). 큐 코드는 바꾸지 않는다 |
| 2-4(미착수)에 주는 것 | 시퀀서의 묶음 병렬 재생 · 페이싱 · 스킵 키가 UI 연출에도 그대로 닿는다(큐 단위). 2-4 를 시작할 때 "UI 묶음을 기다리는 큐" 도우미가 필요하면 그때 GFW 세션이 둔다 |
| 보류 GG-H6 | 다시 볼 조건이 "2-4 착수 때"였지만 게임 쪽 결정(Q-003 · Q-009)으로 트윈 부분만 앞당긴다. 위젯 전환은 GG-H6 에 남긴다 |
