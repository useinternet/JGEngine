## 2. ER-010 글 서식

### 2.1 판단

범용 기능이고 엔진 몫이다. 게임이 요소를 쪼개 흉내 내면(구간마다 요소 하나) 줄바꿈 · 측정 · 말줄임이 모두 깨진다 — 요청서도 그 우회를 쓰지 않겠다고 했다. 수락 권고.

### 2.2 제안 설계

| 항목 | 제안 |
|---|---|
| 문단 서식 | `PGameUIText` 에 `HGameUIParagraphStyle { LineHeight(논리 단위, 0 = 글꼴 기본), LetterSpacing(1/1000 em, 음수 가능), HorizontalScale(1.0 = 100%), ParagraphSpacing('\n' 다음 문단 앞에 더함), bBold, bItalic }`. 글꼴 · 크기 · 색(`HGameUITextStyle`)은 그대로 둔다 — 버튼 라벨 · 입력란은 바뀌지 않는다 |
| 양쪽 맞춤 | `EGameUIHorizontalAlign::Justify`. 자동으로 바뀐 줄만 폭에 맞춰 편다(문단 마지막 줄 · '\n' 앞 줄 · 말줄임 줄은 왼쪽). 남는 폭을 글자 사이에 나누되 띄어쓰기 자리에 더 준다(무게 예: 띄어쓰기 4 : 글자 사이 1) → 띄어쓰기가 적은 한글 줄도 고르게 펴진다 |
| 줄 간격 기준 | 줄 높이 = `LineHeight`, 기준선은 줄 상자 안에서 남는 높이의 절반을 위에 둔다(CSS half-leading). 기준선 사이 거리 = `LineHeight` |
| 구간 서식 | **글 안 표시(마크업)** 권고 — `SetRichText(true)` 일 때만 읽는다: `<b>…</b>` · `<i>…</i>` · `<color=#RRGGBB(AA)>…</color>` · `<hscale=140>…</hscale>`(장평 %), 겹쳐 쓸 수 있다. 글자 그대로의 `<` · `&` 는 `&lt;` · `&amp;`. 모르는 태그는 글자 그대로 그린다(글이 조용히 사라지지 않게). `SetText` 때 한 번 읽어 구간 목록으로 둔다. 게임은 자기 표시(`<b>` · `[[특성]]` 등)를 이 태그로 바꿔 넣는다. (구간 배열 API 를 따로 열지는 않는다 — 내부 구조) |
| 가짜 굵게 | 래스터화한 커버리지를 넓힌다(글리프 그림의 최댓값 필터, 두께 ≈ 픽셀 크기의 1/24, 최소 1px). 굵은 글리프는 아틀라스에 따로 둔다(글리프 키에 굵게 비트). 글자 폭도 그만큼 는다. 글꼴에 굵은 면이 있어도 1차는 합성만(구간 글꼴 바꾸기가 들어오면 그때 진짜 굵은 글꼴) |
| 가짜 기울임 | 글리프 사각형을 기준선 기준으로 약 12° 비튼다(위쪽을 오른쪽으로, 래스터화는 같음). 그리기 목록에 네 꼭짓점 사각형 추가. 글자 폭은 그대로 |
| 장평 | 가로 배율로 래스터화(`scale_x = scale × 장평`) → 늘인 그림이 아니라 선명하다. 글리프 키에 장평(1% 단위). 글자 폭 · 자간 · 자간 보정(kerning)에도 곱한다 |
| 배치 · 측정 | `PGameUIFont::LayoutText` 가 구간 서식 · 문단 서식을 받아, 줄마다 글자 자리(x)까지 계산한 결과를 낸다. 그리기 · `MeasureContent` · 말줄임 · 최대 줄 수가 같은 결과를 쓴다(높이 = 줄 높이 합 + 문단 간격). 지금 함수(서식 없음)는 그대로 둔다(버튼 · 입력란) |
| 바뀌는 파일 | `UI/GameUIDefines.h`(Justify), `GameUIStyle.h`(문단 서식), `GameUIFont.h/.cpp`(배치 · 변형 래스터화 · 글리프 키), `GameUIText.h/.cpp`(서식 · 마크업 · 그리기), `GameUIDrawList.h/.cpp`(네 꼭짓점 사각형), `GameUISelfTest.cpp`. 다른 트랙 파일 없음 |

### 2.3 범위 밖 · 주의

| 항목 | 내용 |
|---|---|
| 구간 글꼴 바꾸기 · 진짜 굵은/기울임 글꼴 | "있으면 좋음". 요청의 글꼴은 모두 Regular 한 벌이라 합성으로 충분하다. 보류 표로 |
| 글 사이 그림(아이콘 이미지) | 요청서가 필요 없다고 했다(아이콘은 본문 글꼴의 글자). GG-H3 에 남긴다 |
| 입력란 · 버튼 | 문단 · 구간 서식은 글자 요소만. 입력란(GG-9)의 커서 계산은 지금 그대로 |
| 성능 | 마크업은 `SetText` 때 한 번만 읽는다. 배치는 지금처럼 그릴 때마다(수백 자 문제없음). 느려지면 GG-H18(배치 캐시) |
| 아틀라스 | 굵게 · 장평 변형마다 글리프가 따로 쌓인다 → ER-011 과 같이 가야 안전하다 |
| 기울임 넘침 | 비튼 글자는 오른쪽으로 조금 나간다 — `SetClip(true)` 인 요소의 오른쪽 끝 글자는 그만큼 잘릴 수 있다 |

## 3. ER-011 글꼴 아틀라스 용량

### 3.1 판단

범용 문제다(글자 수가 많은 언어 · 크기가 바뀌는 UI). 지금은 차면 그 뒤 새 글자가 영영 빈칸이고 게임이 고칠 방법이 없다. 수락 권고. ER-010 이 변형 글리프를 늘리므로 바로 뒤에 넣는다.

### 3.2 제안 설계

| 항목 | 제안 |
|---|---|
| 페이지 | 한 장(1024² RGBA8, 4MB)이 차면 새 장을 연다. 글리프는 자기 페이지 번호를 가진다. 그리기 배치 = (글꼴, 페이지). GPU 텍스처는 페이지마다, 바뀐 페이지만 다시 만든다(지금은 한 장 전체를 매번 다시 올림 → 조금 나아짐) |
| 상한 · 비우기 | 기본 상한 4장(16MB, `SetAtlasPageLimit`). 상한에 닿으면 **이번 프레임에 쓰지 않은 페이지 중 가장 오래 안 쓴 것**을 비우고 다시 채운다(페이지 단위 LRU). 이번 프레임에 쓴 페이지는 비우지 않는다 → 이미 그리기 목록에 들어간 글자가 깨지지 않는다. 한 프레임에 상한보다 많이 필요하면 상한을 잠시 넘기고 경고 한 번 |
| API | `ClearGlyphs()`(전부 비움 — 화면을 크게 바꿀 때), `GetAtlasPageCount()` · 사용률(확인용) |
| 글꼴 대체 (같이 권고) | `PGameUIFont::SetFallbackFont(font)` 사슬. 글리프가 없는 글자는 대체 글꼴의 폭 · 글리프 · 아틀라스로 그린다(배치 · 측정도 같이). 요청 예: 이름 글꼴에 없는 `ô` |
| 바뀌는 파일 | `UI/GameUIFont.h/.cpp`, `GameUIDrawList.h/.cpp`(배치에 페이지), `GameUIRenderer.cpp`(페이지 텍스처), `GameUIText.cpp`(글리프 그리기), `GameUISelfTest.cpp` |

### 3.3 범위 밖 · 주의

| 항목 | 내용 |
|---|---|
| 부분 갱신(바뀐 사각형만 올리기) | Graphics 에 텍스처 부분 갱신 API 가 없다 → 페이지 단위 다시 만들기까지. 부분 갱신은 Graphics 기능이 생기면(GG-H4 에 남김) |
| 1채널(R8) 아틀라스 | 메모리 1/4 이지만 2D 셰이더 · SRV 채널 매핑이 바뀐다(Graphics) → 나중 |
| 비우기 순간 | 비운 페이지의 글자는 다음에 쓸 때 다시 래스터화된다(그 프레임에 조금 느릴 수 있음) |

### 3.4 검증 계획

| # | 내용 |
|---|---|
| 헤드리스 | 서로 다른 한글 1,000자 × 12 · 16 · 20 · 24 · 32px(약 2.5장)를 모두 래스터화 → 빈칸 0 · 경고 0 · 페이지 3장, 상한 2장으로 줄이면 오래된 페이지가 비워지고 이번 프레임 글자는 남음, `ClearGlyphs` 뒤 0, 대체 글꼴로 없는 글자를 그림 · 폭이 대체 글꼴 값 |
