## 2. ER-012 작은 글자 합성 굵게

### 2.1 사실 확인 (요청서 "엔진 현황" ↔ 코드)

| 요청서 | 코드 | 맞나 |
|---|---|---|
| 반지름 `max(1, (int)(pixelSize × BoldStrength × 0.5 + 0.5))` — 72px 미만은 늘 1 | `UI/GameUIFont.cpp:344`. pixelSize/48 을 반올림 → 24px 미만 0 → max 로 1, 24~71px 도 1, 72px 부터 2 | 맞음 |
| 가로 · 세로 (2r+1) 최댓값 필터 → 획 +2r | `dilateCoverage` `:119` (분리형 최댓값, 결과 (w+2r)×(h+2r)) | 맞음 |
| 폭 + em/24 — 11px 에서 +0.46px, 그림은 +2px | 글리프 `:331`, 측정 `MeasureStyledAdvance` `:488`(요청서 486) | 맞음(행 2줄 차이) |
| 증거: "전투." "강제" "폭로" 덩어리, "물품. 무기. 총." 읽기 어려움 | `ER-012_bold_small.png` — 굵은 글자만 속이 막힘 | 맞음 |

### 2.2 제안 설계

| 항목 | 제안 |
|---|---|
| 넓히기 양 | 한쪽 반지름 r = pixelSize × BoldStrength / 2(실수). 양쪽 합 2r = em/24 = 폭 증가(Advance)와 같다 → 이웃과 겹치지 않는다(완료 기준 b) |
| 부분 픽셀 | r = 정수부 n + 소수부 f. 가로 · 세로 분리형 최댓값 필터에서 거리 ≤ n 은 그대로, 거리 n+1 칸은 이웃 커버리지 × f 로 넣는다(가장자리 한 겹을 f 만큼 진하게). 11px: r = 0.23 → 가장자리만 23% — 속 빈 곳은 그대로(완료 기준 a). 72px 이상은 지금과 거의 같다 |
| 비트맵 상자 | 사방 ceil(r) 넓힘(지금처럼 OffsetX/Y −= ceil(r)) |
| 가로로만(있으면 좋음) | 넣지 않는다 — 부분 픽셀이면 세로 증가도 0.23px 라 한글 받침 · 모음 사이가 막히지 않는다. 그래도 모자라면 보류(GG-H25 와 함께) |
| 바뀌는 파일 | `UI/GameUIFont.cpp`(반지름 · `dilateCoverage`), `GameUISelfTest.cpp`. API · 헤더 변경 없음 |

다른 방법(고르지 않음): 크게 래스터화한 뒤 줄이기 — 아틀라스 · 래스터 비용이 크다. 가로 겹쳐 찍기(GDI 식) — 세로 획만 굵어져 큰 글자 모양이 지금과 달라진다.

### 2.3 검증 계획

| # | 내용 |

## 3. ER-013 에디터 씬 뷰포트 해상도

### 3.1 사실 확인

| 요청서 | 코드 · 측정 | 맞나 |
|---|---|---|
| 1280x720 고정, 이유 = 창 크기마다 G버퍼를 다시 만들지 않으려고 | `Source/Editor/JGEditor/Widgets/SceneViewport.cpp:18-20`(주석 · 상수), `:38` `Initialize(…, 1280, 720)`. 보이는 이미지는 비율을 지켜 창에 맞춤(최소 640x360) | 맞음 |
| 게임 UI 배율 = 대상 크기 / 1920x1080 → 0.667 | `UI/GameUIManager.cpp:288-291`(min(가로비, 세로비)), 대상 = `GetDisplayTexture()`(1280x720) | 맞음 |
| DPI 인식 호출 없음, OS 가 늘리는지 확인 필요 | 엔진 코드 · 프로젝트 설정(lua · vcxproj)에 DPI 인식 없음, ImGui 도우미 `ImGui_ImplWin32_EnableDpiAwareness` 는 부르지 않음. **실행 확인(10-02, 이 PC): `GetProcessDpiAwareness(런처) = 0`(인식 안 함), 런처 창 DPI 96, 화면이 1707x1067 로 보임(실제 2560x1600, 150%)** → Windows 가 창 전체를 1.5배 늘려 그린다 | 맞음 + 확인됨 |
| 보류 항목 | JGEditor `TODO_JGEditor.md` E-H1 "씬 뷰포트 렌더 해상도 1280x720 고정" — 다시 볼 조건 "창을 크게 써서 흐림이 문제될 때" | 조건이 왔다 |

흐림의 두 단계: (1) 1280x720 → 보이는 이미지(약 1690x950 논리 픽셀)로 1.32배 늘림(ImGui 이미지), (2) DPI 인식이 없어 창 전체를 1.5배 늘림(Windows). 합쳐 약 2배. ① 만 고치면 (1)이 없어지지만 (2)는 남아 150% 화면에서는 여전히 흐리다.

### 3.2 제안 설계

| 항목 | 제안 |
|---|---|
| ① 렌더 해상도 | 뷰포트가 보이는 이미지 크기(픽셀, 16:9 유지 — 지금 맞춤 규칙 그대로)를 원하는 크기로 두고, 지금 크기와 다르면 크기 변경이 멈춘 뒤(예: 0.3초 그대로 · 마우스 버튼 뗌) 렌더러를 그 크기로 다시 만든다. Graphics 에 `PSceneRenderer` 크기 바꾸기(같은 이름 텍스처를 풀고 다시 등록 — 지금은 `Initialize` 만 있음). 게임 UI 는 코드 변경 없이 배율이 따라간다(1920x1080 이미지 → `GetScale()` 1.0). 16:9 를 지키므로 화면 검증 스크립트(이미지 사각형 역산)도 그대로 |
| ② DPI | 프로세스 DPI 인식(Per-Monitor V2 — 매니페스트 또는 시작 때 호출) + ImGui 글꼴 · 스타일을 DPI 배율로(글꼴 아틀라스 다시 만들기, `ScaleAllSizes`, 모니터를 옮기면 `WM_DPICHANGED`). 안 하면 150% 에서 에디터 글자가 작아진다 → 에디터 전체 모양이 바뀌므로 사용자 확인 대상 |
| 고르지 않은 것 | 게임 UI 만 창 크기 텍스처에 따로 그려 겹치기 — 투명 대상에 그린 UI 를 ImGui 가 겹칠 때 알파가 두 번 곱해진다(GUI 백엔드에 premultiplied 그리기 경로 필요), 장면은 계속 흐리고, 입력 좌표 변환이 두 갈래가 된다. ①이 더 작고 장면까지 선명해진다 |
| 미리보기 해상도 고르기(있으면 좋음) | ① 뒤에 "창 맞춤 · 1280x720 · 1920x1080" 고르기는 작다(같은 다시 만들기 경로). 해상도별 UI 배치 확인이 필요해지면 — 지금은 보류 권고 |
| 바뀌는 파일 | ① `SceneViewport.h/.cpp`(JGEditor), `Classes/SceneRenderer.h/.cpp`(Graphics) ② GUI 모듈 백엔드(`DX12GUIBackend.cpp` · `GUIModule`), 런처 매니페스트 또는 시작 코드 |

### 3.3 검증 계획

| # | 내용 |
|---|---|
| ① | 뷰포트 이미지가 1920x1080 픽셀일 때 `GetScale()` = 1.0(로그), 창을 끌어 바꾸는 동안 렌더러를 다시 만들지 않고 멈춘 뒤 한 번, 다시 만든 뒤 D3D12 메시지 0 · live 0, 게임 UI 화면 검증 20단계 그대로 |
| ② | `GetProcessDpiAwareness = 2`, 150% 에서 에디터 글자 크기가 100% 때와 같은 물리 크기, 캡처가 1.5배 늘린 흐림이 없음 |
