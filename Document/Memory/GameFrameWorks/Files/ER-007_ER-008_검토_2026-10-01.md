## 2. ER-007 자동 줄바꿈

### 2.1 판단

범용 기능이고(규칙 글 · 대사 · 툴팁 · 퀘스트 설명) 엔진 몫이다. 게임에 "`\n` 을 끼워 넣는" 우회는 화면 배율 · 글꼴이 바뀔 때마다 다시 계산해야 하고 게임마다 같은 코드를 갖게 되므로 권하지 않는다. 수락 권고.

### 2.2 제안 설계

| 항목 | 제안 |
|---|---|
| 줄바꿈 방식 | `EGameUITextWrap { None, Word, Character }`. 기본 `None`(지금과 같음 — 기존 화면이 바뀌지 않는다) |
| Word | 공백에서 바꾼다. 한 단어가 줄보다 길면 그 단어 안에서 글자 단위로 바꾼다(주소 · 긴 영단어가 넘치지 않게). 한자 · 가나는 띄어쓰기가 없으므로 글자 사이를 바꿀 자리로 본다. 한국어는 어절(공백) 단위가 되어 보통 쓰는 모양이 된다 |
| Character | 아무 글자 사이에서나 바꾼다(좁은 칸). 닫는 문장부호(`, . ! ? ) ] 」 』 …`)는 줄 첫머리에 오지 않게 앞 글자에 붙인다(최소 규칙) |
| 공통 | `'\n'` 은 그대로 줄을 바꾼다. 줄을 바꾼 자리의 공백은 버린다(다음 줄 앞에 공백이 생기지 않게) |
| API | `PGameUIText::SetWrap(EGameUITextWrap)`, `SetClip(bool)`(사각형 밖 잘라내기), (선택) `SetMaxLines(int32)` + 말줄임. 측정: `HVector2 PGameUIText::MeasureContent(const PGameUIManager* ui, float32 width) const` — 요소의 스타일 · 줄바꿈 방식으로 글 상자 크기(논리 단위)를 돌려준다. 낮은 수준: `PGameUIFont::LayoutText(text, fontSize, wrapWidth, wrap) → 줄 목록(시작 · 끝 · 폭) + 크기` |
| 해상도 독립 | 줄 나누기는 **논리 단위**에서 한다(글꼴 크기를 실수로 두고 글자 너비 · 자간을 계산 — 래스터화 없이 stb_truetype 수치만). 그래서 1280x720 · 1920x1080 어디서나 같은 줄에서 바뀌고, 게임이 읽는 높이도 같다. 그리기는 지금처럼 화면 픽셀 크기로 래스터화하고 정수 픽셀에 맞춘다(넘침은 1px 안쪽) |
| 잘라내기 | `SetClip(true)` 이면 요소 사각형(픽셀) ∩ 부모 클립을 그 글자의 클립으로 쓴다. 그리기 목록이 이미 사각형마다 클립을 받으므로 추가 비용은 배치 하나 |
| 말줄임(선택) | 최대 줄 수(또는 사각형 높이)를 넘으면 마지막 줄을 "…" 이 들어갈 만큼 줄이고 붙인다. 줄 배치 결과(글자 위치)를 쓰므로 작다 |
| 바뀌는 파일 | `UI/GameUIText.h/.cpp`, `UI/GameUIFont.h/.cpp`(배치 함수), `UI/GameUIDefines.h`(열거형), `UI/GameUISelfTest.cpp`. 다른 트랙 파일 없음 |

### 2.3 범위 밖 · 주의

| 항목 | 내용 |
|---|---|
| 리치 텍스트 · 마크업 | 요청서에 없다. 카드 글에 기호 · 굵게 같은 마크업이 있으면 지금은 게임이 평문으로 바꿔 넣는다. 아이콘을 글 사이에 넣는 것은 GG-H3 의 나머지(리치 텍스트)로 남긴다 |
| 스크롤 영역 | 요청서에 없지만 같이 보일 문제: 긴 글이 패널 높이도 넘으면 스크롤이 필요하다(덱 편집 · 카드 목록). 지금 엔진에 스크롤 컨테이너가 없다 — 보류 항목으로 새로 적어 두기를 권한다(요구가 오면) |
| 성능 | 줄 나누기는 매 프레임 다시 한다(지금 줄 폭 계산과 같은 방식). 수백 자는 문제없다. 글이 많아지면 (글 · 크기 · 폭) 별 배치 결과를 요소에 캐시한다 |
| 검증 자료 | 엔진 검증에는 아컴호러 카드 글 대신 일반 한국어 긴 문단을 쓴다(지침서 §1). 01029 본문은 게임 쪽에서 확인한다 |

## 3. ER-008 텍스트 입력 (키보드 · IME)

### 3.1 판단

범용 기능이고 엔진 몫이다(입력 · UI 위젯 시스템). 지금 엔진에는 게임 UI 로 글자 · 키를 넘기는 길이 없어 게임이 대신 만들 수 없다. 수락 권고. 다만 GUI(ImGui 래퍼)와 JGEditor(호스트)까지 바뀌는 작업이라 ER-007 보다 크다.

### 3.2 코드에서 확인한 사실 (설계에 걸리는 것)

| 사실 | 뜻 | 근거 |
|---|---|---|
| 확정된 글자는 ImGui 가 받는다: `WM_CHAR` → `io.AddInputCharacterUTF16` → `io.InputQueueCharacters` | 호스트(씬 뷰포트)가 그 프레임의 글자 큐를 읽어 게임 UI 로 넘기면 된다 | `Source/Runtime/GUI/Imgui/imgui_impl_win32.cpp:803-816`, `imgui.h:2488` |
| ImGui 의 IME 연결 해제 줄이 이 저장소에서 주석 처리돼 있다 → 창은 항상 IME 와 연결 | 한글 IME 로 조합한 글자도 확정되면 `WM_CHAR` 로 들어온다. 따로 IME 를 켜는 작업이 없다 | `imgui.cpp:20088` `//::ImmAssociateContextEx(...)` |
| IME 조합 창 · 후보 창 위치는 ImGui 입력란이 활성일 때만 정해진다(`PlatformImeData`) | 게임 입력란이 포커스일 때 호스트가 그 프레임의 IME 위치(게임 커서 위치)를 직접 넣어야 조합 중 글자가 입력란 옆에 뜬다(ImGui 내부 API) | `imgui.cpp:5078-5079, 5421-5430, 20081-20103`, `imgui_internal.h:2486` |
| 글자 큐는 16비트(`IMGUI_USE_WCHAR32` 꺼짐) | 한글 · 한자 · 라틴은 된다. 이모지 같은 BMP 밖 글자는 U+FFFD 가 된다 | `imconfig.h:66` |
| ImGui 키보드 내비게이션이 켜져 있다(`NavEnableKeyboard`) | 게임 입력란이 포커스일 때 방향키 · Enter · Space · Tab · Backspace 를 ImGui 가 창 안 항목 이동 · 실행에 쓴다 → 호스트가 그 키들의 소유권을 가져야 한다(`SetKeyOwner`, 내부 API) | `GUI/Backends/DX12GUIBackend.cpp:59`, `imgui_internal.h:3595` |
| 클립보드 함수가 있다 | 붙여넣기(Ctrl+V) · 복사(Ctrl+C)를 호스트가 ImGui 로 처리할 수 있다 | `imgui.h:1044-1045` |

### 3.3 제안 설계

**엔진(GFW `UI/`) — 호스트와 무관한 API.** 나중의 단독 실행 호스트(D-5)도 같은 함수를 부른다.

| 항목 | 제안 |
|---|---|
| 포커스 | 관리자가 "글자 입력 포커스" 요소 하나를 든다. 입력란을 누르면 포커스, 다른 곳을 누르면 해제. 스택이 바뀌면(화면이 열리고 닫힘) 해제. 입력 모드 Menu 위젯 아래로 가려진 입력란은 받지 못한다(지금 라우팅 규칙 그대로) |
| 호스트 → 관리자 | `bool HandleTextInput(const PString& utf8)`(확정 글자), `bool HandleKey(EGameUIKey key, EGameUIKeyModifiers mods)`(Backspace · Delete · Enter · Escape · ← → · Home · End · Tab, Ctrl+A · C · V · X, 누르고 있으면 반복), `bool WantsTextInput() const`, `HRect GetTextInputCaretRect() const`(IME 위치용, 렌더 타깃 픽셀), `PString GetTextInputSelection() const`(복사용) |
| 입력란 요소 `PGameUITextInput` | 글자(UTF-8) · 자리 글(placeholder) · 최대 길이(글자 수) · 허용 문자(`SetAllowedCharacters("0123456789.:")` 또는 판정 함수) · 글자 스타일 · 입력란 스타일(배경 보통/포커스/비활성, 커서 · 선택 색). 이벤트 `OnTextChanged(text)` · `OnCommitted(text)`. 커서(글자 단위) · Shift 선택 · Ctrl+A, 클릭한 자리로 커서 이동, 커서 깜빡임, 넘치면 가로로 밀어 커서가 보이게 + 칸 밖 잘라내기(ER-007 잘라내기 · 글자 배치 재사용) |
| 키 의미 | Enter = `OnCommitted` 후 포커스 해제, **Esc = 포커스만 해제**(그 Esc 로 메뉴가 닫히지 않는다 — 다음 Esc 부터 뒤로가기), Tab = 다음 입력란(같은 위젯 안, 있으면) |

**호스트(JGEditor 씬 뷰포트)**

| 항목 | 제안 |
|---|---|
| 넘기는 조건 | 씬 뷰포트 창에 포커스가 있고 `GetUI()->WantsTextInput()` 일 때만 |
| 글자 | 그 프레임 글자 큐(UTF-16 → UTF-8) → `HandleTextInput` |
| 키 | 편집 키를 반복 포함으로 읽어 `HandleKey`. 그 키들의 ImGui 소유권을 가져 내비게이션과 겹치지 않게 |
| Esc | 먼저 `HandleKey(Escape)`(입력 중이면 포커스 해제로 끝), 받지 않았을 때만 지금처럼 `HandleBackAction` |
| IME | 게임 커서 위치(렌더 타깃 픽셀 → 이미지 → 화면 좌표)를 매 프레임 IME 위치로 넣는다 → OS 조합 창 · 후보 창이 입력란 옆에 뜬다(ImGui 자기 입력란과 같은 방식) |
| 클립보드 | Ctrl+V → 클립보드 글을 `HandleTextInput`(허용 문자 · 최대 길이 적용), Ctrl+C/X → `GetTextInputSelection` 을 클립보드로 |

**GUI(HGUI) — 추가만**: `EGUIKey` 에 편집 키 추가, `IsKeyPressed(key, bRepeat)`, 보조 키 상태, `GetInputCharacters`, 키 소유권 잡기, `SetTextInputPosition(화면 좌표, 줄 높이)`(IME), `GetClipboardText/SetClipboardText`, `HGUIImageInput` 에 이미지 화면 좌표.

| ImGui 내부 API | 키 소유권 · IME 위치는 `imgui_internal.h` 를 쓴다(GUI.cpp 안에만 둔다). ImGui 를 올리면 다시 확인할 곳 |
| IME 실제 조합 | 자동 검증은 확정 글자(`WM_CHAR` 로 한글 코드포인트를 보냄)까지다. 실제 한글 IME 조합(ㅎ → 하 → 한)과 조합 창 위치는 사용자가 한 번 눈으로 확인해야 한다 |
| 포커스 · 뒤로가기 | 입력 중 Esc 가 메뉴를 닫지 않는 규칙이 CommonUI 와 같다(입력란이 Back 을 먼저 받음). 메뉴 화면 쪽 코드는 바꿀 것이 없다 |
