## 3. 권고 방향 (Q2) — 안 3 최소형

| 바꿀 것 | 내용 |
|---|---|
| `IGameplayFlow` (새, `GameMaster/Rules/`) | `Start(ctx)` · `RunPendingStep(ctx)`(큐가 빌 때마다, false = 입력 대기) · `EndTurn(ctx, actor)` · `CanEndTurn(state, actor)`. 흐름 객체는 상태를 갖지 않고 상태는 `HGameplayState` 에만 둔다(지금 페이즈 기계와 같은 규칙 — AI 가 상태 복사본 위에서 같은 흐름을 돌린다) |
| 기본 흐름 `PGameplayRoundTurnFlow` | 지금 `PGameplayPhaseMachine` + 순서 정책 그대로. 게임이 흐름을 주지 않으면 이것을 쓴다 → 기존 게임 · `gmtest` §12 · `net.test` 동작이 같다 |
| `HGameplayTurnState` | "지금 명령을 낼 수 있는 행동자" 목록(`Actors`)과 흐름이 정하는 단계 이름(`Step`, PName — 표시 · 로그 · 게임 규칙용)을 더한다. 기본 흐름은 TurnMain 에서 `Actors = [CurrentActor]`. `Round` · `TurnCount` 는 흐름이 쓰는 공용 카운터로 남긴다. 고정 `Phase` 열거형은 기본 흐름 전용(NotStarted · Finished 는 공통) |
| 입력 행동자를 한 곳으로 | 컨트롤러 · 세션의 `GetInputActor` 두 벌을 `HGameplayState` 함수 하나(선택 대기면 선택자, 아니면 `Actors`)로 모은다. 여러 명이면 목록이고, 네트워크는 기존 `IsLocallyControlled` 로 거른다 |
| AI 러너 · `EnumerateLegal` · DevView | `Actors` 를 본다. JGEditor DevView 는 `Step` · `Actors` 를 보여 준다 |
| 단계 폭주 한도 | 게임 흐름이 대기 지점 없이 단계를 계속 예약하면 지금 루프(`runQueue`)는 끝나지 않는다 → 명령당 단계 수 한도 + 오류 이벤트(`MaxEffectsPerCommand` 와 같은 방식). 기본 흐름은 항상 대기 지점에 닿으므로 지금은 문제가 없다 |
| 판 끝 | 흐름이 정한다(`ctx.FinishGame`, 이미 있음). "순서가 비면 끝" 은 기본 흐름의 규칙으로만 남는다 |

넣지 않는 것: 데이터 기반 페이즈 목록 · 행동 주체 규칙, 숨은 정보가 필요한 동시 선택(동시 행동은 "여러 명이 아무 순서로 명령" 까지 — 고른 내용을 공개 전까지 숨기는 것은 기존 결정대로 게임 영역, TODO "숨은 정보 모델"), 캠페인 관리자.
