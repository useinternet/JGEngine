## 3. 제안 설계

| 항목 | 제안 |
|---|---|
| 자리 | 새 파일 `UI/GameUIScrollBox.h/.cpp`(+ 요소 · 관리자 작은 연결, 새 파일이라 프로젝트 다시 생성). 기반 변경: `PGameUIElement` 에 "자식 잘라내기"(아래) |
| 자식 잘라 그리기 · 판정 제외(기반) | 요소에 `SetClipChildren(bool)`(스크롤 칸은 늘 켬 — 일반 패널에도 쓸 수 있다). 켠 요소는 ① 자식을 그릴 때 그리기 정보의 잘라내기 사각형을 자기 사각형과 겹친 것으로 줄였다가 되돌린다(2D 그리기 경로의 배치별 잘라내기 사각형 = 지금 글 `SetClip` 과 같은 방법, 겹친 칸은 안쪽으로 더 좁아짐) ② 판정에서 포인터가 자기 사각형(변환을 되돌린 자리) 밖이면 자손을 보지 않는다 — 올리기 · 누르기 · 끌기 시작 · 놓을 곳 찾기 · 글자 입력 포커스 모두 같은 판정이라 함께 빠진다. 돌린 · 배율을 준 부모(GG-14) 아래: 그리기는 돌린 칸을 감싸는 축 정렬 사각형으로 자르고(지금 규칙), 판정은 돌린 칸 안만 |
| 스크롤 칸 | `PGameUIScrollBox` = 보이는 칸(자기 사각형) + 내용 요소 `GetContent()`(자식은 여기에 붙인다) + 세로 스크롤바(칸 안 오른쪽, 내부 요소). 내용 요소의 위치 = −넘긴 양, 크기 = 내용 크기. 내용 크기는 `SetContentSize` 로 정하거나 0 이면 자식 사각형을 감싸는 크기(자식은 위 · 왼쪽 앵커로 둔다). 넘긴 양은 0 ~ (내용 − 칸)으로 늘 자른다(내용이 줄면 따라 줄어든다). 세로가 먼저, 가로 넘긴 양도 API 에는 둔다(가로 막대는 선택지 (나)) |
| 휠 | 관리자 `HandlePointer` 의 휠: 입력을 받는 위젯을 위 레이어부터 보며, 포인터 자리로 요소 트리를 내려가 그 자리를 덮는 스크롤 칸들을 바깥 → 안쪽 순서로 모은다(요소가 입력 받기인지와 상관없이 — 글 위에서 굴려도 된다). 가장 안쪽 칸부터 그 방향으로 더 넘어갈 수 있는 칸이 받는다(끝에 닿았으면 바깥 칸으로 — 웹 브라우저처럼). 한 번에 넘기는 양 = 스타일(기본 = 글 3줄 또는 60 논리 단위). 받을 칸이 없으면 지금처럼 소비만 |
| 스크롤바 | 바탕(칸 오른쪽, 굵기 · 여백은 스타일) + 손잡이(길이 = 칸 / 내용 비율, 최소 길이 있음, 위치 = 넘긴 양 비율). 손잡이 누르고 끌면 넘어간다 — 관리자에 "누른 요소가 이동도 받는다" 훅(`onPointerDrag(위치)`, 끌기(GG-15) 문턱 없이 바로)을 더한다(슬라이더 등 다음 요소도 쓴다). 빈 바탕 누르면 그쪽으로 한 칸(칸 높이 − 한 줄) 넘김. 내용이 다 들어가면 숨김(스타일로 늘 보임). 스타일 `HGameUIScrollStyle`: 바탕 · 손잡이 텍스처 × 보통/호버/누름 색, 굵기, 여백, 최소 손잡이 길이, 휠 한 번에 넘길 양, 관리자 기본 스타일(버튼 · 입력란과 같은 방식) |
| 코드 API | `ScrollTo(offset)` · `ScrollBy(delta)` · `ScrollIntoView(child, 여백)`(그 자손이 칸 안에 보이게 가장 적게 넘김 — 배치 뒤 사각형 기준) · `GetScrollOffset` · `GetMaxScroll` · `SetContentSize` · `OnScrolled(넘긴 양)`(JG_DECLARE_EVENT, 휠 · 손잡이 · 코드 모두에서 바뀔 때 한 번) |
| 다시 만든 뒤 넘긴 양 유지 — 열쇠 | ① 넘긴 양은 스크롤 칸이 가진다 → 내용만 다시 만들면(`GetContent()->ClearChildren()` 뒤 새로 붙임) 그대로 남고 새 내용 크기로 잘린다. ② 스크롤 칸째 다시 만드는 화면을 위해 **열쇠 = 게임이 정한 이름 `SetScrollKey(PName)`**(기본은 없음 — 같은 이름이 우연히 겹쳐 엉뚱하게 이어지는 일을 막으려고 켜는 쪽만). 열쇠가 있는 칸의 넘긴 양을 그 칸이 든 **위젯**이 열쇠별로 기억하고(위젯이 OnShutdown 될 때 잊음), 같은 위젯 안에서 같은 열쇠의 새 칸이 처음 배치될 때 그 값으로 시작한다(요소는 위젯을 모르므로 관리자가 배치 때 위젯을 넘겨 준다). ③ 게임이 직접: `GetScrollOffset` 을 읽어 두었다가 새 칸에 `ScrollTo` |
| 움직임(D-32 · GG-16)과의 관계 | 트윈 속성에 "넘긴 양"(`EGameUITweenProperty::ScrollOffset`, 스크롤 칸만 — 색처럼 해당 요소만 움직임)을 더하면 `PlayTween` 으로 부드럽게 넘기기 · 위젯 열림 때 맨 위로 등을 게임이 바로 쓴다. 휠 · 빈 바탕 누르기를 부드럽게(스타일 길이 > 0)는 관리자가 그 위젯에서 같은 트윈을 재생 — 연달아 굴리면 같은 속성 겹치기 규칙으로 새 목표로 이어진다. 이것은 선택지 (나). 닫힘 전환 중인 위젯은 입력이 없어 휠도 받지 않는다(지금 규칙 그대로) |
| 헤드리스 | 그리기 목록 · 판정만으로 검사(GPU 불필요) |

### 3.1 위험 · 주의

| 항목 | 내용 |
|---|---|
| 끌어다 놓기(GG-15) | 스크롤 칸 안에서 끄는 요소도 칸 밖으로 나가면 잘려 안 보인다(그리기 변환으로 따라가도 칸이 자른다). 칸 밖으로 끌어 놓는 화면(덱 칸 → 카드 칸)은 게임이 끄는 동안 다른 층에 대신 그릴 것을 둔다 — 요소 재부모(GG-H28)와 같은 문제. 칸 안에서 끄다가 가장자리에 닿으면 저절로 넘기기는 범위 밖 |
| 긴 목록 | 자식은 매 프레임 모두 배치한다(지금도 같음). 칸 밖 사각형은 그리기 목록에 들어가지 않는다(잘라내기). 수천 줄 목록의 "보이는 것만 만들기"(가상 목록)는 범위 밖 |
| 입력란 | 칸 안 입력란의 IME 창 자리는 넘긴 자리를 따른다. Tab 으로 칸 밖 입력란에 포커스가 가면 저절로 보이게 넘기기는 하지 않는다(게임이 `ScrollIntoView`) — 필요하면 다음에 |
| 겹친 칸 | 칸 안의 칸: 휠은 안쪽부터, 끝이면 바깥으로. 잘라내기는 겹친 만큼 좁아짐 |
| 지금 화면 | 스크롤 칸을 쓰지 않는 화면은 그리기 · 판정 · 휠 결과가 지금과 같아야 한다(완료 기준 (e)) — 휠은 받을 칸이 없으면 지금처럼 소비만 |
