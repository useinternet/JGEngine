| 19px +0.79px, 14px +0.58px | 19/24 = 0.79, 14/24 = 0.58 — 명목값 | 맞음(명목값) |

덧붙일 사실 — **실제 잉크 증가는 1px 미만 구간에서 명목값보다 적다.** 넓힘은 "정수부까지 최댓값 + 바깥 한 겹은 이웃 커버리지 × 소수부의 최댓값"이라, 가장자리가 이미 반쯤 칠해진(안티에일리어싱) 픽셀은 소수부만큼 더 진해지지 않는다. `gameui.selftest` 의 세로획 'I' 잉크 폭(가운데 줄 커버리지 합) 측정:

| 크기 | 한쪽 반지름 | 명목 증가 | 실제 증가 | 비율 |
|---|---|---|---|---|
| 11px | 0.23 | +0.46 | +0.40 | 87% |
| 24px | 0.50 | +1.00 | +0.76 | 76% |
| 48px | 1.00 | +2.00 | +2.00 | 100% |

→ 19px(반지름 0.40)는 약 +0.6px, 14px(0.29)는 약 +0.5px 로 추정(측정 없음 — 위 비율로 어림). 획이 가는 글꼴(카드 본문 아캄_AC)에서는 가장자리만 조금 진해지는 정도라 증거 그림 ①처럼 본문과 구별이 어렵다. 세기를 em/12 로 올리면 19px 반지름 0.79 → 실제 약 +1.2px 로 어림(완료 기준 (a) em/12 ± 0.5 = 1.08~2.08 안).

넓힘 식 자체(부분 픽셀 방식)를 바꾸면 세기를 정하지 않은 글의 모습도 바뀌어 완료 기준 (b)("지금과 같다")에 어긋난다 — 식은 그대로 두고 세기만 연다.

## 3. 제안 설계

| 항목 | 제안 |
|---|---|
| 정하는 곳 | 글 요소 문단 서식 `HGameUIParagraphStyle::BoldStrength`(em 비율, 0 = 엔진 기본 em/24). 그 요소의 `bBold` 와 `<b>` 구간이 모두 이 세기. 범위 0 < 값 ≤ em/6(넘으면 em/6) |
| 그림 · 폭 | 지금 식 그대로 세기만 바꿈: 한쪽 반지름 = 픽셀 크기 × 세기 / 2, 폭 증가 = 픽셀 크기 × 세기 → 그림과 폭이 같이 늘어 이웃 글자와 겹치지 않는다. 1px 미만은 부분 픽셀 |
| 배치 | 구간 서식 `HGameUITextRunStyle` 에 세기(요소 값을 받음) → `MeasureStyledAdvance` · 줄 나누기 · 커서가 같은 폭 |
| 글리프 캐시 | 키의 굵게 1비트 → 세기(1/1000 em, 11비트, 0 = 굵게 아님). 세기가 다른 요소의 같은 글자는 따로 래스터화(완료 기준 (c)). 기본 세기는 지금과 같은 반지름(비트 단위로 같은 그림) |
| 버튼 라벨 · 입력란 | 문단 서식이 없어 그대로(굵게 없음) |
| 바뀌는 파일 | `UI/GameUIStyle.h`(필드) · `GameUIFont.h/.cpp`(변형 · 키 · 폭 · 반지름) · `GameUIText.cpp`(요소 세기를 구간에) · `GameUISelfTest.cpp`. 새 파일 없음(프로젝트 다시 생성 불필요). 클래스 크기가 바뀌므로 게임은 다시 빌드 |
| 검사 | 요청서 완료 기준 (a) em/12 로 그린 19 · 14px 한글 "폭로 강제 전투 협상" 잉크 폭 증가 = em/12 ± 0.5px, 빈 곳 안 막힘(ER-012 (a) 와 같은 판정) (b) 세기를 안 정한 글 = 지금과 같음 — 기존 검사 · ER-010 · ER-012 기준 그대로 (c) 한 화면에 세기가 다른 두 요소가 같은 글자 → 각자 세기. 검증 게임 서식 패널에 em/24 · em/12 · em/8 비교 줄 + 캡처 |

### 3.1 고를 것 (D-33)

| 안 | 내용 | 일수 | 판단 |
|---|---|---|---|
| (가) 요소 단위(권고) | 위 3절. 요소마다 세기 하나 | 반나절 | 요청서 요구사항 그대로. 카드 본문 · 툴팁 · 제목은 보통 다른 글 요소라 요소 단위로 충분 |
| (나) (가) + 구간 단위 | 글 안 표시 `<b=…>`(예 `<b=2>` = 기본의 두 배)로 한 요소 안에서 구간마다 다른 세기. 마크업 해석 · 겹친 `<b>` 의 세기 규칙 · 검사 | (가) + 반나절 | 한 요소 안에 세기가 다른 굵게가 둘 이상 필요할 때. 지금 요구 없음 |
| (다) 지금은 안 함 | 게임이 겹쳐 찍기 우회(같은 글을 한 번 더 그려 굵은 구간만 두 번 — 글 요소 두 배, 가로로만 굵어짐, 화면 배율에 따라 달라 보임) 또는 약한 채로 둠 | 0 | 엔진 쪽이 반나절이라 우회 비용이 더 크다 |

### 3.2 다른 길 · 범위 밖

| 항목 | 내용 |
|---|---|
| 굵은 글꼴 면(보류 GG-H25) | `<b>` 를 굵은 TTF 로. 이 게임은 카드 본문 글꼴(아캄_AC)에 굵은 면이 없고 원본 카드 틀도 합성 굵게라 해당 없음. 굵은 면이 있는 게임이 생기면 그때 |
| 글꼴마다 기본 세기 | 요청서 "글꼴마다 기본 굵기가 다르다"에 맞지만, 지금은 요소마다 정하면 된다. 같은 세기를 많은 요소에 되풀이하게 되면 그때(보류 후보) |
| 넓힘 모양 | 지금 넓힘은 네모(가로 → 세로)라 세기를 크게(큰 글자에서 반지름 2px 이상) 하면 모서리가 각지고 좁은 빈 곳이 막힐 수 있다. 완료 기준 (a) 크기에서는 1px 미만이라 해당 없음 — 문제가 보이면 둥근 넓힘(보류 후보) |
| 세로 굵기 | 넓힘은 사방이라 가로획도 굵어진다(줄 간격은 그대로 — 위아래 반지름만큼 넘침은 지금도 있음) |
