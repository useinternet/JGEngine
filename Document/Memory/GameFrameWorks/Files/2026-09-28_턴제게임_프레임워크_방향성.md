### 핵심 결론
1. **후보 3(룰 모델 분리 + 명령/이벤트) 채택.** 후보 1(단일 계층)은 되돌리기·AI·헤드리스·멀티플레이를 구조적으로 막아 배제. 후보 2(StS 1편 액션 큐 하이브리드)는 상태와 연출이 한 큐에 섞이는 문제 — 큐 개념만 가져오고 연출과 분리. 후보 4(룰 ECS)는 "값 타입 상태 + 세대 ID" 만 가져오고 스케줄·아키타입·쿼리는 도입 안 함.
2. **룰 모델은 값 타입.** `JGObject`/`PSharedPtr` 을 룰 모델 안에서 쓰지 않는다 → 스냅샷 = 복사, 결정론, 지난 조사의 GC 함정 전부 우회. 정의(콘텐츠)만 `JGAsset` 파생 리플렉션 객체.
3. **결정론 규칙:** 상태 안 시드 RNG 스트림(용도별. StS 방식), PCG32 자체 구현(`std::uniform_int_distribution` 은 STL 마다 달라 이식 결정론 불가), 수치는 정수, 트리거 정렬 규칙 문서화(우선순위 → 행동자 → 부여 시각), FIFO 큐 + `addToTop`.
4. **콘텐츠는 데이터 정의 + C++ 프리미티브 레지스트리 + 복잡 카드 C++ 탈출구.** 스크립트 언어는 프리미티브 한계 확인 후 재검토(ThirdParty 에 없음).
5. **범위:** BG3 급은 1인 범위 초과. 공통 핵심(턴 상태 기계·효과 파이프라인·상태 효과·명령/이벤트·저장) → StS 형 → Gloomhaven 형 → BG3 형 순. BG3 의 대화·탐험·퀘스트·실시간 탐험은 각각 독립 大 모듈이며 실시간 계층이 생기면 지난 조사의 틱 논의가 재부상.
