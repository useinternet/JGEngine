## 1. 인터페이스 (엔진이 정의, 게임 또는 엔진이 구현)

리플렉션 자동 등록이 필요한 것은 `JGObject` 파생 기반 클래스(`JGTabletop*`), 그렇지 않은 것은 순수 인터페이스(`ITabletop*`, `IMemoryObject` 뿌리).

| 인터페이스 | 역할 | 구현자 | 핵심 메서드 |
|---|---|---|---|
| `JGTabletopCommandHandler` | 명령 종류 하나. 검증 · 실행 · 합법 수 열거 | 게임 (내장: `EndTurn`, `ResolveChoice`) | `GetKind` · `Validate` · `Execute` · `Enumerate` |
| `JGTabletopEffect` | 효과 종류 하나. 큐에서 하나씩 해결. 상태 변경 · 이벤트 발행 · 연쇄 · 선택 요청 | 게임 (내장: `SpawnEntity`, `DestroyEntity`, `MoveToZone`, `SetBoardPosition`, `EndTurn`) | `GetKind` · `Resolve` |
| `JGTabletopTrigger` | 이벤트에 반응해 효과 적재. 정렬 키 제공 | 게임 | `GetPriority` · `GetOwner` · `Matches` · `React` |
| `JGTabletopModifier` | 수치 파이프라인 한 단계에서 값 수정 | 게임 | `GetValueKind` · `GetStage` · `Applies` · `Apply` |
| `ITabletopOrderPolicy` | 라운드마다 행동 순서 생성 | 게임 (기본: `PTabletopFixedOrder` · `PTabletopKeyedOrder`) | `BuildOrder` |
| `ITabletopBoard` | 공간 질의. 좌표 · 거리 · 이웃 · 점유 · 경로 · 시야 | 엔진 4종. 게임 파생 가능 | `Distance` · `Neighbors` · `IsOccupied` · `FindPath` · `HasLineOfSight` |
| `ITabletopEvaluator` | AI 용 상태 평가 | 게임 | `Evaluate` |
| `ITabletopAgent` | 행동자 하나의 명령 선택 | 엔진 2종. 게임 | `ChooseCommand` · `ChooseOption` |
| `ITabletopObserver` | 실행 결과(이벤트) · 상태 교체 구독 | 프레젠테이션 · 로그 · 테스트 | `OnEvents` · `OnStateReplaced` |
| `ITabletopMigrator` | 저장 스키마 버전 간 변환 | 게임 (선택) | `Migrate` |
| `ITabletopComponentTable` | 컴포넌트 저장소 공통 면. 복사 · 직렬화 · 엔티티 파괴 정리 | 엔진 (`HTabletopComponentTable<T>`) | `Clone` · `Remove` · `WriteJson` · `ReadJson` |
| `JGTabletopPresentationStep` | 이벤트 하나를 연출 단계로. 재생 · 완료 · 스킵 | 게임 | `Accepts` · `Begin` · `Tick` · `IsDone` · `Skip` |

## 2. 엔진이 구현하는 클래스

### 2-1. `Tabletop/State/` — 값 타입

| 클래스 | 역할 |
|---|---|
| `HTabletopEntityId` | 인덱스 + 세대. 죽은 참조 감지 |
| `HTabletopEntityRegistry` | 엔티티 생성 · 파괴 · 유효성. 파괴 시 모든 테이블에서 제거 |
| `HTabletopComponentTable<T>` | 타입 `T` 컴포넌트 저장. `Get` · `Add` · `Remove` · `Each` |
| `HTabletopZone` / `HTabletopZoneSet` | 엔티티 ID 순서 컬렉션. 삽입 · 제거 · 이동 · 섞기(스트림 지정) / 이름 → 영역 |
| `HTabletopTurnState` | 라운드 · 페이즈 · 행동 순서 · 현재 행동자 |
| `HTabletopRandomStream` | 결정론 난수. 시드 · 호출 횟수가 상태 |
| `HTabletopChoice` | 선택 대기. 요청자 · 종류 · 후보 · 최소/최대 · 대기 효과 요청 · 보존된 큐 |
| `HTabletopBoardState` | 보드 셀 · 점유 데이터 |
| `HTabletopState` | 루트. 복사 = 스냅샷. `Checksum` · `WriteJson` · `ReadJson` · 스키마 버전 |

| `HTabletopEffectRequest` | 종류 · 주체 · 대상 · 매개변수 · 원인(명령 번호 · 깊이) · 선택 결과 슬롯 |
| `HTabletopEvent` | 종류 · 주체 · 대상 · 이전/이후/차이 · 원인 · 깊이 · 이름-값 확장 |

### 2-3. `Tabletop/Rules/`

| 클래스 | 역할 |
|---|---|
| `HTabletopContext` | 핸들러 · 효과 · 트리거 · 수정자에 넘기는 작업 창구 |

## 4. 게임 모듈 구현 가이드

순서대로 따라가면 헤드리스에서 돌아가는 규칙 → 연출 연결까지 간다. `My*` 는 게임이 붙일 이름.

### 4-0. 모듈 만들기

```
MyGame/
  MyGame.module.json        의존: GameFrameWorks. SharedLib
  MyGameModule.h/.cpp
  Sim/                      GameFrameWorks/Tabletop 헤더만 포함
  View/                     GameFrameWorks/Presentation 헤더 포함
```

`Sim/` 은 Graphics · GUI 헤더를 포함하지 않는다. 그래야 같은 규칙 코드가 `JGConsole` 에서 돈다.

### 4-1. 상태 필드

```cpp
// Sim/MyComponents.h
JGSTRUCT()
struct HMyStat : public IJsonable
{
    JGPROPERTY() int32 Current;
    JGPROPERTY() int32 Max;
};

JGSTRUCT()
struct HMyOwnership : public IJsonable
{
    JGPROPERTY() HTabletopEntityId Owner;
    JGPROPERTY() int32             Team;
};
```

- 값 타입만. 포인터 · `PSharedPtr` · 문자열 대신 `PName`/ID. 다른 엔티티 참조는 `HTabletopEntityId`.

### 4-2. 명령 핸들러

```cpp
// Sim/MyCommands.h
JGCLASS()
class JGMyActCommand : public JGTabletopCommandHandler
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetKind() const override
    {
        return PName("MyAct");
    }

    virtual bool Validate(const HTabletopContext& ctx, const HTabletopCommand& cmd, PString* outReason) const override
    {
        if (ctx.State.Turn.CurrentActor != cmd.Actor)
        {
            *outReason = "not your turn";
            return false;
        }
        if (ctx.State.Has<HMyStat>(cmd.Targets[0]) == false)
        {
            *outReason = "invalid target";
            return false;
        }
        return true;
    }

    virtual void Execute(HTabletopContext& ctx, const HTabletopCommand& cmd) override
    {
        HTabletopEffectRequest req;
        req.Kind    = PName("MyEffect");
        req.Subject = cmd.Actor;
        req.Target  = cmd.Targets[0];
        req.Params  = cmd.Params;
        ctx.Enqueue(req);
    }

    virtual void Enumerate(const HTabletopContext& ctx, HTabletopEntityId actor, HList<HTabletopCommand>& out) const override
    {
        ctx.State.Each<HMyStat>([&](HTabletopEntityId id, const HMyStat&)
        {
            HTabletopCommand cmd;
            cmd.Kind  = GetKind();
            cmd.Actor = actor;
            cmd.Targets.push_back(id);
            out.push_back(cmd);
        });
    }
};
```

- `Validate` 는 상태를 바꾸지 않는다. 실패 사유는 UI 에 그대로 보여 준다.
- `Execute` 는 `ctx` 로만 상태에 접근한다. 전역 · static · 시간 · 외부 난수 금지.
- `Enumerate` 가 UI 하이라이트 · AI · 테스트의 공통 근거다. 반드시 구현한다.

### 4-3. 효과

```cpp
// Sim/MyEffects.h
JGCLASS()
class JGMyEffect : public JGTabletopEffect
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetKind() const override
    {
        return PName("MyEffect");
    }

    virtual void Resolve(HTabletopContext& ctx, const HTabletopEffectRequest& req) override
    {
        HMyStat& stat = ctx.State.Get<HMyStat>(req.Target);
        int32 before  = stat.Current;
        int32 amount  = ctx.Compute(PName("MyValue"), req.Subject, req.Target, req.Params[0]);
        stat.Current  = HMath::Max(0, before - amount);

        HTabletopEvent ev;
        ev.Kind    = PName("MyStatChanged");
        ev.Subject = req.Subject;
        ev.Target  = req.Target;
        ev.Before  = before;
        ev.After   = stat.Current;
        ctx.Emit(ev);

        if (stat.Current == 0)
        {
            HTabletopEffectRequest destroy;
            destroy.Kind   = PName("DestroyEntity");   // 엔진 내장 효과
            destroy.Target = req.Target;
            ctx.Enqueue(destroy);
        }
    }
};
```

- 효과 하나는 "한 가지 상태 변화 + 그 이벤트". 연쇄는 큐에 넣는다.
- 이벤트에 연출에 필요한 값(이전 · 이후 · 원인)을 채운다.

### 4-4. 선택 대기가 필요한 효과 (재진입 패턴)

```cpp
virtual void Resolve(HTabletopContext& ctx, const HTabletopEffectRequest& req) override
{
    if (req.HasChoice() == false)
    {
        HTabletopChoice choice;
        choice.Chooser = req.Subject;
        choice.Kind    = PName("MyPick");
        choice.Min     = 1;
        choice.Max     = 1;
        ctx.State.Zone(PName("MyZone")).CollectTo(choice.Candidates);
        ctx.RequestChoice(choice);        // 엔진이 큐를 보존하고 Submit 을 PendingChoice 로 반환
        return;
    }

    HTabletopEntityId picked = req.Choice[0];   // ResolveChoice 가 오면 엔진이 채워서 같은 효과를 다시 부른다
    // ... picked 로 진행
}
```

- 첫 호출에서 요청하고 반환, 두 번째 호출에서 결과를 쓴다.
- `ResolveChoice` 는 엔진 내장 명령. 후보 밖 선택 · 개수 위반은 엔진이 거부한다.
- 저장 · 되돌리기 · 리플레이가 선택 대기 중에도 동작한다(큐가 상태 안에 있으므로).

### 4-5. 트리거

```cpp
// Sim/MyTriggers.h
JGCLASS()
class JGMyOnChanged : public JGTabletopTrigger
{
    JG_GENERATED_CLASS_BODY
public:
    virtual int32 GetPriority() const override
    {
        return 0;                          // 낮을수록 먼저. 같으면 행동자 소유 → 부여 시각
    }

    virtual bool Matches(const HTabletopContext& ctx, const HTabletopEvent& ev) const override
    {
        return ev.Kind == PName("MyStatChanged") && ctx.State.Has<HMyOwnership>(ev.Target);
    }

    virtual void React(HTabletopContext& ctx, const HTabletopEvent& ev) override
    {
        HTabletopEffectRequest req;
        req.Kind    = PName("MyReaction");
        req.Subject = ev.Target;
        ctx.Enqueue(req);                 // 끼어들어야 하면 EnqueueFront
    }
};
```

- `Matches` 는 순수 조건. `React` 는 효과 적재만.
- 무한 연쇄는 엔진의 깊이 상한이 잡는다.

### 4-6. 수치 단계와 수정자

```cpp
// StartupModule
Tabletop->DefineValueStages(PName("MyValue"), { PName("Base"), PName("Add"), PName("Multiply"), PName("Clamp") });

// Sim/MyModifiers.h
JGCLASS()
class JGMyBonus : public JGTabletopModifier
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetValueKind() const override
    {
        return PName("MyValue");
    }

    virtual PName GetStage() const override
    {
        return PName("Add");
    }

    virtual bool Applies(const HTabletopContext& ctx, const HTabletopValueQuery& q) const override
    {
        return ctx.State.Has<HMyBonusTag>(q.Subject);
    }

    virtual int32 Apply(const HTabletopContext& ctx, const HTabletopValueQuery& q, int32 value) const override
    {
        return value + ctx.State.Get<HMyBonusTag>(q.Subject).Amount;
    }
};
```

- 배율은 정수 백분율. "대신에" 류 규칙은 트리거가 아니라 단계로 온다.

### 4-7. 턴 순서 정책

```cpp
// Sim/MyOrder.h
class PMyOrder : public ITabletopOrderPolicy
{
public:
    virtual void BuildOrder(const HTabletopState& state, HList<HTabletopEntityId>& outOrder) const override
    {
        state.Each<HMyInitiative>([&](HTabletopEntityId id, const HMyInitiative&)
        {
            outOrder.push_back(id);
        });
        HAlgorithm::StableSortBy(outOrder, [&](HTabletopEntityId id)
        {
            return state.Get<HMyInitiative>(id).Value;
        });
    }
};
```

- 안정 정렬. 동률을 정책 안에서 결정론적으로 끝낸다. 기본 정책 2종으로 충분하면 생략.

### 4-8. 보드 선택

```cpp
Tabletop->SetBoard(ETabletopBoardKind::Hex);       // None · Square · Hex · Free
```

- 규칙 코드는 `ctx.State.Board()` 의 `ITabletopBoard` 질의만 쓴다. 좌표는 `HTabletopCoord`(정수).

### 4-9. 모듈 시작

```cpp
// MyGameModule.cpp
void HMyGameModule::StartupModule()
{
    Tabletop = Allocate<PTabletopSimulation>();

    Tabletop->RegisterComponent<HMyStat>();
    Tabletop->RegisterComponent<HMyOwnership>();
    Tabletop->RegisterZone(PName("MyZone"));
    Tabletop->DefineValueStages(PName("MyValue"), { PName("Base"), PName("Add"), PName("Multiply"), PName("Clamp") });

    Tabletop->RegisterAllFromReflection<JGTabletopCommandHandler>();
    Tabletop->RegisterAllFromReflection<JGTabletopEffect>();
    Tabletop->RegisterAllFromReflection<JGTabletopTrigger>();
    Tabletop->RegisterAllFromReflection<JGTabletopModifier>();

    Tabletop->SetOrderPolicy(Allocate<PMyOrder>());
    Tabletop->SetBoard(ETabletopBoardKind::Hex);

    Tabletop->Start(MakeMyInitialState(12345));
}

void HMyGameModule::ShutdownModule()
{
    Tabletop.Reset();
}
```

- 등록은 시작 시 한 번. 플레이 중 등록 변경 금지.

### 4-11. 프레젠테이션 연결

```cpp
// View/MyStatChangedStep.h
JGCLASS()
class JGMyStatChangedStep : public JGTabletopPresentationStep
{
    JG_GENERATED_CLASS_BODY
public:
    virtual bool Accepts(const HTabletopEvent& ev) const override
    {
        return ev.Kind == PName("MyStatChanged");
    }

    virtual void Begin(const HTabletopEvent& ev, PTabletopBinding& binding) override;
    virtual void Tick(float32 dt) override;
    virtual bool IsDone() const override;
    virtual void Skip() override;
};

// View 초기화
Binding   = Allocate<PTabletopBinding>(Tabletop, World);
Sequencer = Allocate<PTabletopSequencer>(Binding);
Sequencer->RegisterAllFromReflection<JGTabletopPresentationStep>();
Sequencer->SetInputPolicy(ETabletopInputPolicy::BufferAndSkip);

// 매 프레임 (Update 버킷)
HTabletopCommand cmd;
if (CommandBuilder.Poll(cmd))
{
    HList<HTabletopEvent> events;
    PString reason;
    ETabletopSubmitResult result = Tabletop->Submit(cmd, events, &reason);
    Sequencer->Enqueue(events);
    if (result == ETabletopSubmitResult::PendingChoice)
    {
        CommandBuilder.BeginChoice(*Tabletop->GetPendingChoice());
    }
    if (result == ETabletopSubmitResult::Rejected)
    {
        DevView.ShowReason(reason);
    }
}
Sequencer->Tick(dt);
```

- 연출 단계는 상태를 읽기만 한다(`const HTabletopState&`).
- `EntitySpawned` / `EntityDestroyed` 는 `PTabletopBinding` 이 처리한다.

## 5. 지켜야 할 규칙 요약

| 위치 | 해야 할 것 | 하지 말 것 |
|---|---|---|
| 상태 구조체 | 값 타입 · `HTabletopEntityId` · `PName` · 정수 | 포인터 · `PSharedPtr` · 문자열 · 실수 |
| `Validate` | `const`. 사유 반환 | 상태 변경 |
| `Execute` / `Resolve` / `React` | `ctx` 로만 접근. 효과를 큐에 | 전역 · static · 시간 · 외부 난수 · 렌더 상태 |
| 이벤트 | 이전 · 이후 · 원인 채움 | "바뀌었다" 만 발행 |
| 트리거 | 조건과 적재 분리 | `Matches` 안에서 상태 변경 |
| 수정자 | 정수 백분율 | 실수 배율 |
| 등록 | 시작 시 한 번 | 플레이 중 등록 변경 |
| `Sim/` 폴더 | `GameFrameWorks/Tabletop` 만 포함 | Graphics · GUI · Presentation 헤더 |
| 연출 단계 | 상태 읽기 | 상태 쓰기 · 명령 직접 실행 |
