# 설계 방안 B 상세 — Tabletop 시뮬레이션 / 프레젠테이션 2계층 (GameFrameWorks 모듈 내)

> **이름 안내 (2026-09-29)**: 이 문서의 Tabletop · Simulation 이름과 일부 구조(Presentation · Sequencer · Binding)는 설계 단계의 것이다. 현재 이름과 구조는 `GameFrameWorks_구현현황_2026-09-28.md`, 옛 이름과의 대응표는 `GameFrameWorks_이름변경안_2026-09-29.md` 를 따른다.

작성 2026-09-28 (개정: 단일 모듈 · 명명 변경). **엔진 시스템 설계.** 콘텐츠는 범위 밖.
전제: 엔진 레이어 / 게임 레이어. 게임 프레임워크 = 엔진 레이어. 방안 선정 근거는 `게임프레임워크_설계방안_요약_2026-09-28.md`.

**개정 사항**
- 시뮬레이션을 별도 모듈로 빼지 않는다. **`GameFrameWorks` 모듈 안의 `Tabletop/` 폴더**로 구현한다.
- 시스템 이름을 **Tabletop** 으로 정하고 모든 타입에 접두한다(`HTabletopState`, `JGTabletopEffect` …). 보드 · 카드 · 테이블탑 RPG 를 한 단어로 가리키고 다른 모듈의 이름과 겹치지 않는다. 문자 그대로가 낫다면 `TurnSim` 으로 일괄 치환 가능.

## 1. 한눈에

```
┌─ 게임 레이어 ───────────────────────────────────────────────────────────────┐
│  MyGame 모듈:  상태 필드 · 명령 · 효과 · 순서 정책 · 평가 함수 │ 연출 단계 · UI      │
└────────────┬───────────────────────────────────────────────────┬────────────┘
             │ 파생 · 리플렉션 자동 등록                             │ 파생
┌─ 엔진 레이어 ┴───────────────────────────────────────────────────┴────────────┐
│  ┌─ GameFrameWorks 모듈 ────────────────────────────────────────────────────┐  │
│  │  ┌─ Tabletop/ (시뮬레이션. Core 만 포함) ──┐ 이벤트 ▶ ┌─ Presentation/ ─────────┐ │  │
│  │  │ HTabletopState (값 타입 · 스냅샷)       │ ───────▶ │ World / Actor / Component │ │  │
│  │  │ 명령 → 검증 → 실행 → 이벤트             │          │ PTabletopBinding          │ │  │
│  │  │ 효과 큐 · 트리거 정렬 · 수치 파이프라인   │ ◀─────── │ PTabletopSequencer        │ │  │
│  │  │ 페이즈 기계 · 선택 대기 · 보드           │  명령 ◀  │ PTabletopCommandBuilder   │ │  │
│  │  │ 스냅샷 · 리플레이 · 체크섬 · 직렬화       │          │ Camera · PTabletopDevView │ │  │
│  │  │ Agents/ (무작위 · 탐색)                 │ 상태 읽기▶│                           │ │  │
│  │  └────────────────────────────────────────┘          └───────────────────────────┘ │  │
│  └──────────────────────────────────────────────────────────────────────────────────┘  │
│  Graphics · GUI · Asset                                                                  │
│  Core (리플렉션 · JSON · 메모리 · 모듈 · 스케줄러)                                          │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

원칙 세 줄.
- 상태를 바꾸는 길은 **명령 하나**뿐이다. 프레젠테이션은 상태를 읽기만 한다.
- Tabletop 은 **프레임을 모른다.** 명령이 올 때만 움직인다. 프레젠테이션만 프레임 틱을 탄다.
- `Tabletop/` 폴더는 **Core 헤더만 포함**한다. 그래야 `JGConsole` 에서 돌고, AI 와 테스트가 같은 코드를 쓴다.

## 2. 모듈과 폴더

| 모듈 | 계층 | 의존 | 현재 |
|---|---|---|---|
| `Core` | 엔진 | — | 있음 |
| `GameFrameWorks` | 엔진 | Core · Asset · Graphics · GUI | 빈 StaticLib → **SharedLib 전환**, `GAMEFRAMEWORKS_API` |
| `AI` | 엔진 | Core | 빈 모듈. 당분간 사용 안 함(에이전트는 `Tabletop/Agents/`) |
| `MyGame` | 게임 | GameFrameWorks | 게임 프로젝트 |

```
Source/Runtime/GameFrameWorks/
  Tabletop/                 시뮬레이션. Core 만 포함 (폴더 규칙)
    State/                  HTabletopState 와 그 구성 요소
    Messages/               HTabletopCommand · HTabletopEffectRequest · HTabletopEvent
    Rules/                  레지스트리 · 큐 · 디스패처 · 파이프라인 · 페이즈 기계 · 룰 엔진
    Boards/                 ITabletopBoard 구현 4종
    Services/               스냅샷 · 명령 로그 · 직렬화 · 헤드리스 러너
    Agents/                 ITabletopAgent 구현 (무작위 · 탐색)
    TabletopSimulation.h    파사드 PTabletopSimulation
  Presentation/             World / Actor / Component + Tabletop 접점
    Scene/                  PWorld · JGActor · JGActorComponent (지난 조사 A안)
    Tabletop/               PTabletopBinding · PTabletopSequencer · PTabletopCommandBuilder · PTabletopDevView
```

**단일 모듈의 대가.** `GameFrameWorks` 가 Graphics · GUI 에 의존하므로 "Tabletop 은 Core 만" 을 빌드 시스템이 강제하지 못한다. 폴더 규칙으로 지키고, 필요하면 나중에 헤더 툴에 include 검사를 넣는다. 헤드리스 실행 자체는 문제없다 — `JGConsole` 은 이미 코드젠 대상 DLL 을 전부 로드하며, Graphics 모듈이 시작되지 않는 한 디바이스는 만들어지지 않는다.

## 3. Tabletop 시뮬레이션

### 3-1. 구성

```
┌─ Tabletop/ ─────────────────────────────────────────────────────────────┐
│  ┌─ State (HTabletopState, 값 타입) ─────────────────────────────────┐  │
│  │ HTabletopEntityRegistry (세대 ID)   HTabletopComponentTable<T>    │  │
│  │ HTabletopZoneSet                    HTabletopBoardState           │  │
│  │ HTabletopTurnState                  HTabletopChoice (선택 대기)    │  │
│  │ HTabletopRandomStream[]             시퀀스 번호 · 체크섬            │  │
│  └──────────────────────────────────────────────────────────────────┘  │
│  ┌─ Rules ─────────────────────────────────────────────────────────┐  │
│  │ PTabletopCommandRegistry / EffectRegistry / TriggerRegistry / ModifierRegistry │
│  │ PTabletopEffectQueue (addToTop / addToBottom)                     │  │
│  │ PTabletopTriggerDispatcher (이벤트 → 수집 → 결정론 정렬)            │  │
│  │ PTabletopValuePipeline (게임 정의 단계 순서로 수정자 적용)           │  │
│  │ PTabletopPhaseMachine + ITabletopOrderPolicy                      │  │
│  │ PTabletopRuleEngine (Validate / Execute 오케스트레이션)             │  │
│  └──────────────────────────────────────────────────────────────────┘  │
│  ┌─ Services ─────────────────────────────────────────────────────┐   │
│  │ PTabletopSnapshotStack   PTabletopCommandLog   PTabletopSerializer │   │
│  │ 체크섬                    합법 수 열거          PTabletopHeadlessRunner │
│  └──────────────────────────────────────────────────────────────────┘  │
│  파사드: PTabletopSimulation                                            │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3-2. 상태 컨테이너 `HTabletopState`

| 항목 | 내용 |
|---|---|
| 형식 | 값 타입. `JGObject`/`PSharedPtr` 없음. 복사 = 스냅샷 |
| 엔티티 | `HTabletopEntityId { Index, Generation }`. 죽은 참조는 세대 불일치로 감지 |
| 컴포넌트 | 게임이 `JGSTRUCT` 로 타입 정의, `HTabletopComponentTable<T>` 가 보관. `ITabletopComponentTable::Clone` 으로 값 복사. 직렬화는 리플렉션 |
| 영역 | `HTabletopZone` = 엔티티 ID 의 순서 컬렉션. 이름은 게임이 정의 |
| 보드 | `ITabletopBoard` 구현의 상태. None / Square / Hex / Free |
| 턴 | `HTabletopTurnState` = 라운드 · 페이즈 · 행동 순서 · 현재 행동자 |
| 선택 대기 | `HTabletopChoice` = 요청자 · 종류 · 후보 · 최소/최대 · 대기 중인 효과 요청 · 보존된 큐 |
| 난수 | `HTabletopRandomStream` 의 시드 · 호출 횟수가 상태. 용도별 배열 |
| 검증 | `Checksum()` — 같은 명령열이면 같은 값 |

### 3-3. 명령 파이프라인

```
   HTabletopCommand (직렬화 가능)
        │
        ▼
  ┌──────────┐  실패 사유   ┌────────────────────┐
  │ Validate │ ──────────▶ │ 프레젠테이션에 반환 │
  └────┬─────┘             └────────────────────┘
       │ 통과
       ▼
  ┌──────────┐  스냅샷 push
  │ Execute  │ ──► JGTabletopCommandHandler ──► 효과 큐 적재
  └────┬─────┘
       ▼
  ┌──────────────────────┐ 큐가 빌 때까지
  │ PTabletopEffectQueue │ ──► JGTabletopEffect::Resolve ──► 상태 변경 ──► 이벤트 발행 ──► 트리거 수집 · 정렬 ──► 큐 적재
  └────┬─────────────────┘
       │ 선택 대기 발생 ─► 큐를 HTabletopChoice 에 보존하고 중단
       ▼
  HList<HTabletopEvent> (원인 명령 번호 · 깊이 포함)  +  명령 로그 append
```

- 플레이어 · AI · 리플레이 · 테스트가 **같은 입구**(`PTabletopSimulation::Submit`)를 쓴다.
- `EnumerateLegal(state, actor)` 가 UI 하이라이트 · AI · 테스트의 공통 근거다.

### 3-4. 효과 해결과 트리거

| 규칙 | 내용 |
|---|---|
| 큐 | FIFO. 끼어들기는 `EnqueueFront` |
| 트리거 정렬 | 명시 우선순위 → 행동자 소유 먼저 → 부여 시각 오름차순. 문서화된 고정 규칙 |
| 대체 효과 | 큐가 아니라 수치 파이프라인 단계로 처리 |
| 수치 파이프라인 | 게임이 단계 목록 정의, `PTabletopValuePipeline` 이 순서대로 `JGTabletopModifier` 적용 |
| 선택 대기 | 효과가 `RequestChoice` 하면 큐를 상태에 보존하고 반환. 내장 `ResolveChoice` 명령으로 같은 효과를 재진입 |
| 연쇄 상한 | 깊이 상한 초과 시 실패 이벤트 발행 후 중단 |

### 3-5. 페이즈 기계 `PTabletopPhaseMachine`

```
  RoundStart ──► OrderResolve ──► TurnStart ──► TurnMain ──► TurnEnd ──► (다음 행동자) ──► RoundEnd ──► RoundStart
                      │                                │
              ITabletopOrderPolicy               HTabletopChoice 로 중단 가능
              (게임이 구현)                       (선택 후 같은 위치에서 재개)
```

- 페이즈 골격과 전이 이벤트는 엔진, **순서 결정은 정책 인터페이스**로 게임이 구현한다.
- 내장 명령 `EndTurn` 이 `TurnMain → TurnEnd` 전이를 만든다.

### 3-6. 보드 `ITabletopBoard`

| 인터페이스 | 제공 |
|---|---|
| `ITabletopBoard` | `HTabletopCoord`(정수) · `Distance` · `Neighbors` · `IsOccupied` · `FindPath` 훅 · `HasLineOfSight` 훅 |
| 구현 | `PTabletopBoardNone` · `PTabletopBoardSquare` · `PTabletopBoardHex` · `PTabletopBoardFree` |
| 상태 | `HTabletopBoardState` 는 `HTabletopState` 의 일부(값 타입). 규칙은 인터페이스 질의만 사용 |

### 3-7. 서비스

| 서비스 | 동작 |
|---|---|
| `PTabletopSnapshotStack` | 명령마다 상태 복사 push. `Undo` = pop |
| `PTabletopCommandLog` | 실행된 명령 기록. 리플레이 입력 |
| `PTabletopSerializer` | 상태 + 명령 로그 ↔ JSON. 스키마 버전 확인 후 `ITabletopMigrator` |
| 체크섬 | 결정론 회귀 테스트 기준값 |
| `PTabletopHeadlessRunner` | `JGConsole` 에서 명령 스크립트 실행 → 체크섬 · 통계 |

### 3-8. 결정론 규칙

1. 상태 밖의 변수 금지(전역 · static · 시스템 시간).
2. 난수는 `HTabletopRandomStream` 만. 자체 구현(STL 분포는 구현마다 달라 이식 결정론 불가).
3. 규칙 수치는 정수. 배율은 백분율 정수.
4. 컨테이너 순회 순서 고정(해시맵 순회로 결과가 갈리면 안 됨).
5. 프레임 · 시간 · 렌더 상태를 규칙에서 참조 금지.

## 4. Presentation 계층

### 4-1. 구성

```
┌─ Presentation/ ──────────────────────────────────────────────────────────┐
│  Scene/     PWorld · JGActor · JGActorComponent (씬 트리 · 트랜스폼 · 프리팹 · 렌더 핸들) │
│  Tabletop/  PTabletopBinding         HTabletopEntityId ↔ Actor. 상태 읽기 창구         │
│             PTabletopSequencer       이벤트 → JGTabletopPresentationStep 큐. 인과 묶음 · 병렬/직렬 · 스킵 │
│             PTabletopCommandBuilder  피킹 · 타깃 선택 · 선택 대기 UI → HTabletopCommand │
│             PTabletopDevView (ImGui) 상태 인스펙터 · 이벤트 로그 · 되돌리기 · 체크섬     │
└───────────────────────────────────────────────────────────────────────────┘
```

### 4-2. 바인딩 `PTabletopBinding`
- `EntitySpawned` / `EntityDestroyed` 이벤트로 Actor 를 만들고 지운다. 상태를 폴링하지 않는다.
- Actor 는 표시용 값을 상태에서 읽되 쓰지 않는다(`const HTabletopState&`).
- 연출 상태(피격 리액션 · 호버 · 드래그)는 Actor 의 것. Tabletop 상태와 분리.

### 4-3. 시퀀서 `PTabletopSequencer`

```
  이벤트 목록 ──► 인과(원인 명령 · 깊이)로 묶기 ──► JGTabletopPresentationStep 생성 ──► 큐
                                                                                 │ 프레임 틱
      정책: 직렬/병렬 · 페이싱 · 스킵 · 연출 중 입력(ETabletopInputPolicy)             ▼
                                                                    Actor 애니메이션 · 카메라 · UI
```

- 이벤트에는 연출에 필요한 정보(이전/이후 값 · 원인 · 위치)가 있어야 한다. **이벤트 스키마는 시퀀서 요구로 정한다.**
- 선택 대기가 뜨면 큐를 비운 뒤 `PTabletopCommandBuilder` 에 선택 모드를 연다.

### 4-4. 프레임 타이밍

```
  프레임:  |----tick----|----tick----|----tick----|----tick----|
  Tabletop: [명령 A 실행]                          [명령 B 실행]
            (한 번에 완료, 이벤트 30개)              (선택 대기로 중단)
  Pres    : ▶ 단계1 ▶ 단계2 ▶▶ 단계3(병렬) ▶ 단계4 ...  ▶ 선택 UI ...
```

Tabletop 은 명령 시점에 즉시 끝난다. 프레젠테이션이 그 결과를 여러 프레임에 걸쳐 푼다.

## 6. 엔진 ↔ 게임 확장점

| 확장점 | 엔진이 제공 | 게임이 구현 | 등록 |
|---|---|---|---|
| 상태 필드 | `HTabletopComponentTable<T>` · 직렬화 | `JGSTRUCT` 타입들 | `RegisterComponent<T>` |
| 명령 | 파이프라인 · 로그 · 리플레이 · 내장 `EndTurn` `ResolveChoice` | `JGTabletopCommandHandler` 파생 | 리플렉션 자동 |
| 효과 | 큐 · 정렬 · 선택 대기 · 내장 `SpawnEntity` `DestroyEntity` `MoveToZone` `SetBoardPosition` `EndTurn` | `JGTabletopEffect` 파생 | 리플렉션 자동 |
| 트리거 | 디스패처 · 정렬 규칙 · 깊이 상한 | `JGTabletopTrigger` 파생 | 리플렉션 자동 |
| 수치 단계 · 수정자 | `PTabletopValuePipeline` | 단계 목록 · `JGTabletopModifier` 파생 | `DefineValueStages` + 자동 |
| 턴 순서 | `PTabletopPhaseMachine` · 기본 정책 2종 | `ITabletopOrderPolicy` | 인스턴스 주입 |
| 보드 | `ITabletopBoard` · 구현 4종 | 선택 또는 파생 | `SetBoard` |
| AI | 합법 수 · `PTabletopSearchAgent` | `ITabletopEvaluator` · `ITabletopAgent` | `SetAgent` |
| 연출 | Actor/Component · `PTabletopSequencer` · `PTabletopBinding` | `JGTabletopPresentationStep` 파생 · UI | 리플렉션 자동 |
| 이벤트 | 기본 필드(원인 · 깊이 · 주체 · 대상 · 이전/이후) | 게임 이벤트 종류 · 이름-값 확장 | — |

등록 시점은 게임 모듈의 `StartupModule`. 리플렉션이 파생 클래스를 열거하므로(`JGClass::GetChildClasses`) 대부분 자동 등록이다.

## 9. 착수 순서

1. **GameFrameWorks SharedLib 전환 + `Tabletop/` 골격**: 상태 컨테이너 · 세대 ID · 명령 파이프라인 · 이벤트 · 스냅샷 · 체크섬 · 헤드리스 러너. 합격: 같은 명령열 → 같은 체크섬.
2. **효과 · 트리거 · 페이즈**: 큐 · 정렬 규칙 · 선택 대기 재진입 · 페이즈 기계 · 순서 정책 인터페이스.
3. **Presentation 연결**: 바인딩 · 시퀀서(ImGui 로 먼저) · 명령 빌더. 합격: 이벤트만으로 연출, Tabletop 코드 무변경.
4. **보드 · 에이전트**: 구현 4종 · 합법 수 열거 · 탐색.
5. 게임 레이어 첫 검증 모듈로 확장점 전부 통과.

### 10-3. 사용 흐름

```cpp
void HMyGameModule::StartupModule()
{
    Tabletop = Allocate<PTabletopSimulation>();
    Tabletop->RegisterComponent<HMyData>();
    Tabletop->RegisterAllFromReflection<JGTabletopCommandHandler>();
    Tabletop->RegisterAllFromReflection<JGTabletopEffect>();
    Tabletop->RegisterAllFromReflection<JGTabletopTrigger>();
    Tabletop->RegisterAllFromReflection<JGTabletopModifier>();
    Tabletop->SetOrderPolicy(Allocate<PMyOrder>());
    Tabletop->SetBoard(ETabletopBoardKind::Hex);
    Tabletop->Start(MakeInitialState(12345));
}

// 플레이 중 (프레젠테이션 한 프레임)
switch (Tabletop->Submit(cmd, events, &reason))
{
case ETabletopSubmitResult::Rejected:      DevView.ShowReason(reason);                              break;
case ETabletopSubmitResult::Executed:      Sequencer->Enqueue(events);                              break;
case ETabletopSubmitResult::PendingChoice: Sequencer->Enqueue(events);
                                           CommandBuilder.BeginChoice(*Tabletop->GetPendingChoice()); break;
}
```
