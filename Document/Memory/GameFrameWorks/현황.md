## 3. 구현 현황 상세

### 완료 (코드에 반영된 핵심 결정)

| 항목 | 내용 |
|---|---|
| 상태 | `HGameplayState` 값 타입, 복사 = 스냅샷, noexcept 이동 생성 · 대입. 컴포넌트는 게임이 `IJsonable` 구조체로 정의(헤더 툴이 구조체를 처리하지 않아 `WriteJson/ReadJson` 수동) |
| 엔티티 · 수명 가드 | 인덱스 + 세대. `Add<T>` 는 `T*`(죽은 ID 면 nullptr), 보드 · 영역 쓰기는 `HGameplayState::SetBoardPosition` · `MoveToZone` 이 죽은 ID 거부. 내장 효과는 죽은 대상이면 이벤트 없이 건너뜀 |
| 명령 경로 | `Submit` → `Validate` → 스냅샷 push → `Execute` → 핸들러 → 효과 큐 루프 → 이벤트. 루프 한 바퀴 = 방금 끝난 단계의 이벤트에 대한 트리거 `React` → 효과 하나 `Resolve`. 큐가 비면 예약된 페이즈 단계 |
| 선택 대기 | `RequestChoice` 는 **효과 `Resolve` 안에서만** 받는다(bool 반환, 밖이면 오류 로그 + false). 남은 큐를 `HGameplayChoice::SavedQueue` 에 보존, 내장 `ResolveChoice` 로 재진입 |
| 트리거 | `Emit` 때는 `Match` 만. `React(HGameplayTriggerContext&, const HGameplayEvent&)` 는 이벤트를 낸 단계가 끝난 뒤 발행 순 → 우선순위 → 등록 순. 컨텍스트는 `Enqueue/EnqueueFront` 만, 상태 const. 깊이 한도 `MaxEffectDepth` 64, 명령당 `MaxEffectsPerCommand` 4096 |
| 페이즈 | RoundStart → OrderResolve → TurnStart → TurnMain → TurnEnd → … → RoundEnd. 전이는 `EGameplayPhaseStep`(BeginRound · ResolveOrder · BuildOrder · NextTurn · EnterTurnMain) 단계로 나눠 **효과 큐가 빈 뒤** 진행, 예약 단계는 `HGameplayTurnState::PendingStep`(저장 · 되돌리기에 보존). 내장 `EndTurn` 효과는 TurnStart 에서도 받음 |
| 수치 | `DefineValueStages(kind, stages)` → `ctx.Compute` 가 단계 순으로 `JGGameplayModifier` 적용 |
| 되돌리기 | `PGameplaySnapshotStack` = `HDeque` + `pop_front`, `Pop` 은 상태를 옮겨 줌. 한도 기본 256 |
| 결정론 | 레지스트리 종류 이름 사전순 정렬(`Finalize` — `Start` · `ImportDocument`(Load) · `Replay` 가 부름), PCG32 용도별 8 스트림, 체크섬 = JSON 텍스트 FNV-1a 64 |
| 읽기 전용 경계 | const 상태의 `Find` · `Get` · `Table` 은 const 반환(static_assert 회귀) |
| 저장 · 문서 | 초기 상태 + 현재 상태 + 명령 로그, `SchemaVersion` 불일치 시 `IGameplayMigrator`. 리슨 서버 트랙이 추가한 API: `ExportDocument` · `ImportDocument` · `RulesFingerprint` · `TeamOfActor` · `SetUndoEnabled/IsUndoEnabled` · `PGameplayAgentRunner::Choose` |
| 등록 | `RegisterAllFromReflection<T>()` — `JGClass::GetChildClasses` 재귀 → `AllocateByClass` → `Cast` |
| 월드 소유 | 엔진(`JGGameInstance`: `LoadWorld` · `UnloadWorld` · `GetWorld` · `SetEntryClass<T>` · `OnWorldLoaded/Unloading`)이 소유. 게임은 `SetEntryClass` · `LoadWorld` 만. 월드 생성 직후 `JGGameEntryActor` 파생을 스폰 → `OnEnterWorld`. 모듈은 `ReplaceGameInstance<T>` 와 틱만 |
| 월드 수명 | 틱 중 스폰은 다음 틱 시작에 반영, 그 사이 파괴 예약된 액터는 넣지 않음(`flushPendingSpawn`). `GetWorldPosition` 은 행렬 4행(`Get_C(n, 3)`) |
| GameMasterActor | `PGameMaster` 보유, 이벤트 → `JGGameplayCue` 순차 재생 + 스킵, 바인딩 표(엔티티 ↔ `JGGameplayEntityActor`), 입력 정책 Block/Buffer. 스폰 바인딩은 큐 시작 전, 파괴 바인딩은 큐 완료 후(`applyBindingBeforeCue` · `applyBindingAfterCue` · `finishActiveCue`). 관찰자는 별도 객체 `PGameMasterActorObserver`(`IMemoryObject` 뿌리 둘 회피) |
| 동적 캐스트 | `Cast<>` 는 정적 관계만 보므로 컴포넌트 · 액터 탐색은 `RawDynamicCast<>` |
| 콘솔 | `gmtest`(GameMaster 92 + 월드 19)를 모듈 안 `HAutoConsoleCommand` 로 선언. JGConsole 과 프로젝트 모드 에디터(게임 모듈이 GFW 를 연결)에서 보임. 별칭 `simtest` 는 2026-09-30 제거 |

게임 모듈이 보는 API 는 `Files/GameFrameWorks_구현현황_2026-09-28.md` §3 이 기준이다(설계 단계의 `설계방안B_인터페이스_구현가이드` 는 구조가 다르다). 게임 프로젝트 템플릿(`Build/Templates/GameProject/Source/{PROJECT_NAME}/{PROJECT_NAME}Module.cpp`)이 실제 사용 예다: `ConnectModule("GameFrameWorks")` → `JGGameInstance::Get().SetEntryClass<JG{PROJECT_NAME}EntryActor>()` → `LoadWorld(PName("{PROJECT_NAME}"))`.
