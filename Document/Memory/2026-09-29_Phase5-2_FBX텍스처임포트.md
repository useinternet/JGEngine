# 2026-09-29 Phase 5-2 FBX 임베디드 텍스처 임포트

## 결론
- FBX 안에 들어 있는 텍스처가 `.jgasset`(`JGTexture`, `R8G8B8A8_Unorm`, 밉 1장)으로 저장되고, 다시 로드하면 GPU 픽셀이 원본과 같다. PNG 2장은 완전 일치, JPG는 평균 오차 0.54.
- TODO 문구(포맷 변경 + 호출 활성화)만 했으면 0바이트 텍스처가 저장됐다. FBX 임베디드 텍스처는 assimp에서 항상 압축 상태(PNG/JPG 파일 바이트)라 디코딩이 필요했다.
- 가장 큰 남은 문제는 저장 크기다(5-30). 원본 4MB 텍스처가 73.7MB 파일이 되고, 메시 에셋도 같은 원인이다.

## 알아 둘 것 (코드에 없는 사실)
- assimp FBX 로더의 임베디드 텍스처: `mHeight == 0`, `mWidth` = 바이트 수, `achFormatHint` = 확장자, `mFilename` = FBX에 적힌 원본 경로 그대로(`textures/Checker.png`, `C:\Art\Photo.jpg`). `scene->mTextures` 순서는 익스포트 순서와 다를 수 있다(검증 FBX에서 Checker, Photo, Noise 순).
- `JGCLASS` 헤더는 자기 `.generation.h`를 반드시 포함해야 한다. `JG_GENERATED_CLASS_BODY`는 생성 헤더마다 다시 정의되므로, 빠지면 먼저 포함된 다른 클래스의 본문이 펼쳐진다. 모듈마다 include 순서가 달라서 한 모듈에서만 컴파일 오류가 난다(Graphics는 통과, Devkit은 `'_subMeshes'` 오류).
- `JGTexture`는 `WriteJson/ReadJson`을 직접 구현해 생성 본문을 쓸 수 없다. 그래서 `JG_GENERATED_SIMPLE_BODY`(GetType만)를 넣었다. 이전에는 `LoadObject`가 이름으로 `JGTexture`를 만들어 로드 자체는 됐지만 `GetType()`은 `JGAsset`이었다.
- 텍스처 저장(`SaveObject` → `JGTexture::WriteJson` → `ReadbackTextureImmediate`)은 메인 스레드에서만 된다. DevScene `OnInitialize`는 프레임 밖이라 "inside a frame" 경고가 나오지 않았다.
- 엔진의 assimp(`Bin/DevelopEngine/assimp-vc143-mt.dll`, import lib `ThirdParty/assimp/assimp-mt.lib`, 릴리스 /MD)에는 FBX 익스포터가 들어 있고, 임베디드 텍스처를 FBX 안에 담아 써 준다. 테스트 FBX는 이걸로 만든다.
- `.bat`에 한글 주석을 쓰면 cmd(OEM 코드 페이지)가 줄을 합쳐 "The syntax of the command is incorrect."가 난다. 배치 파일은 ASCII로 쓴다.

## 다시 검증하려면
1. `Document/Memory/tools/fbx_embedded_texture/build.bat <폴더>` 후 `<폴더>\make_embedded_texture_fbx.exe EmbeddedTextureTest.fbx` ("RESULT: PASS" 확인)
2. `devscene_import_test_snippet.cpp.txt`의 (A)~(E)를 `DevScene.cpp`에 넣고 Devkit 빌드
3. `Content/TempAsset/ImportTest` 삭제 → `JG_IMPORTTEST=<fbx 절대 경로>`로 실행 → 로그 `ImportTest : RESULT PASS (3 / 3)`
4. 끝나면 코드와 `Content/TempAsset/ImportTest`(74MB, 시작마다 로드됨), `Bin/DevelopEngine/DevScene_ImportTest_Checker.png`를 지운다

- 이 세션 동안 다른 세션이 GameFrameWorks를 고치며 빌드했다. 한 번은 그쪽 vcxproj가 없는 파일을 가리켜 C1083, 한 번은 같은 PDB 동시 쓰기로 C1041이 났다(내 솔루션 빌드와 겹침). 그 뒤 솔루션은 16/16 빌드됐다. 마지막 빌드는 `tasklist`로 다른 빌드가 없는 것을 확인하고 `Devkit.vcxproj`만 `BuildProjectReferences=false`로 했다.
