### 한 줄 요약
풀은 "고정 클래스 × 고정 개수"라 한 클래스가 차면 `nullptr`을 돌려주고 assert는 무효라 무음 크래시가 나며, 오늘 11:57 실행이 실제로 32바이트 클래스 4096/4096에서 끊겼다. 채운 것은 PSO 캐시의 프레임당 3개 누수(패딩 바이트 해시)인데 이건 병렬 세션이 고치는 중이고, 풀·GC·스마트 포인터 쪽 취약점은 그대로다.

### 확정한 사실 (상세는 분석 문서 §2~§4)
1. `HMemoryChunk::Allocate` 고갈 시 `JG_ASSERT("no memory space left.")`(항상 참) 후 `nullptr` 반환, 호출자 무검사. 1MB 초과는 `MemoryQueues.at()` `out_of_range`(기존 기록의 "2MB"는 정확히 1MB).
2. `PSharedPtr` 대입: `p = nullptr` / 빈 포인터 대입 / 빈 포인터 move 대입은 **no-op**, `p = p`는 참조 -1 후 널. `Memory.h`의 copy/move를 그대로 옮긴 코드로 컴파일 재현. `= nullptr` 대입 28곳(`JGGraphics.cpp:58` `_graphicsAPI = nullptr` 포함).
3. 스레드별 청크 100.69MB(30,768블록, 헤더 16B) 전부 상주. 메인 청크 피크 사용 548KB(0.5%), 32B 클래스만 상시 275개 사용.
4. GC: FIFO 큐를 매 프레임 2회 순회(살아 있는 객체 전부 재삽입), 파괴 순서 = 할당 순서, WeakCount 무시(5-18), GC가 프레임 시작(펜스 대기 전)에 실행.
5. 할당·해제마다 Info 로그 + 매 줄 flush → 로그의 99.97%. 프레임당 풀 연산 345회(16B 47회는 `_ITERATOR_DEBUG_LEVEL=2` 컨테이너 프록시).
6. 스레드 간 해제 경합(소유 스레드 Allocate 무잠금), `MemoryStatistics.cpp:59-61` `[0]` 인덱스 버그, `GStringTable` 정리 로직이 큐 재삽입을 안 해 사실상 무효, `_syncTaskPool` erase 없음.
