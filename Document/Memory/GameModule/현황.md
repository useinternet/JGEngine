## 1. 역할과 범위

원칙 (결정 D1–D7, §3):

| 원칙 | 내용 |
|---|---|
| 게임 코드는 엔진 밖 | 게임 고유 코드는 `<Project>/Source/<Name>`(게임 모듈) · `Source/<Name>Editor`(에디터 모듈)에 둔다. 엔진 트리는 읽기 전용 — 프로젝트 모드는 엔진 트리에 아무것도 쓰지 않는다(툴 로그 `Build/BatchFiles/jg_log.txt` 제외) |
| 엔진 단독 = 특수 경우 | "프로젝트 루트 = 엔진 루트 = 실행 위치 기준 `../../`". 산출물이 옛 툴과 바이트 동일해야 한다(회귀 기준, 검증됨) |
| 엔진을 소스로 포함 (D3) | 게임 솔루션에 엔진 프로젝트 15개가 Engine 그룹으로 들어가고 산출물은 전부 `<Project>/Bin/<Config>/` |
| 코드젠 2곳 (D4) | 게임 모듈 → `<Project>/Temp/CodeGen`, 엔진 모듈 → `<Engine>/Temp/CodeGen`(엔진 PreBuild 소관, 프로젝트 모드는 읽기만) |
| 엔진 루트 해석 (D7) | `.jgproject` 의 `EngineRoot` → 비어 있으면 환경변수 `JGENGINE_ROOT` → 둘 다 없으면 오류. `GCoreSystem::Create` 가 한 번 정해 모든 DLL 이 같은 값을 본다 |
| 호스트 (D1 · D2) | 에디터 환경 = JGEditor + `<Name>` + `<Name>Editor`. 게임 실행 = `<Name>` 만 — 호스트 미정 |

GameProject 폴더 구조 (배치 1 이 만들고 배치 2 가 채운다):

```
<Engine>/Build/BatchFiles/CreateGameProject.bat <ProjectDir> [Name]    배치 1: 템플릿 복사 + 토큰 치환 (JGBuildTool -newproject=)
<Engine>/Build/BatchFiles/GenerateGameProjectFiles.bat <ProjectDir>    배치 2: JGHeaderTool -project= → JGBuildTool -project=
<Engine>/Build/Templates/GameProject/                                  템플릿 13 파일 (Source/ 밖에 둔다)

<ProjectDir>/
  <Name>.jgproject               { "Project": { Name, EngineRoot, GameModules:[<Name>], EditorModules:[<Name>Editor] } }
  GenerateProjectFiles.bat       배치 2 래퍼 (엔진 절대경로가 박혀 있다)
  .gitignore                     Bin/ Temp/ .vs/ *.sln <Name>.lua
  <Name>.lua · <Name>.sln        생성물 (Engine 그룹 15 + <Name>/Source 그룹 2)
  Bin/<Config>/                  엔진 + 게임 산출물, zlibstatic.lib · assimp-mt.lib · assimp-vc143-mt.dll (배치 2 가 복사)
  Content/                       아직 아무도 읽지 않음 (R7)
  Source/<Name>/                 <Name>.module.json · <Name>Defines.h · <Name>Module.h/.cpp · <Name>EntryActor.h/.cpp   (H<Name>Module, JG<Name>EntryActor)
  Source/<Name>Editor/           <Name>Editor.module.json · <Name>EditorDefines.h · <Name>EditorModule.h/.cpp        (H<Name>EditorModule)
  Temp/{CodeGen,Obj,ProjectFiles}/   CodeGen 에는 게임 모듈 것 + module_system_info.json(엔진 + 게임 SharedLib)
```

폴더 = 모듈 = DLL = premake 프로젝트 이름(D5). `MyGame` → `MyGame.dll` · `_MYGAME` · `MYGAME_API` · `HMyGameModule`, `MyGameEditor.dll` · `_MYGAMEEDITOR` · `HMyGameEditorModule`.

## 5. 알려진 함정 · 주의사항

| 함정 | 내용 · 대처 |
|---|---|
| 배치는 Bin 의 exe 를 부른다 | 커밋에 `Bin/DevelopEngine/JGBuildTool.exe` · `JGHeaderTool.exe` 가 없으면 옛 exe 가 `-project=` 를 모른다. 툴 소스를 고치면 솔루션 빌드 → exe 커밋 |
| 옛 exe + 새 `BuildTemplate.lua` | 템플릿에 `ENGINE_ROOT or ""` 기본값이 있어 엔진 단독은 돈다. 프로젝트 모드는 새 exe 필수 |
| 엔진 코드젠이 있어야 한다 | `Temp/` 는 미추적. 새 클론 · Temp 삭제 뒤에는 엔진 `GenerateProjectFiles.bat` 먼저. 배치 2 는 `Temp/CodeGen/module_system_info.json` 이 없으면 안내 후 종료 코드 1 |
| 엔진에 리플렉션 헤더 · 파일이 추가되면 | vcxproj 파일 목록은 생성 시점 글롭 → 게임 프로젝트도 배치 2 재실행(안 하면 `Module_..._Code_Generation_...` unresolved) |
| 생성 2회차 회귀 기준 | 배치 2 를 연속 2회 돌리면 2회차 재작성은 `module_system_info.json` 1개만. 엔진 PreBuild 2회차는 lua 사본 · `ModuleInfoTemplate.json` · module_system_info 3개, 컴파일 대상 0 |
| 프로젝트 이름 규칙 | C++ 식별자(ASCII) · `JG` 시작 금지 · 엔진 모듈 폴더명 금지(`Game`, `GUI`, `Asset` …, 대소문자 무시). 위반은 배치 1 이 종료 코드 1. 엔진 모듈과 같으면 DLL 충돌 + premake 가 프로젝트를 합침 + 모듈 조회(타입 해시)가 실패 |
| 프로젝트는 엔진 하나에 묶인다 | `EngineRoot` 가 다른 엔진의 배치로 배치 2 를 돌리면 `Project X belongs to engine ...` 로 거부. 에이전트마다 엔진 worktree 가 다르면 프로젝트 사본도 따로 |
| 런타임 엔진 루트 | 게임 Bin 에서 실행할 때 `EngineRoot` 비어 있고 `JGENGINE_ROOT` 도 없으면 `Engine root is unknown` critical. 다른 PC 와 공유하려면 EngineRoot 를 비우고 각자 환경변수 |
| 경로 | ASCII · 공백 없이(`fs::path::string()` ANSI, premake `--file=` 따옴표 없음). 배치는 끝 `\` 를 떼서 넘긴다(`"C:\X\"` 는 argv 에서 따옴표가 풀림) |
| DevelopGame 구성 | 게임 모듈에 `DebugConfig` 를 주면 LNK2038(Core /MD vs 게임 /MDd). 템플릿 기본값 `ConfirmConfig` 유지. 게임 디버깅은 DevelopEngine 으로 |
| 리플렉션 헤더 | 헤더당 `JGCLASS` 1개, 자기 `.generation.h` 직접 include, `JGPROPERTY()` 한 줄, `JGSTRUCT` 미지원. **파일명이 엔진 리플렉션 헤더(`Actor.h`, `World.h` …)와 겹치면** 엔진 헤더가 게임의 생성 헤더를 집는다 |
| 모듈 의존 | `ModuleDependencies` 는 전이되지 않는다(`<Name>Editor` 가 GFW 헤더를 보면 `GameFrameWorks` 도 적어야 함 — 템플릿에 이미 적혀 있음). `ShutdownModule` 에서 의존 모듈 Disconnect 금지(RefCount 없음) |
| Core 헤더 변경 | `FileHelper.h` · `CoreSystem.h` 가 바뀌어 모든 모듈이 한 번 전부 재컴파일된다 |
| 스크래치 worktree | `%TEMP%` 아래 worktree 는 MSBuild 가 헤더 의존을 추적하지 않는다(MSB8029) → 헤더를 바꿨으면 `-t:Rebuild` |
| 3-way 병합 | `git show HEAD:<file>` 은 LF, 작업 트리는 CRLF → base 는 `git cat-file --filters HEAD:<file>` |
| 커밋 분리 | `CoreSystem.cpp` · `Module.cpp` 에 DevConsole 변경이 섞여 있어 파일 단위로 나눠 커밋할 수 없다 |
| 로그 | `Build/BatchFiles/jg_log.txt` · `Bin/DevelopEngine/jg_log.txt` 는 공유 파일 — 다른 세션이 덮어쓴다. 증적은 콘솔 표준 출력(crashwalk) 으로 |
| 3rd party dll 이름 | `assimp-mt.lib` 가 찾는 DLL 은 `assimp-vc143-mt.dll`. 배치 2 가 `ThirdParty/assimp/assimp-mt.dll` 을 그 이름으로 복사한다 |
| 게임 Content | `<Project>/Content` 는 아무도 읽지 않는다(`GameContentDirectory()` 빈 스텁, `/JGGame/` 토큰은 critical). 에셋은 아직 엔진 Content 만(R7) |
| 게임 실행 = 전 모듈 로드 | `codeGen()` 이 module_system_info 의 모든 SharedLib 를 시작 시 로드하므로 `<Name>Editor.dll` 도 로드된다(R5). 지금은 호스트가 JGEditor 뿐이라 드러나지 않음 |
