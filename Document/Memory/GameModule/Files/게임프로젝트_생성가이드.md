# 게임 프로젝트 생성 가이드

엔진 밖 폴더에 게임 프로젝트를 만들고, 엔진을 소스로 포함한 솔루션을 생성해 JGEditor 에서 실행하기까지.
배경과 설계 결정은 `Document/게임모듈_사전작업_분석_2026-09-29.md`.

---

## 0. 준비

| 항목 | 내용 |
|---|---|
| 도구 | Visual Studio 2022 (C++ 데스크톱 개발) |
| 경로 | 엔진 · 프로젝트 경로 모두 **ASCII** (예: `D:\Games\MyGame`). 한글 등이 든 프로젝트 경로는 배치가 처음에 거부한다. 공백은 된다 |
| 엔진 코드젠 | 엔진 루트에서 `GenerateProjectFiles.bat` 를 한 번 실행해 엔진 `Temp/CodeGen` 이 있어야 한다. 게임 프로젝트는 엔진 코드젠을 읽기만 한다 |

---

## 1. 프로젝트 만들기

```bat
<Engine>\Build\BatchFiles\CreateGameProject.bat D:\Games\MyGame
```

두 번째 인자로 이름을 따로 줄 수 있다(`CreateGameProject.bat D:\Games\Proto MyGame`). 비우면 폴더 이름.

**이름 규칙** — 이름이 폴더 · 모듈 · DLL · 클래스 이름이 된다.

| 규칙 | 이유 |
|---|---|
| C++ 식별자 (ASCII 영문 · 숫자 · `_`, 숫자로 시작 금지) | `H<Name>Module` 같은 클래스 이름이 된다 |
| `JG` 로 시작 금지 | 엔진 모듈 몫. `JG` 는 에디터 모듈이 `JGEditor` 가 된다 |
| 엔진 모듈 이름 금지 (`GUI`, `Asset`, `Graphics`, `GameFrameWorks` …) | DLL 이 같은 Bin 에서 부딪히고, 모듈 클래스 이름이 엔진 것과 겹친다 |
| `Game` 금지 (대소문자 무시) | 템플릿 엔트리 액터 `JGGameEntryActor` · `GameEntryActor.h` 가 GameFrameWorks 의 것과 같아진다 |

만들어지는 것:

```
D:\Games\MyGame\
  MyGame.jgproject             이름 · 엔진 경로 · 모듈 목록
  GenerateProjectFiles.bat     솔루션 생성 (아래 2단계)
  .gitignore                   Bin/ Temp/ .vs/ *.sln MyGame.lua
  Bin\  Content\  Temp\
  Source\MyGame\               게임 모듈 (MyGame.dll)
    MyGame.module.json · MyGameDefines.h · MyGameModule.h/.cpp · MyGameEntryActor.h/.cpp
  Source\MyGameEditor\         에디터 모듈 (MyGameEditor.dll)
    MyGameEditor.module.json · MyGameEditorDefines.h · MyGameEditorModule.h/.cpp
```

## 2. 솔루션 만들기

```bat
D:\Games\MyGame\GenerateProjectFiles.bat
```

`MyGame.sln` 이 생긴다. 엔진 프로젝트(Engine 그룹)와 게임 모듈(MyGame 그룹)이 함께 들어 있고, 산출물은 모두 `MyGame\Bin\<구성>\` 에 모인다.

**다시 실행해야 할 때** — 파일 목록은 생성 시점에 정해진다.

| 한 일 | 다시 실행 |
|---|---|
| 게임 소스 파일 추가 · 삭제 · 이름 변경 | `GenerateProjectFiles.bat` |
| 게임 헤더에 `JGCLASS` · `JGPROPERTY` · `JGENUM` 추가 · 변경 | `GenerateProjectFiles.bat` |
| 엔진에 파일 · 리플렉션 헤더 추가, 엔진 모듈 추가 · 삭제 | 엔진 `GenerateProjectFiles.bat` → 게임 `GenerateProjectFiles.bat` |
| 엔진 · 게임 소스 내용만 수정 | 필요 없음. 그냥 빌드 |

## 3. 빌드 · 실행

1. `MyGame.sln` 을 연다. 시작 프로젝트는 `JGLauncher` 로 지정돼 있다.
2. 구성 **DevelopEngine** 으로 빌드한다(엔진 · 게임 모두 Debug. 게임 코드 디버깅도 이 구성으로 한다).
3. F5. 창 제목이 `JGEditor - MyGame` 이고, `Bin\DevelopEngine\jg_log.txt` 에 다음이 보이면 정상이다.

```
Project MyGame: project D:/Games/MyGame/, engine <Engine>/
Startup MyGame Module...
MyGame entry actor entered world
Startup MyGameEditor Module...
```

에디터 메뉴 `MyGame > Reload World` 는 에디터 모듈이 붙인 예시 메뉴다.

**창 없이 확인** — 게임 모듈이 헤드리스로 뜨고 내려가는지 본다(`Bin\DevelopEngine` 에서).

```bat
JGConsole.exe module.test MyGame
```

`MyGame entry actor entered world` → `module.test: MyGame connected (error logs 0)` → `disconnected (error logs 0)` → `OK` 이고 종료 코드 0 이면 정상이다. 연결 · 해제하는 동안 `[error]` · `[critical]` 로그가 하나라도 나오면 종료 코드 1. `MyGameEditor` 는 GUI 가 없어 실패하는 것이 정상이다.

**멀티플레이로 실행** — 같은 게임을 두 번 띄운다. 호스트는 `JGLauncher.exe -host` (포트 기본 47771, 바꾸려면 `-host=<포트>`), 참가자는 `JGLauncher.exe -join=<호스트 주소>[:<포트>] -name=<이름>`. 참가자는 호스트의 월드를 따라 로드하고, 게임이 이미 진행 중이면 지금 상태를 받는다. 로그에 `JGGameInstance: hosting on port 47771` · `JGGameInstance: joining ...` · `PGameplayClientSession: joined as slot 1` 이 보이면 연결된 것이다. 호스트는 모든 인터페이스로 열어 Windows 방화벽 확인 창이 뜰 수 있다(한 기계 안에서 시험할 때는 `-bind=127.0.0.1`). 엔트리 액터는 4절의 멀티플레이 규약을 따라야 한다.

## 4. 두 모듈의 역할

| 모듈 | 로드되는 곳 | 둘 것 |
|---|---|---|
| `MyGame` | 게임 실행 · 에디터 환경 | 규칙 · 액터 · 게임 인스턴스. 시작 시 GameFrameWorks 를 연결하고 엔트리 액터를 등록한 뒤 월드를 로드한다 |
| `MyGameEditor` | 에디터 환경(JGEditor)만 | 이 게임 전용 에디터 메뉴 · 위젯. `MyGame` 에 의존 |

JGEditor 가 `.jgproject` 의 `GameModules` → `EditorModules` 순으로 연결하고, 종료는 역순으로 먼저 내린다.

**지킬 것**

| 규칙 | 이유 |
|---|---|
| 의존 모듈은 `*.module.json` 의 `ModuleDependencies` 에 **직접** 적는다 | 의존은 전이되지 않는다. `MyGame` 헤더가 GameFrameWorks 헤더를 include 하면 `MyGameEditor` 에도 `GameFrameWorks` 를 적어야 한다 |
| `ShutdownModule` 에서 의존 모듈을 Disconnect 하지 않는다 | 모듈 연결에 참조 카운트가 없다. 종료 순서는 JGEditor 와 엔진이 맡는다 |
| 모듈이 `PSharedPtr` 로 든 전역 객체는 `ShutdownModule` 에서 Reset | GC 종료 순서 문제 |
| 모든 .cpp 첫 줄 `#include "PCH/PCH.h"`, 파일은 UTF-8 | 빌드 옵션 `/utf-8` |
| 리플렉션 헤더: 헤더 하나에 `JGCLASS` 하나, 자기 `<파일>.generation.h` 를 직접 include, `JGPROPERTY()` 는 한 줄, 타입에 공백 · `::` 금지, `JGSTRUCT` 미지원 | 헤더 툴이 줄 단위로 읽는다 |
| 리플렉션 헤더 파일 이름을 엔진 것(`Actor.h`, `World.h` …)과 겹치지 않게 | 생성 헤더를 파일 이름으로 찾으므로 엔진 헤더가 게임의 생성 헤더를 집는다 |
| DevelopGame 구성에서도 `ConfirmConfig` (템플릿 기본값) | `DebugConfig` 는 엔진(Release)과 CRT 가 달라 링크되지 않는다(LNK2038) |
| 엔트리 액터(멀티플레이 규약): 규칙 · 컴포넌트 등록은 모든 기계에서, 초기 상태 구성과 시작(`JGGameMasterActor::StartGame`)은 `GetGameInstance().IsAuthority()` 일 때만 | 클라는 호스트가 보낸 초기 상태로 시작한다. `PGameMaster::Start` 를 직접 불러도 싱글은 세션이 이어받지만, 클라에서 부르면 호스트와 어긋난다. 템플릿 `OnEnterWorld` 주석이 예시다 (Server 5-2b) |

**모듈을 더 만들 때** — `Source\<Module>\<Module>.module.json` 을 두고(폴더 이름 = 파일 이름 = ModuleName), define 은 `_` + 대문자 모듈명(`_<MODULE>`), `.jgproject` 의 `GameModules` 또는 `EditorModules` 에 이름을 추가한 뒤 `GenerateProjectFiles.bat`.

## 5. 엔진 위치

`MyGame.jgproject` 의 `EngineRoot` 가 엔진을 가리킨다(배치 1 이 만든 엔진 경로를 적는다). 비워 두면 환경변수 `JGENGINE_ROOT` 를 쓴다. 둘 다 있으면 `EngineRoot` 가 이긴다.

- 다른 PC 와 프로젝트를 공유할 때: `EngineRoot` 를 비우고 각자 `JGENGINE_ROOT` 를 설정한다. `GenerateProjectFiles.bat` 안의 엔진 경로도 고친다.
- 엔진 worktree 가 여러 개일 때: 프로젝트는 `EngineRoot` 의 엔진 하나에 묶인다. 다른 엔진의 배치 파일로 생성하면 거부한다. 에이전트마다 프로젝트 사본을 쓴다.

## 6. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| `engine code generation is missing` | 엔진 루트에서 `GenerateProjectFiles.bat` |
| `Project MyGame belongs to engine ..., but this tool is in ...` | 다른 엔진의 배치 파일로 실행했다. 그 엔진 것을 쓰거나 `EngineRoot` 를 고친다 |
| `Engine root is unknown` (실행 시) | `EngineRoot` 가 비었고 `JGENGINE_ROOT` 도 없다 |
| `Project names starting with JG are reserved` · `... is an engine module name` · `Game is reserved` | 이름 규칙(1단계) |
| 게임 솔루션의 `Game` 프로젝트가 `C1083 ... Source\Runtime\Game\Main.cpp` 로 실패 | 엔진 `Game` 모듈 삭제(GameModule R4) 전에 만든 솔루션이다. 게임 `GenerateProjectFiles.bat` 를 다시 실행한다 |
| LNK1104 `zlibstatic.lib` / 실행 시 Graphics 로드 실패 | `Bin\<구성>\` 의 3rd party 파일이 없다. `GenerateProjectFiles.bat` 를 다시 실행하면 복사한다 |
| unresolved external `Module_..._Code_Generation_...` | 리플렉션 헤더를 추가하고 솔루션을 다시 만들지 않았다 |
| 헤더 툴 · 빌드 툴 오류 | 콘솔 출력과 `<Engine>\Build\BatchFiles\jg_log.txt`. 툴은 실패하면 종료 코드 1 로 끝난다 |
| `Project path must be ASCII ...` | 프로젝트 경로(폴더 이름)에 한글 등 ASCII 가 아닌 문자가 있다. 영문 경로에 만들거나 옮긴다(공백은 된다) |
| `'PreBuild.bat' is not recognized` (엔진 `GenerateProjectFiles.bat`) | 2026-09-30 이전 배치 파일이다. 지금 배치는 `NoDefaultCurrentDirectoryInExePath` 가 켜진 셸에서도, 어느 폴더에서 실행해도 돈다 |
| `/JGGame/...` 에셋이 `Game content is only available in a game project` | 엔진 단독으로 실행했다. 게임 `Bin\<구성>\JGLauncher.exe` 로 실행한다 |

## 7. 게임 에셋 (Content)

게임 에셋(`.jgasset`)은 `MyGame\Content\` 아래에 둔다. 경로는 `/JGGame/<Content 기준 상대경로>` 이고 엔진 에셋은 그대로 `/JGEngine/...` 이다.

| 경로 | 가리키는 파일 |
|---|---|
| `/JGEngine/TempAsset/Sample` | `<Engine>\Content\TempAsset\Sample.jgasset` |
| `/JGGame/Cards/Deck` | `MyGame\Content\Cards\Deck.jgasset` |

- 시작할 때 엔진 Content → 게임 Content 순으로 모든 `.jgasset` 을 올린다. 확장자를 빼면 `.jgasset` 이 붙는다.
- 엔진 단독 실행(엔진 `Bin`)에는 게임 Content 가 없다.
- **엔진 에셋 파일을 복사해 쓸 때는 `_guid` 를 바꾼다.** 같은 GUID 가 두 번 올라오면 나중 것은 `Duplicate asset guid ... with <먼저 올라온 경로>. Skipped` 오류와 함께 로드되지 않는다(먼저 것은 그대로 쓴다).
