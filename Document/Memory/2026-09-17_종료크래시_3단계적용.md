### 핵심 설계 판단 — 캐시를 "제거" 대신 "수명 관리"로
원래 계획은 `getDX12API()` 의 static 캐시를 없애고 매번 `FindModule` 하는 것이었다.
그런데 `FindModule` 이 뮤텍스를 잡는데, `HDirectXAPI::GetDevice()` 가
`DynamicDescriptionAllocator` 의 디스크립터 커밋 등 **프레임당 수천 번 도는 경로**에 있다.

그래서 캐시는 유지하되 **`PDirectX12API` 가 자기 수명을 직접 알리도록** 바꿨다.
- `HDirectXAPI::resetCache()` ← `PDirectX12API::Initialize()` 진입부
- `HDirectXAPI::invalidateCache(this)` ← `PDirectX12API::Destroy()` **말미** + 소멸자
- 둘 다 private + `friend class PDirectX12API`

외부 호출자가 무효화를 기억해야 하는 구조가 아니라 객체가 스스로 알리는 구조라 빠뜨릴 여지가 없다.
`Destroy()` 말미인 것이 중요하다 — 앞에 두면 `_commandQueue->Flush()` 등 정리 작업이 this 를 못 쓴다.

`JGGraphics.cpp` 의 전역 `GetGraphicsAPI()` 는 호출처가 에셋/씬 생성 경로뿐이라
**캐시를 완전히 제거**했다. `PJGGraphicsAPI` 가 추상 클래스라 폴백을 못 만들어서
null 이면 Critical 로그 + `JG_CHECK`.

### null 가드 21개
- void → 조기 return / 포인터 → nullptr / 값 → 기본 생성 값
- 참조 반환 7개 → 빈 폴백 인스턴스 (`find()` 가 `end()` 로 떨어져 조용히 no-op)
- 폴백은 **함수 지역 static**. 폴백 경로를 안 타면 아예 생성되지 않는다.
  const / non-const 게터 쌍이 같은 인스턴스를 보도록 접근자 함수로 감쌌다.
  (사용자 요청으로 파일 스코프 static → 함수 지역 static 으로 변경)

## [정정] "ShutdownModule 두 번 호출" 은 오진이었다

처음에 로그의 `Startup Graphics Module...` 1회 / `Shutdown Graphics Module...` 2회를 보고
중복 호출로 판단했으나 **틀렸다.**

`Source/Runtime/Asset/AssetModule.cpp` L15, L21 의 복사-붙여넣기 오타다.
Asset 모듈이 Graphics 모듈의 로그 문자열을 그대로 찍는다.
`ShutdownModule()` 은 각각 한 번씩만 호출된다.

`JGGraphics.cpp` 의 `if (_graphicsAPI != nullptr)` 가드는 여전히 유효한 방어지만
(모듈 파괴 순서가 뒤집히면 실제로 필요하다), "확정 크래시를 막고 있다"는 서술은 취소한다.

## 실제 종료 흐름 (이번 실행 로그 기준)

`GModuleGlobalSystem::Destroy()` 의 `_modulesByType` 해시 순회에서
**JGDev_Graphics 가 우연히 첫 대상**이 되었고, 그 `ShutdownModule()` 안의
수동 역순 Disconnect(Devkit → DevConsole → DevStatistics → Asset → GUI → Graphics)가
제대로 돌았다. **순서가 맞은 것은 우연이다.**

Graphics 는 `DisconnectModule("Graphics")` → `Module.cpp:172` 의 Flush 에서 파괴되고,
남은 텍스처/버퍼는 그 뒤 `Module.cpp:192` 의 Flush 에서 파괴된다.
원래 크래시는 후자에서 났다. (사용자가 준 콜스택과 일치)
