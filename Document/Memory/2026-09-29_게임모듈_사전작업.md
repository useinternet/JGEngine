## 확정 사실 (재현 · 코드로 확인)
- `UserWorkDirectory = <Project>`, `UserWorkCategories = ["Source"]` 이면 지금 BuildTool 도 `Source/` 바로 아래 폴더(재현 당시 `Game` · `Editor`, 지금 규칙으로는 `<Name>` · `<Name>Editor`)를 모듈로 수집한다(카테고리 = `Source`). 1단 구조에 스캔 수정은 필요 없다. 그룹 이름만 `MyGame/Source`.
- BuildTool Step 4(PCH 삽입)가 `EngineDirectory()/ModulePath`(BuildTool.cpp:408) 를 `recursive_directory_iterator` 로 열다 `filesystem_error` → Debug 빌드 툴이라 **"Microsoft Visual C++ Runtime Library" abort 대화상자로 무한 대기**. 배치에서 돌리면 멈춘다. Step 5(premake) · module_system_info 기록에 도달하지 못한다.
- Step 3 lua 에서 게임 모듈 경로가 엔진 루트 기준 문자열: 게임 `Editor` 의 `"Source/Editor/"` 는 **엔진 `Source/Editor` 카테고리(DevConsole · JGEditor 등)** 를 가리키고, 게임 `Game` 은 엔진 `Source/Runtime/Game` 과 같은 이름 · 같은 `Temp/CodeGen/Game/` 을 쓴다.
- HeaderTool 은 `_userModuleSet` 이 비어 게임 헤더를 전부 건너뛴다(HeaderTool.cpp:171). 정상 종료도 139.
- Core 가 StaticLib 라 `HFileHelper` 함수 static 은 DLL 마다 따로다. 런타임 루트는 파일이나 GCoreSystem 공유 상태로 풀어야 한다.
- 3rd party(`ThirdParty/zlib/zlibstatic.lib`, `ThirdParty/assimp/assimp-mt.{lib,dll}`)는 엔진 `Bin/<Cfg>/` 에 손으로 복사돼 있고 PCH 의 `#pragma comment(lib)` 로 모든 모듈이 링크한다. 게임 Bin 에도 필요하다.
- DevelopGame("엔진 Release + 게임 Debug")은 StaticLib Core 와 CRT/IDL 이 달라 LNK2038 로 링크가 안 된다(설계상). `Bin/DevelopGame` 이 없어 빌드된 적도 없다.
- 템플릿을 `Source/` 아래 두면 엔진 BuildTool 이 템플릿 모듈을 엔진 모듈로 수집한다 → `Build/Templates/GameProject/` 권장.
