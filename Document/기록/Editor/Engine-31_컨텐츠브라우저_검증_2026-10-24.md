- JGEditor 에 **Content Browser 창**(`JGContentBrowser`, 메뉴 `Windows/Content Browser`)을 만들었다. 설계도의 첫 판 범위를 모두 확인했다: 폴더 트리, 타일(텍스처는 실제 그림), 찾기, 종류 칩, 세부 칸, `.fbx` 가져오기, 데이터 테이블 더블클릭 열기, 경로 복사.

  - 빌드: 엔진 · 시험 게임 모두 오류 0 · 경고 0.
  - 자체 시험: gfw.selftest 9/9 그룹 통과, gui.selftest 10/10 통과.
  - 에디터: 매번 종료 코드 0.
- 묶음 패치: `Temp/ContentBrowser/ContentBrowser_all.patch`. 지금 메인 HEAD(008cf58)에 그대로 얹힌다. 적용 · 커밋은 엔진 총괄이 한다.

## 알게 된 것 · 남은 것 (이번에 고치지 않음)

| 무엇 | 언제 | 까닭 · 제안 |
|---|---|---|
| 메뉴로 처음 연 창이 아주 작게 뜬다(가로 약 810 · 세로 약 100 px) | 저장된 배치(`imgui.ini`)에 창 자리가 없을 때 | `JGWidget` 에 처음 크기를 정하는 길이 없다. DevConsole · 메모리 창의 옛 할 일 B-11 과 원인이 같다. 끌어서 키우거나 도킹하면 배치에 남는다. GUI 몫 일감으로 제안 |
| 타일 · 경로 막대로 폴더를 옮기면 트리가 그 폴더까지 펼쳐지지 않는다 | 접힌 폴더 안으로 들어갈 때 | HGUI 에 다음 노드를 펼쳐 두는 감싸개가 없다. 다음 판 후보 |
| DevConsole 이 시작할 때 자기 탭을 고른다 | DevConsole 과 같은 도킹 칸에 붙인 창 | 입력 줄 포커스 때문. 원래 있던 동작이고, 시험 배치에서는 DevConsole 을 닫아 피했다 |
| 긴 이름은 타일 폭에서 잘린다 | 이름이 약 19자를 넘을 때(125% 화면 배율) | 썸네일에 마우스를 올리면 풍선 도움말로 전체 이름이 보인다 |
| 가져오기는 끝날 때까지 에디터를 멈춘다 | Import 를 누를 때 | `ImportAssetFile` 이 동기 함수다. 큰 FBX 에서 문제가 보이면 따로 일감 |
| 이미 올라온 에셋을 다시 가져오면 브라우저 세부는 옛 내용이다 | 같은 원본을 두 번 Import 할 때 | GameFrameWork 안내: 파일은 새로 쓰지만 에셋 DB 는 옛 에셋을 그대로 둔다. 다시 읽기는 첫 판 범위 밖이다 |

- 팀 지침 9절(API Reference) 관련:
  - 이번 Editor 몫(`JGContentBrowser`)은 에디터 창이다. 게임 프로젝트가 쓰는 공개 C++ API 는 바뀌지 않는다.
  - 새 공개 함수 `HGUI::TreeNode` · `TreePop` · `IsItemDoubleClicked` · `ListAssetFolder` · `ImportAssetFile` 의 문서는 GUI · GameFrameWork 몫이다.
  - API Reference 문서와 모듈 README 는 아직 없다(2026-10-24 기준).
