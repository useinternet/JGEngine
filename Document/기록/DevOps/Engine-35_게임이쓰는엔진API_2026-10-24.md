## 4. 센 방법과 한계

- 엔진 헤더 226개(모듈 6)에서 클래스 · 구조체 · 열거 · 별칭 · 매크로 · 맨 위 함수 선언과 클래스 몸의 멤버 함수 이름을 모으고, 게임 쪽 코드(주석 · 문자열을 뺀 글)에서 그 이름이 나오는 횟수를 셌다.
- include 는 게임 자기 폴더에 없는 이름만 엔진 헤더로 본다. 검증 게임 폴더는 일부 소스만 있어 그 게임의 `*Defines.h` · `*EntryActor.h` 같은 자기 헤더가 없다(10개 — 엔진 API 와 상관없음).
- 멤버 함수는 `.이름(` · `->이름(` · `::이름(` 꼴만 센다(같은 클래스 안에서 `this` 없이 부르는 호출은 빠진다). 같은 이름이 여러 엔진 클래스에 있으면 "여러 클래스" 표로 나누고, 그 게임이 이름을 쓰는 엔진 클래스에만 붙였다. †는 게임 쪽에도 같은 이름의 함수가 있어 수가 섞였을 수 있다는 뜻이다.
- 템플릿 · `auto` 로 받은 객체의 형은 알 수 없어, 이름을 직접 쓰지 않는 클래스의 멤버 호출은 빠질 수 있다.
- 다시 만들기: `python -X utf8 -I Document/기록/DevOps/Engine-35_api_usage.py C:/Develop/JGEngine <json>` → `python -X utf8 -I Document/기록/DevOps/Engine-35_gen_doc.py <json> <md>` (아래 5절 표가 그 출력이다).
