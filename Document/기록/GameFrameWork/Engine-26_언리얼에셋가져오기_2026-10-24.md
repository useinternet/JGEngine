## 2. 언리얼에서 내보내기 (확인한 방법)

사용자 프로젝트(Start.uproject · Config)는 바꾸지 않았다. Python Editor Script Plugin 은 기본으로 꺼져 있다(`PythonScriptPlugin.uplugin` 의 `EnabledByDefault: false`). 그래서 내보내기 전용 프로젝트를 git 밖에 따로 만들었다.

1. `Temp/UnrealExport/JGExport/JGExport.uproject` — 모듈 없는 프로젝트이고, `Plugins` 에 `{ "Name": "PythonScriptPlugin", "Enabled": true }` 하나만 둔다.
2. Start 의 `Content/LevelPrototyping` 과 `Content/Characters/Mannequins/{Meshes,Materials,Textures,Rigs}` 를 같은 경로로 복사한다. 그러면 `/Game/...` 패키지 이름이 그대로 유지된다. 엔진 에셋(`/Engine/...`)은 어느 프로젝트에서나 읽힌다.
3. 스크립트 `Temp/UnrealExport/export_assets.py` 를 commandlet 으로 돌린다. 결과는 `Temp/UnrealExport/Out/{Meshes,Textures}` 에 나온다.

```bat
set JGEXPORT_PART=static
"C:\Program Files\Epic Games\UE_5.7\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" C:\Develop\JGEngine\Temp\UnrealExport\JGExport\JGExport.uproject -run=pythonscript -script=C:\Develop\JGEngine\Temp\UnrealExport\export_assets.py -unattended -nop4 -nosplash -NullRHI -stdout
set JGEXPORT_PART=textures
(같은 명령)
```

스크립트의 핵심(에셋 하나):

```python
task = unreal.AssetExportTask()
task.set_editor_property("object", unreal.load_asset("/Engine/BasicShapes/Cube"))
task.set_editor_property("filename", r"...\Out\Meshes\Cube.fbx")
task.set_editor_property("automated", True)
task.set_editor_property("prompt", False)
task.set_editor_property("exporter", unreal.StaticMeshExporterFBX())   # 텍스처는 unreal.TextureExporterPNG()
task.set_editor_property("options", fbx_option)                       # unreal.FbxExportOption: ascii · collision · level_of_detail = False
unreal.Exporter.run_asset_export_task(task)
```

- 실행 시간: 정적 메시 12 s, 텍스처 10 s(이 PC, 첫 실행).
- 로그: `Temp/UnrealExport/export_run.log` · `export_textures.log` · `export_skeletal.log`. 에셋마다 `JGEXPORT OK|FAIL` 한 줄이 남는다.

## 3. JGEngine 으로 가져오기 · 에디터 확인

JGEngine 에는 FBX 가져오기를 부르는 진입점(콘솔 명령 · 메뉴)이 아직 없다. 따로 된 PNG · TGA 를 텍스처 에셋으로 만드는 가져오기도 없다(FBX 에 묻힌 텍스처만 처리). 그래서 시험 게임 코드가 엔진 공개 API 를 직접 부른다.

| 단계 | 내용 |
|---|---|
| 시험 게임 | `Build\BatchFiles\CreateGameProject.bat Temp\Games\UnrealAssetTest UnrealAssetTest` → 게임 모듈 코드 수정 → `GenerateProjectFiles.bat` → 게임 솔루션 빌드(DevelopEngine, 오류 0). 게임 솔루션이 메인 트리 `Temp/CodeGen` 을 쓰므로 `MainTree.cmd -name=GameFrameWork hold` 안에서 했다 |
| 가져오기 | `Bin\DevelopEngine\JGLauncher.exe -game -nosound -ueimport=C:/Develop/JGEngine/Temp/UnrealExport/Out` → `UEIMPORT RESULT: 31/31`, 종료 0, 30 s(로그 `Temp/Games/UnrealAssetTest/Temp/verify/import3.crashwalk.txt`) |
| 메시 | `.fbx` 마다 `PFBXAssetImportArguments`(Flags = Import_StaticMesh · Import_Texture, DestPath = `Content/Unreal/Meshes/<파일 이름>/`)로 `JGFBXAssetImporter::Import` 를 부른다 |
| 텍스처 | `.png` · `.tga` 를 stb_image 로 RGBA8 로 풀고, 엔진 `WriteTexture` 와 같은 인자로 `JGTexture::Create` → `SaveObject`(`Content/Unreal/Textures/<이름>.jgasset`) |
| 보기 | 에디터(게임 Bin 의 `JGLauncher.exe`)를 띄우면 엔트리 액터가 `Content/Unreal/Meshes` 의 메시 19개를 5열로 세우고 궤도 카메라를 둔다. HUD 는 텍스처 12장을 에셋 DB(`LoadAssetAsync`)에서 받아 그림 + 이름으로 띄운다 |
| 결과 | 에셋 DB "Success Load Asset" 31(/JGGame/Unreal/), `UEVIEW mesh … requested` 19, `UEVIEW texture shown` 12, Error 0, Warning 1(원래 있던 `NOT Support Asset Path`), 종료 0, live blocks 0. 캡처 `Temp/Games/UnrealAssetTest/Temp/verify/editor_start.png` |

가져온 에셋: `Temp/Games/UnrealAssetTest/Content/Unreal/` 23 MB. 텍스처 크기는 16² ~ 2048²이고, T_ground_Moss_D(2048², 에셋 17.9 MB)가 가장 크다.

## 4. 알아 둘 것

- **스켈레탈 메시 내보내기는 commandlet 에서 안 된다.** `SkeletalMeshExporterFBX` 가 `Assertion failed: MeshObject (SkinnedMeshComponent.cpp:4677)` 로 언리얼을 멈췄다. `-NullRHI` 를 빼도 같았다. 에디터 창(UnrealEditor.exe)으로 띄워 Python 을 돌리면 될 수도 있지만 시험하지 않았다. JGEngine 가져오기도 지금은 정적 메시만 쓴다(스켈레탈 FBX 는 `Import_StaticMesh` 만 주면 바인드 포즈 정적 메시로 읽힌다).
- **메시 파일 이름은 FBX 장면 이름이다.** SM_MatPreviewMesh_01 은 `SM_MatPreviewMesh_01.SM_MatPreviewMesh_01.SM_MatPreviewMesh_01.jgasset` 이 되었다(그래도 에셋 DB 가 읽고 화면에 나옴). 그래서 FBX 마다 하위 폴더를 하나씩 썼다.
- **머터리얼 · 텍스처 연결은 없다.** 메시는 엔진 기본 머터리얼(흰색)로 보인다. 언리얼 FBX 내보내기는 텍스처를 FBX 에 묻지 않는다.
- **축 · 크기:** 언리얼 단위(cm) 그대로 들어왔다. 방향이 언리얼과 같은지는 따로 맞춰 보지 않았다.
- **라이선스:** 언리얼 엔진 · 템플릿 에셋은 Epic 라이선스다. 저장소나 게임에 넣으려면 보고함으로 사용자에게 먼저 묻는다.
