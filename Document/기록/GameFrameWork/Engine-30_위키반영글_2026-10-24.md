### 1-3. 새 절 — 문서 끝(쿠킹 검사 표 뒤)

```markdown
## 3. ListAssetFolder, ImportAssetFile (폴더 읽기 · 가져오기)

`ListAssetFolder`(폴더 읽기)와 `ImportAssetFile`(가져오기)은 에디터 컨텐츠 브라우저가 Content 폴더를 보여 주고 원본 파일을 에셋으로 만들 때 쓰는 함수다. 폴더 · 에셋 · 원본 파일은 모두 에셋과 같은 토큰 경로(`/JGEngine/…` · `/JGGame/…`)로 다룬다.

- `ListAssetFolder`는 폴더 바로 아래의 하위 폴더 · 에셋(`.jgasset`) · 원본 파일을 `HAssetFolderEntry` 목록으로 돌려준다. 순서는 폴더 → 에셋 → 원본이고, 같은 종류 안에서는 이름 순이다.
- 원본 파일은 가져오기 클래스가 받는 파일만 목록에 나온다. 가져오기 클래스는 지금 `JGFBXAssetImporter` 하나이므로 `.fbx`만 해당한다.
- 에셋 항목의 클래스 이름(`ClassName`)은 에셋 데이터베이스에 올라온 에셋만 채워진다.
- `ImportAssetFile`은 원본 파일의 확장자로 가져오기 클래스를 골라 저장 폴더에 에셋을 쓰고, 새로 쓴 에셋의 토큰 경로를 `HAssetImportResult`로 돌려준다. 새 에셋은 곧바로 에셋 데이터베이스에 로드를 요청한다.
- 메시 · 텍스처 에셋은 만들 때 GPU 리소스를 만들므로, 가져오기는 Graphics가 연결된 프로세스(에디터)에서만 동작한다.
```

쓴 까닭(넣지 않음): 위키 규칙대로 개념 · 관계만 적고, 토큰이 틀릴 때의 반환값 · 한글 이름 건너뜀 · 다시 가져오기 동작 같은 세부는 넣지 않았다. 그런 세부는 GameFrameWork API Reference(Engine-40)의 주의사항 칸 몫이다. 그림은 새로 만들지 않았다 — 0-1 그림(에셋 데이터베이스)과 1-1 그림(메시 · 텍스처 에셋 · `JGFBXAssetImporter`)이 이미 이 흐름의 두 끝을 보여 준다.
