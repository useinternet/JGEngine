# 설계 방안 B 상세 — 시뮬레이션 / 프레젠테이션 2계층

작성 2026-09-28. **엔진 시스템 설계.** 콘텐츠(규칙 데이터·행동 정의)는 범위 밖.
전제: 엔진 레이어 / 게임 레이어. 게임 프레임워크 = 엔진 레이어. 방안 선정 근거는 `게임프레임워크_설계방안_요약_2026-09-28.md`.

## 1. 한눈에

```
┌─ 게임 레이어 ──────────────────────────────────────────────────────────┐
│  MyGame 모듈:  상태 필드 · 명령 · 효과 · 순서 정책 · 평가 함수 │ 연출 액터 · UI    │
└────────────┬──────────────────────────────────────────────────┬────────┘
             │ 등록(StartupModule) / 파생                         │ 파생
┌─ 엔진 레이어 ┴──────────────────────────────────────────────────┴────────┐
│                                                                          │
│  ┌─ Simulation 커널 (Core 만 의존) ─────┐  이벤트 로그 ▶  ┌─ Presentation ──────────┐ │
│  │ 상태 컨테이너 (값 타입, 스냅샷)      │ ─────────────▶ │ World / Actor / Component │ │
│  │ 명령 → 검증 → 실행 → 이벤트          │                │ SimBinding (ID ↔ Actor)   │ │
│  │ 효과 해결 큐 · 트리거 정렬            │ ◀───────────── │ Sequencer (연출 큐)       │ │
│  │ 턴 상태 기계 · 선택 대기              │  명령 ◀         │ CommandBuilder (입력·피킹) │ │
│  │ 보드 추상화 · 합법 수 열거            │                │ Camera · DevView(ImGui)   │ │
│  │ 스냅샷 · 리플레이 · 체크섬 · 직렬화   │  상태 읽기 전용 ▶│                           │ │
│  └──────────────────────────────────────┘                └───────────────────────────┘ │
│           ▲ 합법 수 · 상태 복사                                     ▲                  │
│  ┌─ AI ───┴───────────┐                     ┌─ Graphics · GUI · Asset ─┴──┐            │
│  │ 탐색 · 규칙 에이전트 │                     │ 렌더 핸들 · ImGui · 에셋 DB  │            │
│  └────────────────────┘                     └─────────────────────────────┘            │
│  ┌─ Core ────────────────────────────────────────────────────────────────────────┐    │
│  │ 리플렉션 · JSON · 메모리 · 모듈 · 스케줄러 · 수학                                 │    │
│  └───────────────────────────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

원칙 세 줄.
- 상태를 바꾸는 길은 **명령 하나**뿐이다. 프레젠테이션은 상태를 읽기만 한다.
- 커널은 **프레임을 모른다.** 명령이 올 때만 움직인다. 프레젠테이션만 프레임 틱을 탄다.
- 커널은 **Core 만 의존**한다. 그래서 그래픽 없이 돌고, AI 와 테스트가 같은 코드를 쓴다.

## 2. 모듈 구성

| 모듈 | 계층 | 의존 | 역할 | 현재 |
|---|---|---|---|---|
| `Core` | 엔진 | — | 리플렉션 · JSON · 메모리 · 모듈 · 스케줄러 | 있음 |
| `Simulation` | 엔진 | Core | 시뮬레이션 커널 (§3) | **신규**. SharedLib |
| `GameFrameWorks` | 엔진 | Core · Asset · Graphics · GUI · Simulation | 프레젠테이션 (§4) | 빈 StaticLib → SharedLib 전환 |
| `AI` | 엔진 | Core · Simulation | 탐색 · 규칙 에이전트 프레임 | 빈 모듈 |
| `MyGame` | 게임 | Simulation · GameFrameWorks · AI | 규칙 · 연출 · UI | 게임 프로젝트 |

```
        MyGame ──────────────┬────────────┬──────────┐
                             ▼            ▼          ▼
                       GameFrameWorks ──► Simulation ◄── AI
                        │  │  │              │
                        ▼  ▼  ▼              ▼
                  Graphics GUI Asset ──────► Core
```

의존은 아래로만. `Simulation` 이 Graphics/GUI 를 포함하는 순간 헤드리스가 깨지므로 **`module.json` 의존 목록으로 강제**한다.

## 3. Simulation 커널

### 3-1. 구성

```
┌─ Simulation ─────────────────────────────────────────────────────────┐
│                                                                       │
│  ┌─ 상태 (HSimState, 값 타입) ─────────────────────────────────────┐  │
│  │ 엔티티 레지스트리 (세대 ID)   컴포넌트 테이블 (게임이 타입 정의)  │  │
│  │ 영역(Zone) 컬렉션            보드 (IBoard 구현 상태)             │  │
│  │ 턴 상태 (라운드·페이즈·순서)  선택 대기 (PendingChoice)           │  │
│  │ 난수 스트림 상태              시퀀스 번호 · 체크섬                │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                       │
│  ┌─ 규칙 처리 ────────────────────────────────────────────────────┐  │
│  │ 명령 핸들러 레지스트리  → 검증(Validate) / 실행(Execute)          │  │
│  │ 효과 해결 큐 (addToTop / addToBottom)                           │  │
│  │ 트리거 디스패처 (이벤트 → 리스너 수집 → 결정론 정렬)              │  │
│  │ 수치 파이프라인 (게임이 단계 정의: 기본 → 가산 → 배율 → 최종)      │  │
│  │ 턴 상태 기계 + ITurnOrderPolicy                                  │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                       │
│  ┌─ 서비스 ───────────────────────────────────────────────────────┐  │
│  │ 스냅샷 스택 (되돌리기)   명령 로그 (리플레이)   직렬화 (저장)      │  │
│  │ 체크섬 (결정론 검증)     합법 수 열거          헤드리스 드라이버   │  │
│  └────────────────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────┘
```

### 3-2. 상태 컨테이너

| 항목 | 내용 |
|---|---|
| 형식 | 값 타입. `JGObject`/`PSharedPtr` 없음. 복사 = 스냅샷 |
| 엔티티 | `HEntityId { Index, Generation }`. 죽은 참조는 세대 불일치로 감지 |
| 컴포넌트 | 게임이 `JGSTRUCT` 로 타입 정의, 커널이 타입별 테이블 보관. 직렬화는 리플렉션 |
| 영역 | 엔티티 ID 의 순서 있는 컬렉션. 게임이 영역 종류를 정의 |
| 보드 | `IBoard` 구현체의 상태. 없음 / 사각 격자 / 육각 격자 / 자유 공간 |
| 턴 | 라운드 · 페이즈 · 행동 순서 · 현재 행동자 |
| 선택 대기 | 해결 중 입력이 필요할 때 커널이 채우는 슬롯. 누가 · 무엇을 · 후보 목록 · 미해결 효과 큐 |
| 난수 | 스트림 상태(시드 · 호출 횟수)가 상태의 일부. 외부 난수 금지 |
| 검증 | `Checksum()` — 같은 명령열이면 같은 값 |

### 3-3. 명령 파이프라인

```
   HCommand (직렬화 가능)
        │
        ▼
  ┌──────────┐  실패 사유   ┌────────────────────┐
  │ Validate │ ──────────▶ │ 프레젠테이션에 반환 │
  └────┬─────┘             └────────────────────┘
       │ 통과
       ▼
  ┌──────────┐  스냅샷 push
  │ Execute  │ ──► 명령 핸들러 ──► 효과 큐에 적재
  └────┬─────┘
       ▼
  ┌──────────────┐ 큐가 빌 때까지 반복
  │ 효과 해결 큐  │ ──► 효과 1개 실행 ──► 상태 변경 ──► 이벤트 발행 ──► 트리거 수집·정렬 ──► 큐에 적재
  └────┬─────────┘
       │ 선택 대기 발생 시 ─► 큐를 상태에 보존하고 중단 ─► PendingChoice 노출
       ▼
  HList<HSimEvent>  (원인 명령 번호 · 깊이 포함)  +  명령 로그 append
```

- 명령은 **플레이어 · AI · 리플레이 · 테스트가 모두 같은 입구**로 넣는다.
- `EnumerateLegal(state, actor)` 가 UI 하이라이트 · AI · 테스트의 공통 근거다.

### 3-4. 효과 해결과 트리거

| 규칙 | 내용 |
|---|---|
| 큐 | FIFO. 끼어들기는 `addToTop` |
| 트리거 정렬 | 명시 우선순위 → 행동자 소유 먼저 → 부여 시각 오름차순. 문서화된 고정 규칙 |
| 대체 효과 | 큐가 아니라 수치 파이프라인 단계로 처리 |
| 수치 파이프라인 | 게임이 단계 목록을 정의, 커널이 단계 순서대로 수정자를 적용 |
| 선택 대기 | 효과가 입력을 요구하면 큐를 상태에 보존하고 반환. `ResolveChoice` 명령으로 재개 |

### 3-5. 턴 상태 기계

```
  RoundStart ──► OrderResolve ──► ActorTurn ──► (다음 행동자) ──► RoundEnd ──► RoundStart
                     │                 │
              ITurnOrderPolicy    PendingChoice 로 중단 가능
              (게임이 구현)        (선택 후 같은 위치에서 재개)
```

- 페이즈 골격은 커널, **순서 결정은 정책 인터페이스**로 게임이 구현한다(고정 순서 · 이니셔티브 · 라운드 이니셔티브 …).
- 페이즈 전환도 이벤트로 발행되어 프레젠테이션이 연출한다.

### 3-6. 보드 추상화

| 인터페이스 | 제공 |
|---|---|
| `IBoard` | 좌표 타입 · 거리 · 이웃 · 경로 탐색 훅 · 시야 훅 · 점유 조회 |
| 구현 | `None`(카드 전투처럼 보드 없음) · `SquareGrid` · `HexGrid` · `FreeSpace` |
| 상태 | 보드 상태는 `HSimState` 의 일부(값 타입). 규칙은 `IBoard` 질의만 사용 |

### 3-7. 서비스

| 서비스 | 동작 |
|---|---|
| 스냅샷 · 되돌리기 | 명령마다 상태 복사 push. 되돌리기 = pop |
| 리플레이 | 초기 상태 + 명령 로그 재적용 |
| 저장 · 로드 | 상태 JSON (리플렉션) + 명령 로그 |
| 체크섬 | 결정론 회귀 테스트의 기준값 |
| 합법 수 열거 | 명령 핸들러가 후보 생성 |
| 헤드리스 드라이버 | `JGConsole` 에서 명령 스크립트 실행 → 체크섬 · 통계 |

### 3-8. 결정론 규칙

1. 상태 밖의 변수 금지(전역 · static · 시스템 시간).
2. 난수는 상태 안의 스트림만. 자체 구현(STL 분포는 구현마다 달라 이식 결정론 불가).
3. 규칙 수치는 정수.
4. 컨테이너 순회 순서 고정(해시맵 순회로 결과가 갈리면 안 됨).
5. 프레임 · 시간 · 렌더 상태를 규칙에서 참조 금지.

## 4. Presentation 계층

### 4-1. 구성

```
┌─ GameFrameWorks ─────────────────────────────────────────────────────┐
│  World / Actor / Component  (씬 트리 · 트랜스폼 · 프리팹 · 렌더 핸들) │
│  SimBinding      HEntityId ↔ Actor 테이블. 상태 읽기 전용 접근         │
│  Sequencer       이벤트 → 연출 단계 큐. 인과 기반 묶음 · 병렬/직렬 · 스킵 │
│  CommandBuilder  피킹 · 타깃 선택 모드 · 선택 대기 UI → HCommand        │
│  Camera          보드 궤도 · 고정 · 포커스                              │
│  DevView (ImGui) 상태 인스펙터 · 이벤트 로그 · 되돌리기 · 체크섬          │
└───────────────────────────────────────────────────────────────────────┘
```

### 4-2. 바인딩

- 엔티티 생성/파괴 **이벤트**로 Actor 를 만들고 지운다. 상태를 폴링하지 않는다.
- Actor 는 표시용 값(체력 바 등)을 상태에서 읽되 쓰지 않는다.
- 연출 상태(피격 리액션 · 호버 · 드래그)는 Actor 의 것. 커널 상태와 분리.

### 4-3. 시퀀서

```
  이벤트 로그 ──► 인과(원인 명령 · 깊이)로 묶기 ──► 연출 단계 생성 ──► 큐
                                                                    │ 프레임 틱
      정책: 직렬/병렬 · 페이싱 · 스킵 · 연출 중 입력(차단/버퍼/스킵)     ▼
                                                            Actor 애니메이션 · 카메라 · UI
```

- 이벤트에는 연출에 필요한 정보(이전/이후 값 · 원인 · 위치)가 있어야 한다. **이벤트 스키마는 시퀀서 요구로 정한다.**
- 선택 대기가 뜨면 큐를 비운 뒤 UI 로 넘긴다.

### 4-4. 프레임 타이밍

```
  프레임:  |----tick----|----tick----|----tick----|----tick----|
  Sim   :  [명령 A 실행]                          [명령 B 실행]
           (한 번에 완료, 이벤트 30개)              (선택 대기로 중단)
  Pres  :  ▶ 단계1 ▶ 단계2 ▶▶ 단계3(병렬) ▶ 단계4 ...  ▶ 선택 UI ...
```

커널은 명령 시점에 즉시 끝난다. 프레젠테이션이 그 결과를 여러 프레임에 걸쳐 푼다. 이것이 규칙과 연출의 타이밍 결합을 없애는 핵심이다.

## 6. 엔진 ↔ 게임 확장점

| 확장점 | 엔진이 제공 | 게임이 구현 | 등록 |
|---|---|---|---|
| 상태 필드 | 컴포넌트 테이블 · 직렬화 | `JGSTRUCT` 타입들 | 리플렉션 자동 |
| 명령 | 파이프라인 · 로그 · 리플레이 | 명령 종류 · 검증 · 실행 핸들러 | 레지스트리(`PName`) 또는 파생 클래스 자동 등록(`GetChildClasses`) |
| 효과 | 해결 큐 · 정렬 · 선택 대기 | 효과 종류 | 레지스트리 |
| 트리거 · 수치 단계 | 디스패처 · 파이프라인 | 조건 · 단계 목록 | 레지스트리 |
| 턴 순서 | 상태 기계 · 페이즈 | `ITurnOrderPolicy` | 인스턴스 주입 |
| 보드 | `IBoard` · 기본 구현 3종 | 선택 또는 파생 | 인스턴스 주입 |
| AI | 합법 수 · 탐색 골격 | 평가 함수 · 행동 정책 | 인스턴스 주입 |
| 연출 | Actor/Component · 시퀀서 · 바인딩 | 연출 액터 · 단계 종류 · UI | 파생 클래스 |
| 이벤트 | 기본 필드(원인 · 깊이 · 주체 · 대상) | 게임 이벤트 종류 · 추가 필드 | 리플렉션 |

등록 시점은 게임 모듈의 `StartupModule` 이다. 리플렉션이 파생 클래스를 열거할 수 있으므로(`JGClass::GetChildClasses`) 대부분 자동 등록이 가능하다.

---

## 7. 게임 레이어 한 모듈의 모습

```
MyGame/
  Sim/     상태 필드(JGSTRUCT) · 명령 · 효과 · 트리거 · 수치 단계 · 순서 정책 · 평가 함수
  View/    연출 액터 · 연출 단계 · UI · 카메라 설정
  Content/ 정의 데이터 (범위 밖)
  MyGameModule.cpp  StartupModule 에서 등록 · 보드 종류 선택 · 런치
```

`Sim/` 은 `Simulation` 만, `View/` 는 `GameFrameWorks` 만 포함하도록 폴더 단위로 의존을 지킨다.

---

## 8. 열린 설계 질문

| # | 질문 | 선택지 | 기본안 |
|---|---|---|---|
| 1 | 컴포넌트 테이블 저장 형식 | 타입별 `HList<T>` + ID 인덱스 / 리플렉션 기반 범용 테이블 | 타입별 `HList<T>` (템플릿). 범용 테이블은 툴 전용 |
| 2 | 명령·효과 등록 | `PName` 레지스트리 / 파생 클래스 자동 열거 | 둘 다. 자동 열거가 기본, 레지스트리는 데이터 주도용 |
| 3 | 이벤트 기본 필드 | 최소(종류·주체·대상) / 연출용 확장(이전·이후·원인·위치) | 확장. 시퀀서가 요구 |
| 4 | 선택 대기의 큐 보존 | 상태 안 직렬화 / 드라이버 메모리 | 상태 안. 저장·리플레이 포함 |
| 5 | 보드 인터페이스 범위 | 좌표·거리만 / 경로·시야까지 | 좌표·거리·이웃 + 경로·시야는 훅 |
| 6 | 스냅샷 빈도 | 명령마다 / 턴마다 | 명령마다(상태가 작음) |

---

## 9. 착수 순서

1. **커널 골격**: 상태 컨테이너 · 세대 ID · 명령 파이프라인 · 이벤트 · 스냅샷 · 체크섬 · 헤드리스 드라이버. 합격: 같은 명령열 → 같은 체크섬.
2. **효과·트리거·턴**: 해결 큐 · 정렬 규칙 · 선택 대기 · 턴 상태 기계 · 순서 정책 인터페이스.
3. **프레젠테이션 연결**: 바인딩 · 시퀀서(ImGui 로 먼저) · 명령 빌더. 합격: 이벤트만으로 연출 가능, 커널 코드 무변경.
4. **보드 · AI**: `IBoard` 3종 · 합법 수 열거 · 탐색 골격.
5. 게임 레이어 첫 검증 모듈로 확장점 전부 통과.

## 10. 게임 모듈이 보는 API 형식

두 면으로 나뉜다. **게임이 구현·등록하는 면**(엔진이 기반 클래스·인터페이스 제공)과 **게임이 호출하는 면**(드라이버 하나). 이름은 가칭.

### 10-1. 게임이 구현하는 면

```cpp
// 상태 필드. 값 타입. 커널이 타입별 테이블로 보관하고 리플렉션으로 직렬화한다
JGSTRUCT()
struct HMyData : public IJsonable
{
    JGPROPERTY() int32 ValueA;
    JGPROPERTY() int32 ValueB;
};

// 명령 핸들러. 검증과 실행을 분리한다
JGCLASS()
class JGMyCommand : public JGCommandHandler
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetKind() const override;                                                        // "MyCommand"
    virtual bool  Validate(const HSimContext& ctx, const HCommand& cmd, PString* outReason) const override;
    virtual void  Execute(HSimContext& ctx, const HCommand& cmd) override;                         // 효과를 큐에 넣거나 상태를 바꾸고 이벤트 발행
    virtual void  Enumerate(const HSimContext& ctx, HEntityId actor, HList<HCommand>& out) const override;  // 합법 수
};

// 효과. 큐에서 하나씩 해결된다
JGCLASS()
class JGMyEffect : public JGEffect
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetKind() const override;
    virtual void  Resolve(HSimContext& ctx, const HEffectRequest& req) override;
};

// 트리거. 이벤트에 반응해 효과를 큐에 넣는다. 정렬은 커널 규칙
JGCLASS()
class JGMyTrigger : public JGTrigger
{
    JG_GENERATED_CLASS_BODY
public:
    virtual bool Matches(const HSimContext& ctx, const HSimEvent& ev) const override;
    virtual void React(HSimContext& ctx, const HSimEvent& ev) override;
};

// 턴 순서 정책. 라운드마다 행동 순서를 만든다
class PMyTurnOrder : public ITurnOrderPolicy
{
public:
    virtual void BuildOrder(const HSimState& state, HList<HEntityId>& outOrder) const override;
};

// AI 평가 (선택)
class PMyEvaluator : public IEvaluator
{
public:
    virtual int32 Evaluate(const HSimState& state, HEntityId actor) const override;
};
```

핸들러·효과·트리거가 받는 `HSimContext` 는 커널이 만들어 넘기는 **작업 창구**다. 게임 코드가 상태에 손대는 방법은 이것뿐이다.

```cpp
struct SIMULATION_API HSimContext
{
    HSimState& State;                                    // Get<T>(id) · Add<T>(id) · Remove<T>(id) · Each<T>(fn) · Zone(name) · Board()
    void Enqueue(const HEffectRequest& req);             // 큐 뒤 (addToBottom)
    void EnqueueFront(const HEffectRequest& req);        // 큐 앞 (addToTop)
    void Emit(const HSimEvent& ev);                      // 이벤트 로그. 원인 명령·깊이는 커널이 채운다
    HRandomStream& Rng(ERngStream stream);               // 상태 안의 스트림만
    void RequestChoice(const HChoiceRequest& req);       // 해결 중단 → 선택 대기
};
```

### 10-2. 게임이 호출하는 면

```cpp
class SIMULATION_API PSimulation : public IMemoryObject
{
public:
    // 설정 — 게임 모듈 StartupModule 에서 한 번
    template<class T> void RegisterAllFromReflection();         // JGClass::GetChildClasses 로 파생 클래스 자동 등록
    void RegisterHandler(PSharedPtr<JGCommandHandler> handler); // 수동 등록도 가능
    void RegisterEffect(PSharedPtr<JGEffect> effect);
    void RegisterTrigger(PSharedPtr<JGTrigger> trigger);
    void SetTurnOrderPolicy(PSharedPtr<ITurnOrderPolicy> policy);
    void SetBoard(EBoardKind kind);
    void Start(const HSimState& initial);

    // 플레이 — 프레젠테이션 · AI · 리플레이 · 테스트가 전부 같은 입구
    ESubmitResult Submit(const HCommand& cmd, HList<HSimEvent>& outEvents, PString* outReason = nullptr);
    //   Rejected(검증 실패) / Executed(완료) / PendingChoice(선택 대기로 중단)
    const HSimState&       GetState() const;                    // 읽기 전용
    void                   EnumerateLegal(HEntityId actor, HList<HCommand>& out) const;
    const HChoiceRequest*  GetPendingChoice() const;            // 선택 대기 중이면 내용, 아니면 null

    // 되돌리기 · 저장 · 검증
    bool      Undo();                                           // 마지막 명령 취소 (스냅샷 pop)
    HSimState Snapshot() const;                                 // AI 시뮬레이션용 복사
    void      Restore(const HSimState& state);
    bool      Save(const PString& path) const;                  // 상태 + 명령 로그
    bool      Load(const PString& path);
    bool      Replay(const HList<HCommand>& log, HList<HSimEvent>& outEvents);
    uint64    Checksum() const;

    // 알림 (선택). Submit 반환값과 같은 내용을 구독으로도 받을 수 있다
    HMulticastDelegate<const HList<HSimEvent>&> OnEvents;
};
```

### 10-3. 게임 모듈에서의 사용 흐름

```cpp
// 시작
void HMyGameModule::StartupModule()
{
    Sim = Allocate<PSimulation>();
    Sim->RegisterAllFromReflection<JGCommandHandler>();
    Sim->RegisterAllFromReflection<JGEffect>();
    Sim->RegisterAllFromReflection<JGTrigger>();
    Sim->SetTurnOrderPolicy(Allocate<PMyTurnOrder>());
    Sim->SetBoard(EBoardKind::Hex);
    Sim->Start(MakeInitialState());
}

// 플레이 (프레젠테이션 쪽 한 프레임 안)
HCommand cmd = CommandBuilder.Build(pickResult);
HList<HSimEvent> events;
PString reason;
switch (Sim->Submit(cmd, events, &reason))
{
case ESubmitResult::Rejected:
    UI.ShowReason(reason);
    break;
case ESubmitResult::Executed:
    Sequencer.Enqueue(events);
    break;
case ESubmitResult::PendingChoice:
    Sequencer.Enqueue(events);                  // 중단 전까지의 이벤트는 연출
    UI.ShowChoice(*Sim->GetPendingChoice());    // 선택 후 ResolveChoice 명령을 다시 Submit
    break;
}
```

헤드리스(`JGConsole`)에서는 `CommandBuilder` 자리에 스크립트나 AI 가 오고 나머지는 같다.
