## 1. 인터페이스 (엔진이 정의, 게임 또는 엔진이 구현)

리플렉션 자동 등록이 필요한 것은 `JGObject` 파생 기반 클래스(`JG*`)로, 그렇지 않은 것은 순수 인터페이스(`I*`, `IMemoryObject` 뿌리)로 둔다.

| 인터페이스 | 역할 | 구현자 | 핵심 메서드 |
|---|---|---|---|
| `JGCommandHandler` | 명령 종류 하나. 검증 · 실행 · 합법 수 열거 | 게임 (엔진 내장: `EndTurn`, `ResolveChoice`) | `GetKind` · `Validate` · `Execute` · `Enumerate` |
| `JGEffect` | 효과 종류 하나. 큐에서 하나씩 해결. 상태 변경 · 이벤트 발행 · 추가 효과 · 선택 요청 | 게임 (엔진 내장: `SpawnEntity`, `DestroyEntity`, `MoveToZone`, `SetBoardPosition`, `EndTurn`) | `GetKind` · `Resolve` |
| `JGTrigger` | 이벤트에 반응해 효과를 큐에 넣는다. 정렬 키(우선순위 · 소유자) 제공 | 게임 | `GetPriority` · `GetOwner` · `Matches` · `React` |
| `JGModifier` | 수치 파이프라인의 한 단계에서 값을 바꾼다 | 게임 | `GetStage` · `Applies` · `Apply` |
| `ITurnOrderPolicy` | 라운드마다 행동 순서를 만든다 | 게임 (엔진 기본: 고정 순서 · 키 정렬) | `BuildOrder` |
| `IBoard` | 공간 질의. 좌표 · 거리 · 이웃 · 점유 · 경로 · 시야 훅 | 엔진 4종. 게임 파생 가능 | `Distance` · `Neighbors` · `IsOccupied` · `FindPath` · `HasLineOfSight` |
| `IEvaluator` | AI 용 상태 평가 | 게임 | `Evaluate` |
| `IAgent` | 행동자 하나의 명령 선택. 입력 대리 · AI · 스크립트 | 엔진 기본 2종. 게임 | `ChooseCommand` · `ChooseOption` |
| `ISimObserver` | 명령 실행 결과(이벤트 목록)와 상태 변경 구독 | 프레젠테이션 · 로그 · 테스트 | `OnEvents` · `OnStateReplaced` |
| `IStateMigrator` | 저장 버전 간 상태 변환 | 게임 (선택) | `Migrate` |
| `IComponentTable` | 컴포넌트 타입별 저장소의 공통 면. 복사 · 직렬화 · 엔티티 파괴 시 정리 | 엔진 (`HComponentTable<T>`) | `Clone` · `Remove` · `WriteJson` · `ReadJson` |
| `JGPresentationStep` | 이벤트 하나를 연출 단계로 바꾼다. 재생 · 완료 판정 · 스킵 | 게임 | `Accepts` · `Begin` · `Tick` · `IsDone` · `Skip` |

## 4. 게임 모듈 구현 가이드

순서대로 따라가면 헤드리스에서 돌아가는 게임 규칙 → 연출 연결까지 간다. 코드는 골격만이며 `My*` 는 게임이 붙일 이름이다.

### 4-0. 모듈 만들기

```
MyGame/
  MyGame.module.json        의존: Simulation, GameFrameWorks, AI. SharedLib
  MyGameModule.h/.cpp       IModuleInterface
  Sim/                      Simulation 만 포함
  View/                     GameFrameWorks 만 포함
```

규칙: `Sim/` 아래 파일은 Graphics · GUI 헤더를 포함하지 않는다. 그래야 같은 규칙 코드가 `JGConsole` 에서 돈다.

### 4-1. 상태 필드 정의

```cpp
// Sim/MyComponents.h
JGSTRUCT()
struct HMyStat : public IJsonable
{
    JGPROPERTY() int32 Current;
    JGPROPERTY() int32 Max;
};

JGSTRUCT()
struct HMyOwnership : public IJsonable
{
    JGPROPERTY() HEntityId Owner;
    JGPROPERTY() int32     Team;
};
```

- 값 타입만. 포인터 · `PSharedPtr` · 문자열 대신 `PName`/ID.
- 다른 엔티티 참조는 `HEntityId`.
- 시작 시 `Sim->RegisterComponent<HMyStat>()` 로 테이블을 만든다(4-9).

### 4-2. 명령 정의와 핸들러

```cpp
// Sim/MyCommands.h
JGCLASS()
class JGMyActCommand : public JGCommandHandler
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetKind() const override
    {
        return PName("MyAct");
    }

    virtual bool Validate(const HSimContext& ctx, const HCommand& cmd, PString* outReason) const override
    {
        if (ctx.State.Turn.CurrentActor != cmd.Actor)
        {
            *outReason = "not your turn";
            return false;
        }
        if (ctx.State.Has<HMyStat>(cmd.Targets[0]) == false)
        {
            *outReason = "invalid target";
            return false;
        }
        return true;
    }

    virtual void Execute(HSimContext& ctx, const HCommand& cmd) override
    {
        HEffectRequest req;
        req.Kind    = PName("MyEffect");
        req.Subject = cmd.Actor;
        req.Target  = cmd.Targets[0];
        req.Params  = cmd.Params;
        ctx.Enqueue(req);                 // 상태를 직접 바꿔도 되지만 효과로 넣으면 트리거 · 연출 · 되감기가 균일해진다
    }

    virtual void Enumerate(const HSimContext& ctx, HEntityId actor, HList<HCommand>& out) const override
    {
        ctx.State.Each<HMyStat>([&](HEntityId id, const HMyStat&)
        {
            HCommand cmd;
            cmd.Kind  = GetKind();
            cmd.Actor = actor;
            cmd.Targets.push_back(id);
            out.push_back(cmd);
        });
    }
};
```

- `Validate` 는 상태를 바꾸지 않는다(`const`). 실패 사유는 UI 에 그대로 보여 준다.
- `Execute` 는 `ctx` 로만 상태에 접근한다. 전역 · static · 시간 · 외부 난수 금지.
- `Enumerate` 가 UI 하이라이트 · AI · 테스트의 공통 근거다. 반드시 구현한다.

### 4-3. 효과

```cpp
// Sim/MyEffects.h
JGCLASS()
class JGMyEffect : public JGEffect
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetKind() const override
    {
        return PName("MyEffect");
    }

    virtual void Resolve(HSimContext& ctx, const HEffectRequest& req) override
    {
        HMyStat& stat = ctx.State.Get<HMyStat>(req.Target);
        int32 before  = stat.Current;
        int32 amount  = ctx.Compute(PName("MyValue"), req.Subject, req.Target, req.Params[0]);   // 수치 파이프라인 (4-6)
        stat.Current  = HMath::Max(0, before - amount);

        HSimEvent ev;
        ev.Kind    = PName("MyStatChanged");
        ev.Subject = req.Subject;
        ev.Target  = req.Target;
        ev.Before  = before;
        ev.After   = stat.Current;
        ctx.Emit(ev);                     // 원인 명령 번호 · 깊이는 커널이 채운다

        if (stat.Current == 0)
        {
            HEffectRequest destroy;
            destroy.Kind   = PName("DestroyEntity");   // 엔진 내장 효과
            destroy.Target = req.Target;
            ctx.Enqueue(destroy);
        }
    }
};
```

- 효과 하나는 "한 가지 상태 변화 + 그 이벤트" 로 작게 만든다. 연쇄는 큐에 넣는다.
- 이벤트에는 연출에 필요한 값(이전 · 이후 · 원인)을 채운다. 나중에 채우려면 효과를 전부 다시 연다.

### 4-4. 선택 대기가 필요한 효과

```cpp
virtual void Resolve(HSimContext& ctx, const HEffectRequest& req) override
{
    if (req.HasChoice() == false)
    {
        HChoiceRequest choice;
        choice.Chooser    = req.Subject;
        choice.Kind       = PName("MyPick");
        choice.Min        = 1;
        choice.Max        = 1;
        ctx.State.Zone(PName("MyZone")).CollectTo(choice.Candidates);
        ctx.RequestChoice(choice);        // 커널이 큐를 상태에 보존하고 Submit 을 PendingChoice 로 반환
        return;
    }

    HEntityId picked = req.Choice[0];     // ResolveChoice 명령이 오면 커널이 채워서 같은 효과를 다시 부른다
    // ... picked 로 진행
}
```

- 재진입 패턴이다. 첫 호출에서 요청하고 반환, 두 번째 호출에서 결과를 쓴다.
- `ResolveChoice` 명령은 엔진 내장. 후보 밖 선택 · 개수 위반은 커널이 거부한다.
- 저장 · 되돌리기 · 리플레이가 선택 대기 중에도 동작한다(큐가 상태 안에 있으므로).

### 4-5. 트리거

```cpp
// Sim/MyTriggers.h
JGCLASS()
class JGMyOnChanged : public JGTrigger
{
    JG_GENERATED_CLASS_BODY
public:
    virtual int32 GetPriority() const override
    {
        return 0;                          // 낮을수록 먼저. 같으면 행동자 소유 → 부여 시각
    }

    virtual bool Matches(const HSimContext& ctx, const HSimEvent& ev) const override
    {
        return ev.Kind == PName("MyStatChanged") && ctx.State.Has<HMyOwnership>(ev.Target);
    }

    virtual void React(HSimContext& ctx, const HSimEvent& ev) override
    {
        HEffectRequest req;
        req.Kind    = PName("MyReaction");
        req.Subject = ev.Target;
        ctx.Enqueue(req);                 // 끼어들어야 하면 EnqueueFront
    }
};
```

- `Matches` 는 순수 조건. `React` 는 효과 적재만. 상태를 직접 바꾸지 않는다.
- 무한 연쇄 방지는 커널의 깊이 상한이 잡는다(초과 시 실패 이벤트).

### 4-6. 수치 단계와 수정자

```cpp
// StartupModule 에서 단계 순서 정의
Sim->DefineValueStages(PName("MyValue"), { PName("Base"), PName("Add"), PName("Multiply"), PName("Clamp") });

// Sim/MyModifiers.h
JGCLASS()
class JGMyBonus : public JGModifier
{
    JG_GENERATED_CLASS_BODY
public:
    virtual PName GetValueKind() const override { return PName("MyValue"); }
    virtual PName GetStage() const override     { return PName("Add"); }

    virtual bool Applies(const HSimContext& ctx, const HValueQuery& q) const override
    {
        return ctx.State.Has<HMyBonusTag>(q.Subject);
    }

    virtual int32 Apply(const HSimContext& ctx, const HValueQuery& q, int32 value) const override
    {
        return value + ctx.State.Get<HMyBonusTag>(q.Subject).Amount;
    }
};
```

- 배율은 정수 백분율. 실수 금지.
- "대신에" 류 규칙은 트리거가 아니라 여기(단계)로 온다.

### 4-7. 턴 순서 정책

```cpp
// Sim/MyTurnOrder.h
class PMyTurnOrder : public ITurnOrderPolicy
{
public:
    virtual void BuildOrder(const HSimState& state, HList<HEntityId>& outOrder) const override
    {
        state.Each<HMyInitiative>([&](HEntityId id, const HMyInitiative& init)
        {
            outOrder.push_back(id);
        });
        HAlgorithm::StableSortBy(outOrder, [&](HEntityId id)
        {
            return state.Get<HMyInitiative>(id).Value;
        });
    }
};
```

- 안정 정렬. 동률 처리를 정책 안에서 결정론적으로 끝낸다.
- 엔진 기본 `PFixedTurnOrder`(등록 순) · `PKeyedTurnOrder`(정수 키 정렬)로 충분하면 생략.

```cpp
Sim->SetBoard(EBoardKind::Hex);       // None · Square · Hex · Free
```

- 규칙 코드는 `ctx.State.Board()` 의 `IBoard` 질의만 쓴다. 좌표 타입은 `HBoardCoord`(정수).
- 사용자 정의 격자는 `IBoard` 파생 후 `Sim->SetBoard(PSharedPtr<IBoard>)`.

### 4-11. 프레젠테이션 연결

```cpp
// View/MyStatChangedStep.h
JGCLASS()
class JGMyStatChangedStep : public JGPresentationStep
{
    JG_GENERATED_CLASS_BODY
public:
    virtual bool Accepts(const HSimEvent& ev) const override
    {
        return ev.Kind == PName("MyStatChanged");
    }

    virtual void Begin(const HSimEvent& ev, PSimBinding& binding) override;   // 대상 Actor 찾아 연출 시작
    virtual void Tick(float32 dt) override;
    virtual bool IsDone() const override;
    virtual void Skip() override;                                             // 최종 상태로 즉시
};

// View 초기화
Binding   = Allocate<PSimBinding>(Sim, World);          // 스폰 · 파괴 이벤트로 Actor 관리
Sequencer = Allocate<PSequencer>(Binding);
Sequencer->RegisterAllFromReflection<JGPresentationStep>();
Sequencer->SetInputPolicy(ESequencerInputPolicy::BufferAndSkip);

// 매 프레임 (Update 버킷)
HCommand cmd;
if (CommandBuilder.Poll(cmd))
{
    HList<HSimEvent> events;
    PString reason;
    ESubmitResult result = Sim->Submit(cmd, events, &reason);
    Sequencer->Enqueue(events);
    if (result == ESubmitResult::PendingChoice)
    {
        CommandBuilder.BeginChoice(*Sim->GetPendingChoice());   // 선택 완료 시 ResolveChoice 를 Poll 이 돌려준다
    }
    if (result == ESubmitResult::Rejected)
    {
        DevView.ShowReason(reason);
    }
}
Sequencer->Tick(dt);
```

- 연출 단계는 상태를 읽기만 한다. 쓰기는 컴파일 단계에서 막힌다(`const HSimState&`).
- `EntitySpawned` / `EntityDestroyed` 는 `PSimBinding` 이 처리하므로 게임 단계는 안 만든다.

## 5. 지켜야 할 규칙 요약

| 위치 | 해야 할 것 | 하지 말 것 |
|---|---|---|
| 상태 구조체 | 값 타입 · `HEntityId` · `PName` · 정수 | 포인터 · `PSharedPtr` · 문자열 · 실수 |
| `Validate` | `const`. 사유 반환 | 상태 변경 |
| `Execute` / `Resolve` / `React` | `ctx` 로만 접근. 효과를 큐에 | 전역 · static · 시간 · 외부 난수 · 렌더 상태 참조 |
| 이벤트 | 이전 · 이후 · 원인 채움 | "바뀌었다" 만 발행 |
| 트리거 | 조건과 적재 분리 | `Matches` 안에서 상태 변경 |
| 수정자 | 정수 백분율 | 실수 배율 |
| 등록 | 시작 시 한 번 | 플레이 중 등록 변경 |
| `Sim/` 폴더 | Simulation 만 포함 | Graphics · GUI 헤더 |
| 연출 단계 | 상태 읽기 | 상태 쓰기 · 명령 직접 실행 |
